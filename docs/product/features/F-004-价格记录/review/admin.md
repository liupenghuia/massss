## 我理解的需求

管理员在车辆详情页里对已存在车辆设价/改价（数值或"面谈"），也可在建车辆草稿时带初始价。每次真实变动（新值≠当前值）自动生成一条不可篡改记录（变动前、变动后、时间、操作人）。管理后台在车辆详情内查看该车的价格记录列表，不做独立价格历史页，不做按价格状态筛车，不做批量改价、导出、审批、二次确认。本期登录管理员权限一致，都能改价。

## 我的方案倾向

- 车辆详情页做一个"价格"卡片：当前价（数值/面谈）+ 编辑入口 + 该车价格记录列表（时间倒序，操作人、变动前、变动后）。就近原则，不单独开页面。
- 编辑价格用行内表单/抽屉，两个互斥输入模式（金额 输入框 / "面谈"开关），提交前做本地校验（>0、最多 2 位小数），减少无效请求。
- 无二次确认弹窗（ADR-016 已定），但用"保存前展示变动前→变动后对比文案"的方式做低成本纠错提示，不算审批流程。
- 建车辆草稿表单里价格字段是可选的一个子区块，跟核心信息字段并列，不额外占一屏。
- 价格记录列表默认不分页限制条数（车辆量级小、单车记录数不会很大），先全量拉，超预期再加分页。

## 反对/风险

| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 无二次确认+价格零容忍 | ADR-016 已裁定不做二次确认，但价格错误是零容忍项。若管理后台不做任何前置校验/对比展示，纯靠"再改一次"纠错，误改期间前台已展示错误价格。建议至少做"提交前展示变动前→变动后"的非阻断提示，不算违反"无二次确认"的裁决。 |
| 中 | 操作人字段的可读性 | spec 只说"操作人=登录账号"，未说明记录列表里展示的是账号名/昵称还是账号 ID。展示纯 ID 不利于运营核查是谁改的价，需要后端返回可读的操作人标识。 |
| 中 | 反查失败报错的 UI 呈现 | spec 要求"F-001 反查（是否已填写）失败必须报错，不得视为未填写"。发布校验页若把这类系统错误和"价格未填写"用同一种提示展示，运营会误判为正常拦截而不去重试，需要在发布校验的错误文案里明确区分"系统异常"与"业务未满足"。 |
| 低 | 回收站车辆的价格记录可见性 | ADR-016 把回收站中记录的展示/清理留给 F-005，管理后台在车辆已进回收站时，详情/只读页是否仍展示价格记录未定，需 F-005 定稿时同步。 |

## 对其他端的隐含要求

- **服务端**：价格记录列表接口需返回可读的操作人字段（不只是内部账号 ID），供后台列表直接渲染。
- **服务端**：F-001 反查"是否已填写"失败时的错误需要有区分于"未填写"的错误码，供后台展示不同提示文案。
- **F-001（车辆详情）**：价格卡片嵌入车辆详情页，需要在该页面布局中预留位置，与核心信息、图片等模块并列而非另开页面。
