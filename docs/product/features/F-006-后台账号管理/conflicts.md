## 一致项

- 两级账号体系（admin / super_admin），业务权限完全相同，权限差仅体现在账号生命周期管理（建号/停用/启用/改角色/重置密码）。
- 会话为服务端存储、可吊销，8 小时滑动过期，不用 JWT，每次 `/admin/*` 请求需查库校验，不做本地缓存。
- 账号仅「启用/停用」两态，不做物理删除，不做字段级分权。
- 登录名永久唯一占用，不可复用/改名。
- 建号/重置密码返回一次性明文口令，展示一次即不可再查，且该操作不支持幂等重放（细节边界见待裁决）。
- 首次登录/密码重置后强制改密（`mustChangePassword`），改密前不能使用其他功能。
- 系统禁止最后一个启用的超管被停用或降级；此校验存在并发竞态风险，需数据库层（行锁/唯一约束/事务）兜底，不能仅靠应用层"先查再写"。
- 401（未登录）与 403（权限不足/已停用等）须严格区分，前端做不同 UI 分支。
- 管理后台是纯 Web，微信内置浏览器按普通手机浏览器对待，不做微信专属适配（不接 JS-SDK、不做 UA 分支）。

## 冲突项

## 无人认领的空白

1. `mustChangePassword` 未进入 spec 状态机表格集中定义——domain 提出，其余四方未回应是否需要补入状态机章节。
2. 账号从 `disabled` 重新 `active` 后，`mustChangePassword` 是否需重置为 `true`——domain 提出，api/qa/admin/miniapp 均未接话。
3. 超级管理员能否自我降级为 `admin`（非最后一个超管前提下）——domain 提出，其余四方未回应，权限矩阵未显式排除或允许。
4. 停用/改密后会话失效的最大允许延迟未量化——qa 标为高严重度并要求定具体阈值用于自动化断言超时；api 只说明架构原则（不加缓存、每请求查库），未给出数值型 SLA。
5. 登录失败锁定（15 分钟）与登录接口 IP 级限流同时触发时的优先级/返回错误码——qa 提出，api/domain/admin 均未回应。
6. 建号/重置密码超时后再次调用，是否会使前一次生成的口令立即失效——qa 提出；api 仅答复"有审计日志可供核实"，未直接回答该行为本身。
7. 密码策略的上限长度与允许字符集（仅有下限：8 位含字母数字）——qa 提出，无人回应。
8. 首次强制改密完成前，是否允许登出/切换账号/查看只读信息等"改密页以外"的路径——qa 提出，admin 虽提到改密页做路由守卫级拦截，但未明确是否允许登出等操作，未直接回应该问题。
9. 登录失败锁定（15 分钟）能否被超管手动解锁，还是只能等待或走停用/启用流程——qa 提出，无人回应。
10. 账号列表接口是否返回"当前是否为最后一个启用超管"的判断依据，供前端做操作前置提示——admin 提出需要接口方确认，api/domain 未回应是否提供该字段。
11. 微信安全域名拦截风险（链接被"已停止访问该网页"拦截）由谁负责处理域名报备/白名单——miniapp 仅提醒该风险属于外部依赖，未指出由服务端/运维/产品哪一方跟进，其余四方未认领。

## 需要用户裁决的问题

1. 账号从 `disabled` 重新 `active` 后，`mustChangePassword` 是否强制置为 `true`（等同一次密码重置）？
2. 超级管理员是否允许把自己降级为 `admin`（在非最后一个超管的前提下），还是应和"停用自己"一样禁止？
3. 停用/改密后会话失效的最大允许延迟是多少（用于定义验收标准与自动化用例的断言超时）？
4. 登录失败锁定（15 分钟）与登录接口 IP 级限流同时触发时，返回哪个错误码、是否有优先级？
5. 建号/重置密码超时后再次调用，是否会使前一次生成的口令立即失效？
6. 密码策略的上限长度与允许字符集（是否限制特殊符号/emoji）是什么？
7. 首次强制改密完成前，是否允许登出、切换账号、查看自己的只读信息等"改密页以外"的路径？
8. 登录失败锁定（15 分钟）是否可被超管手动解锁，还是只能等待自动解锁或走停用/启用流程？
9. 账号列表接口是否需要返回"当前是否为最后一个启用超管"的判断依据，供前端做操作前置提示？
