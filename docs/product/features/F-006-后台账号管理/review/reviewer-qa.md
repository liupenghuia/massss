## 我理解的需求

管理后台必须登录才能使用。账号只有两级：管理员与超级管理员。无只读、无审核员、无审批流、无字段级分权、无前台用户体系。未登录不得进入管理后台页面、不得调用 `/admin/*`。被停用账号须立即失去登录与改数能力。管理员不得创建/停用他人账号。登录态须能标识 F-001/F-003/F-004 的操作人。

## 我的方案倾向

验收应拆成可自动化的接口用例为主、页面拦截为辅：未带有效登录态访问 `/admin/*` 一律拒绝；管理员调用账号生成/停用接口被拒；停用后同一会话与新登录均不能再写数据。操作人字段必须是稳定账号标识。停用「立即」应定义为服务端校验每次请求。零容忍项「后台账号越权」要求把越权矩阵写成固定用例。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 「立即不能再登录、不能再改数据」未定义会话与令牌行为 | 停用后旧 cookie/token 是否立刻失效没有可测口径。 |
| 高 | `/admin/*` 未登录拒绝缺少统一可断言结果 | 未规定 HTTP 状态、错误码、是否区分未登录与无权限。 |
| 高 | 超级管理员自身生命周期未写 | 能否停用另一个超管、最后一个超管能否被停、初始超管如何存在，均无验收句。 |
| 中 | 「生成、分配」步骤与凭证形态未定义 | 无法写创建成功/失败用例。 |
| 中 | 停用与删除、登录失败次数、并发双开未说明 | 缺少异常路径。 |
| 中 | 操作人标识与停用后的历史记录关系未说清 | 若标识可变，追溯会断。 |
| 低 | 登录页是否算 `/admin/*`、登出行为未写 | 登录页可匿名与「未登录不能进后台」容易测成互斥。 |

## 对其他端的隐含要求

- **服务端：** 所有 `/admin/*` 必须鉴权；每次写操作复核账号状态与角色；返回值需稳定可测。
- **管理后台：** 未登录进入业务页应跳转登录；不能只靠隐藏按钮。
- **前台：** 不得复用管理登录态。
- **F-001/F-003/F-004：** 写操作必须带同一套操作人；无登录态的写应失败。
- **安全：** 测试需覆盖「管理员改他人账号」「已停用改车辆/价格/图片/回收站」越权路径。

## 我需要别人回答的问题

1. 未登录访问 `/admin/*` 的 HTTP 状态码、错误体、页面跳转分别是什么？已登录但角色不足、已停用是否同一套码？
2. 登录凭证形态是什么？停用后已有凭证多久内必须失效？
3. 「生成」和「分配」分别做什么？初始密码谁定、是否强制首次改密、用户名规则？
4. 停用后账号能否重新启用？列表是否仍展示已停用账号？
5. 超级管理员如何初始化？超管能否创建/停用其他超管？系统是否允许零个可用超管？
6. 操作人写入日志/价格记录的字段是账号 ID、登录名还是显示名？
7. 是否允许同一账号同时多处登录？登录失败次数是否锁定？
8. 本期是否要做「重置管理员密码」？
9. 管理后台登录页的 URL 是否在 `/admin` 下？该页是否允许未登录访问？
10. 自动化验收是否允许使用固定种子账号？口令如何安全存放？
