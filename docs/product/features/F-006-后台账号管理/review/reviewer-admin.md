## 我理解的需求

管理后台必须登录才能用。账号只有两级：管理员、超级管理员。权限差只在「账号生命周期」（生成、分配、停用）；车辆/图片/价格/回收站两边都能做，不设只读、审核员、审批流、字段级分权、多租户。前台无用户体系。登录态要能标识 F-001/F-003/F-004 的操作人。停用后必须立刻不能登录、不能再改数据。管理员不能创建/停用别人的账号。未登录不能进后台页、不能打 `/admin/*`。

## 我的方案倾向

- 后台单独做「账号」页，仅超级管理员可见入口；管理员侧栏不出现该菜单，接口仍必须鉴权拒绝。
- 账号列表最小列：账号标识、角色、状态（启用/停用）、创建时间。筛选先做角色、状态。本期不做批量停用、不做导出。
- 「生成」做成超级管理员创建账号（标识 + 初始口令一次展示）；若产品把生成和分配合成一步，就做成「新建管理员」单动作。
- 停用必须二次确认，成功后当前会话立即失效；所有 `/admin/*` 每次请求校验「未停用」。
- 操作人标识用稳定的账号 ID；停用后历史日志仍能对应到该账号。
- 账号生命周期本身也要落库审计（谁在何时生成/停用了谁），本期可不做查看页。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 停用只拦登录页、不拦已有会话 | 若 token 在过期前仍能调改价、上下架、回收站，等于停用无效。 |
| 高 | 账号接口只藏 UI、服务端不按角色拒绝 | 管理员若知道 URL 仍能生成/停用账号，权限模型破产。 |
| 高 | 首个超级管理员如何落地未写 | 没有种子账号规则时系统无法登录，或实现时用硬编码后门。 |
| 中 | 「生成、分配」三个动作未拆清 | 运营日常是「给新人一个能登录的号」还是「先造空号再改密交付」不清楚。 |
| 中 | 最后一个超级管理员被停用 | 若允许停掉唯一超管，账号页无人可进。 |
| 中 | 操作人标识不稳定 | 若操作人存展示名且允许改登录名，价格记录与操作日志无法追溯。 |
| 低 | 账号列表无筛选、无审计查看页 | 人少可上线；出事时只能查库。 |

## 对其他端的隐含要求

- **服务端**：所有 `/admin/*` 先鉴权再鉴角色；停用账号的一切写接口返回未授权/账号停用。会话在停用后立即失效。操作日志/价格记录写入当前登录账号的稳定 ID。
- **管理后台 Web**：未登录一律进登录页。管理员看不到账号管理。停用二次确认。
- **前台 Web**：继续无登录；若前后台同域，会话必须隔离。
- **F-001/F-003/F-004/F-005**：业务页只认「已登录且未停用」。
- **安全**：初始超管口令不能写进仓库；本期就是账号+口令，不要留第三方登录开关。

## 我需要别人回答的问题

1. 第一个超级管理员怎么来：安装种子、手工插库，还是一次性初始化页？
2. 「生成」和「分配」是两个步骤还是一次「新建管理员」？
3. 登录凭证是什么：登录名+密码？是否强制首次改密、忘记密码谁处理？
4. 超级管理员能否创建另一个超级管理员？系统是否允许多个超管？
5. 超级管理员能否停用其他超管、能否停用自己？最后一个启用超管是否禁止停用？
6. 停用后账号是保留（可再启用）还是不可逆？
7. 管理员能否改自己的密码？超管改别人密码是否本期范围？
8. 登录名创建后能否修改？操作日志里的「操作人」展示什么？
9. 会话形态：cookie 还是 token，有效期多久，是否单设备登录？
10. 账号管理页本期要不要操作记录查看？
11. 管理员误开账号管理 URL 时如何展示？
12. 是否允许删除账号（与停用区别）？
13. 停用号的登录名能否被新号占用？
14. 管理后台与前台是否同域部署，如何避免 cookie 串到前台？
