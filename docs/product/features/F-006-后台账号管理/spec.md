## 背景

管理后台必须登录才能使用。账号仅两级：管理员（车辆/图片/价格/回收站全部业务操作）、
超级管理员（管理员全部权限 + 账号生命周期管理）。前台无用户体系，不得复用后台会话。

## 用户故事

- 作为超级管理员，我给新同事开一个管理员账号，系统生成初始口令，我口头告诉他。
- 作为管理员，我首次登录被要求改密，之后可以正常使用后台全部业务功能。
- 作为超级管理员，我发现一个账号异常，立刻停用它，该账号下一次请求即失败，无法再改任何数据。
- 作为管理员，我忘了密码，请超级管理员帮我重置。

## 状态机

账号状态为三个正交维度：

| 维度 | 取值 |
|---|---|
| 角色 | `admin`（管理员）/ `super_admin`（超级管理员） |
| 启用状态 | `active`（启用）/ `disabled`（停用） |
| 改密状态 | `mustChangePassword` 为 `true`（需强制改密）/ `false`（正常） |

- 停用是状态转移，可重新启用。
- 仅 `disabled` 状态的账号允许**删除**（软删除，落 `deleted_at`，不物理清除行，不可恢复，
  不释放登录名）；`active` 账号删除返回 409。删除后账号从列表消失，历史审计记录保留，
  展示层对已删除账号兜底显示"已删除账号"（ADR-119）。
- 系统**禁止**将最后一个处于 `active` 的 `super_admin` 停用。
- 账号从 `disabled` 重新 `active` 时，`mustChangePassword` 强制置为 `true`，等同一次密码重置（ADR-101）。
- `mustChangePassword=true` 期间仅放行"修改密码"与"登出"两个接口，其余 `/admin/*`
  一律返回 `MUST_CHANGE_PASSWORD`（403），不放开查看只读信息等其他路径（ADR-106）。
- 停用/改密后，该账号发起的**下一次** `/admin/*` 请求即必须失败（401/403），
  架构上无会话缓存层，不存在传播延迟窗口（ADR-102）。

## 各端职责

### 服务端
- 会话存服务端（可吊销），不使用长期 JWT 塞角色。
- 每次 `/admin/*` 请求实时校验账号未停用；停用/改密后作废该账号全部现有会话。
- 会话有效期 8 小时滑动过期；同一账号允许多端同时登录。
- 未登录 → `401`；已登录但角色不足或已停用 → `403`。
- 密码最少 8 位（按字符数）含字母数字，上限 72 字节（按 UTF-8 字节数，非字符数，
  避免 bcrypt 静默截断，ADR-111 修正），字符集不做额外限制（仅拒绝控制字符）（ADR-105、ADR-111）；
  连续 5 次登录失败锁定该账号 15 分钟，不支持手动解锁，只能等待自动解锁或走停用/启用流程（ADR-107）；
  登录接口先过 IP 级限流（超限返回 `TOO_MANY_REQUESTS`），通过后再判断账号是否锁定（ADR-103）。
- 建号/重置密码每次调用立即使该账号此前所有未使用的一次性口令失效，只有最新一次生成的有效（ADR-104）。
- 账号列表接口不返回"是否最后一个启用超管"字段，该场景由 `LAST_SUPER_ADMIN` 错误码兜底（ADR-108）。
- 账号管理写接口（建号/停用/启用/重置密码/删除）服务端二次校验超级管理员角色。
- 删除接口前置状态检查须在数据库层用条件更新判断受影响行数，不得"先查再改"两步式判断，
  避免并发删除/并发启用下的竞态窗口（ADR-119）。
- 账号写接口（停用/启用、角色变更、重置密码、删除）的主变更与操作审计写入必须在**同一个
  事务**内提交，任一环节失败整体回滚，不得先落库主变更、再单独开事务写审计——避免审计写入
  失败时出现"数据已变更但接口返回错误"的不一致（ADR-120）。
- 部署时种子脚本创建首个超级管理员，口令通过环境变量注入，不进仓库。
- 账号生命周期（创建/停用/启用/重置密码）落库审计，本期不做查看页。

### 管理后台
- 登录页 URL 不在 `/admin/*` 前缀下，允许未登录访问；其余全部要求登录。
- 超级管理员可见「新建管理员」「停用/启用账号」「重置密码」「删除账号」入口；管理员不可见。
- 「删除账号」入口仅对**已停用**账号展示，点击弹出简单二次确认弹窗（非输入账号名确认），
  文案明确提示"删除后不可恢复"（ADR-119）。
- **自行改密**入口对所有已登录角色开放：顶栏「我的资料」（`/profile`）。账号管理页
  不再承载「改自己的密码」。强制首次改密仍走独立 `/password` 守卫（ADR-112）。
- 停用账号、重置他人密码须站内二次确认；启用账号不需要（ADR-112）。
- 账号列表默认展示全部账号（含已停用），带状态标签。
- 新建账号：填登录名提交，系统生成随机初始口令，创建成功页展示一次（成功结果用信息色，
  不用警示色）。
- 首次登录（含密码重置后）强制跳转改密页面，改密前无法使用其他功能。

### 前台
- 无用户体系，`/public/*` 不校验、不读取任何后台会话。

## 权限矩阵

| 操作 | 管理员 | 超级管理员 |
|---|---|---|
| 车辆录入/编辑/上下架 | ✅ | ✅ |
| 改价 | ✅ | ✅ |
| 图片/评估报告管理 | ✅ | ✅ |
| 删除到回收站/恢复 | ✅ | ✅ |
| 新建管理员账号 | ❌ | ✅ |
| 停用/启用管理员账号 | ❌ | ✅ |
| 新建/停用其他超级管理员 | ❌ | ✅（不能停用自己） |
| 删除账号（含超管） | ❌ | ✅（仅限已停用账号；不能删除自己，因不能停用自己） |
| 修改他人角色（升降级） | ❌ | ✅（不能把最后一个启用超管降级） |
| 修改自己的角色（自我降级） | — | ❌（一律禁止，与"不能停用自己"同一防误操作逻辑，ADR-109） |
| 重置他人密码 | ❌ | ✅ |
| 修改自己的密码 | ✅ | ✅ |

## 账号与登录名规则

- 登录名全局唯一，**创建后不可修改**；账号停用后其登录名**永久占用**，不可被新账号复用；
  账号删除后登录名同样**永久占用不释放**，不可复用（ADR-119）。
- 操作日志与价格记录的「操作人」字段**落库存账号稳定 ID**，展示时实时查询当前登录名。
- 忘记密码由超级管理员重置（生成新随机口令展示一次），重置后同样触发首次强制改密。

## 边界与限制

### 明确不做
- 不做前台注册/登录/收藏。
- 不做微信/企微身份登录、不做小程序登录（ADR-001）。
- 不做只读账号、审核流、自定义权限矩阵。
- 不做多租户。
- 不做字段级分权——两级角色的业务能力完全相同，权限差只在「管账号」。
- 不做账号生命周期审计查看页（落库但不做界面）。
- 不做邮箱/短信找回密码。

### 已知限制
- 停用后最多允许一次已在服务端执行中的写请求跑完，不强制中断进行中的事务。
- 允许多端同时登录，不做账号共享风控。
- 无审计查看页，问题排查需开发直接查库。
- 登录名永久占用不可回收，误建账号的登录名永久作废。

### 部署
- 管理后台与前台**不同域部署**，天然隔离会话 Cookie，无需额外分区方案。

## 接口与安全边界（ADR-031）

- 会话 Cookie：`HttpOnly; Secure; SameSite=Strict; Path=/admin`；管理后台前端与 API 同源部署。
- CSRF：`SameSite=Strict` + 状态变更接口校验 `Origin` header。
- 密码：argon2id（或 bcrypt cost≥12）存储，恒定时间比较，全站强制 HTTPS。
- 错误码：`FORBIDDEN`（角色不足）/ `MUST_CHANGE_PASSWORD` / `INVALID_CREDENTIALS`（密码错误或
  账号不存在统一码，防枚举）/ `ACCOUNT_DISABLED` / `ACCOUNT_LOCKED` / `ACCOUNT_LOGIN_NAME_TAKEN`
  / `CANNOT_DISABLE_SELF` / `LAST_SUPER_ADMIN`。删除接口：账号不存在或已删除返回 `404`
  （重复删除不采用幂等成功语义）；账号非 `disabled` 状态返回 `409`（ADR-119）。
- 登录失败：DB 原子计数，固定 15 分钟锁定窗口，成功登录清零，登录接口加 IP 级限流。
- 建号/重置密码不支持幂等重放，网络超时未收到口令时靠再次调用重置补救；网关/日志对这两个
  接口的响应体脱敏。
