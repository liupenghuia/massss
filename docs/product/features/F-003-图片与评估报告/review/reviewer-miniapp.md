## 我理解的需求

管理员在管理后台为车辆上传图片（≥4 张，无上限）和第三方评估报告文件（PDF/PNG/jpeg），可拖拽排序、给单张图片加说明文案；文件统一走对象存储 + CDN，不落应用服务器本地磁盘。访客在前台（无登录、无用户体系的 Web 页面）查看车辆的全部图片、图片说明和评估报告。车辆与图片/报告的关联用 F-001 的技术主键。图片在线编辑、视频、审核流程均不做。

docs/principles.md 中 ADR-001 已明确：前台与管理后台均采用 Web 技术栈，不做微信小程序。因此本 feature 不涉及小程序原生技术栈（openid/unionid、小程序审核类目、小程序隐私接口授权弹窗、分包体积等）本身不适用。

## 我的方案倾向

本 feature 属于 Web 域，不采用小程序技术栈，我不对具体实现方案（图片上传组件、PDF 预览方案、CDN 选型等）给出建议——这些不在我的角色范围内。

我的评审聚焦一个交叉场景：前台是无登录的展示页面，其链接大概率会被复制、转发，其中很可能包含"被分享到微信群聊/好友、并在微信内置浏览器（X5 内核）中打开"这一路径，即便产品本身不做小程序，也绕不开微信生态对 H5 链接的一系列限制。这部分风险如果不提前确认，上线后大概率会以"链接打不开""图片加载不出来""评估报告点了没反应"的用户投诉形式出现，而这类问题很难在事后靠前端小修小补解决，需要提前定方案。

## 反对/风险

| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 评估报告若为 PDF，微信内置浏览器（X5 内核）对 PDF 的原生预览支持不稳定，很多机型/版本会直接下载失败或显示空白，而不是"直接展示" | 需求明确"上传评估报告文件（PDF、PNG、jpeg），直接展示"，如果访客是通过微信分享链接进入（大概率会发生），"直接展示"在微信内置浏览器里可能无法兑现，需要有兜底方案（如转图片、跳转外部浏览器提示等），否则会被当作 bug |
| 中 | 图片/评估报告所在的 CDN 域名如果命中微信的域名安全策略（如被误判为营销推广、域名信誉分低、未备案等），会被拦截或提示"已停止访问该网页"，导致图片/文件整体不可见 | 这类拦截是链路层面的，前端代码无法规避，只能靠域名备案、内容规范、必要时申请微信互联互通白名单等运营手段预防；建议提前确认域名备案状态和内容合规性 |
| 低 | 缺少分享卡片（Open Graph）配置，车辆详情页被转发到微信时，卡片标题/封面图/描述会用默认值或抓取失败，影响传播效果和可信度 | 属于锦上添花项，非核心资产准确性问题，可按 principles.md"可带上线"的取向暂缓 |

## 对其他端的隐含要求

- **服务端 / 前台页面**：需要为车辆详情页（含图片、评估报告）提供 Open Graph meta 信息（og:image、og:title、og:description），供微信分享卡片抓取使用；否则分享出去的链接在微信里观感差，间接影响"访客能查看"这一成功标准的实际达成率。
- **Web 前端（浏览器端）**：评估报告的"直接展示"逻辑不能假设运行在标准桌面浏览器里，需要显式考虑微信内置浏览器（X5 内核）这一目标环境，尤其是 PDF 类型；建议前端方案里明确"内嵌预览失败时的兜底交互"（如提示用户点击右上角用浏览器打开、或后端转码成图片），而不是默认所有环境都能内嵌渲染 PDF。这个决定应由 Web 端 reviewer 或 F-001/F-003 主评审拍板，我这里只提出风险，不替其决策。
- **对象存储 / CDN 选型**：选型时除了成本和稳定性，还需确认所选 CDN 域名/图床服务是否曾被微信生态拉黑或限流（部分低成本图床、短链服务有被屏蔽的历史），否则会出现"后台传了图、前台在普通浏览器能看、在微信里看不了"的诡异现象，排查成本很高。
- **运营 / 内容合规**：前台页面内容（车辆图片、评估报告）如涉及价格、联系方式等，需注意不要触发微信对"诱导分享""站外引流广告"的判定规则，否则整站链接可能被微信标记拦截，这是运营层面的隐含要求，不是技术能单独解决的。

## 我需要别人回答的问题

- 访客访问前台车辆详情页/评估报告的链接，是否会作为微信群聊/好友分享的主要传播路径？如果是，"评估报告直接展示"和"图片可查看"这两条成功标准是否需要显式覆盖"在微信内置浏览器中打开"这一场景（并作为验收条件之一）？如果不是主要路径，是否可以接受"微信内打开体验较差，需引导用户用系统浏览器打开"作为已知限制？
- 前台使用的域名是否已完成 ICP 备案？是否已确认不在微信域名安全黑名单内？这个确认建议在选型/部署阶段做，而不是等上线后被动发现链接被拦截。
- 评估报告"直接展示"的具体交互方式（新标签页打开原文件 / 页面内嵌 iframe 预览 / 转码成图片轮播）尚未在 brief 中给出，这决定了微信内置浏览器兼容问题的严重程度，需要 Web 端方案确定后我才能判断风险是否已被覆盖，暂记录为待跟踪项，不代替裁决。
