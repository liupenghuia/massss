## 我理解的需求

管理员上传车辆图片（≥4张无上限）和评估报告（PDF/PNG/jpeg），存于对象存储+CDN，前台访客
（无登录态）查看全部图片、图片说明、评估报告，报告"直接展示"=新标签页打开原文件。
ADR-001 已确认不做小程序，前台是响应式 H5；ADR-011 已确认前台链接主要经微信内分享传播，
域名备案是部署前置条件、非本 feature 开发范围。本评审只评微信内置浏览器（X5 内核）打开
该 H5 页面时，图片查看与报告预览/下载的体验风险。

## 我的方案倾向

- 认同 ADR-011 的结论：微信分享为主传播路径，但不做微信专属能力，纯 URL 也要能用。
- 评估报告"新标签页打开"在微信内置浏览器下对 PDF 大概率会触发系统下载而非预览，
  ADR-011 已判定为"可接受的降级"，本期不需要额外开发绕过方案（如接入微信 JS-SDK 或
  第三方 PDF.js 内嵌预览器），维持现状即可，但需要在验收时截图/实测确认降级路径本身
  是可用的（不是白屏或报错）。
- 图片展示走 `<img>` 标准标签+CDN 直链即可，不需要走小程序图片API或长按识别二维码之类
  的专属交互；微信内长按图片保存是浏览器原生行为，不需要额外实现。

## 反对/风险

| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | CDN/对象存储域名可能命中微信域名安全策略 | 微信对被举报或被判定为诱导分享、包含恶意内容的域名会拦截，域名被封后前台链接和图内嵌的 CDN 资源在微信内会直接被屏蔽提示"该网页包含恶意内容"，且用户完全无法访问，属于零容忍级别的可用性风险（不是展示瑕疵）。ADR-011 已识别为遗留风险，"域名确定后专门检查一次"，需要明确谁来做、什么时候做。 |
| 中 | 图片/PDF 走公开直链，无 Referer/防盗链校验 | ADR-009 已定为公开直链且下架后不失效，微信环境下分享出去的链接会被大量预取/缓存（微信内置浏览器和公众号会预加载分享卡片图），若对象存储没有基本的防盗链或限速策略，可能被动放大 CDN 流量成本（本项目月度云支出上限 500 元，是敏感项）。 |
| 中 | PDF 在微信内置浏览器新标签页打开触发下载而非预览 | ADR-011 已判定可接受，但如果实际测试中出现"下载后无法直接查看"（部分安卓机型微信下载的文件被存到应用私有目录、用户找不到)，会变成事实上不可用，建议上线前用真机（iOS微信 + 安卓微信）各测一次。 |
| 低 | 分享卡片（Open Graph / 微信自定义分享 meta）未覆盖 | ADR-011 已注明"本次决策未覆盖"，车辆详情页若无缩略图/标题 meta，微信分享卡片会显示默认灰图和 URL，影响传播效果但不影响核心功能，非阻塞项。 |

## 对其他端的隐含要求

- 前台（public-web）：评估报告链接需保证在无 Referer 或跨域访问时依然可直接打开，不要
  依赖 Cookie/Session（前台本就无登录态，风险低但需在实现时确认未误加鉴权头）。
- 前台（public-web）：图片与报告的 `<img>`/`<a>` 需使用标准可被微信内置浏览器解析的
  MIME 类型和文件后缀，避免因扩展名缺失导致微信判定为不安全文件而拦截下载。
- 服务端：若后续要加防盗链/Referer 白名单，需把微信域名（如 servicewechat.com 相关内嵌
  webview）和公众号常见 UA 一并纳入白名单，避免误伤主要分享场景。

## 我需要别人回答的问题
