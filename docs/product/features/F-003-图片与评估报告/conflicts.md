## 一致项

- 车辆图片≥4张、无上限，支持排序、单图1:1说明文案；评估报告可挂多份、按上传时间倒序，无手动排序（api/domain/qa/miniapp/admin）。
- 上传走"客户端直传对象存储+预签名URL、服务端仅做元数据确认落库"三段式（api/domain/qa/admin）。
- 图片/报告无独立状态机，增删改即时生效，可见性完全继承车辆的发布状态（api/domain/qa/admin）。
- 已上架车辆删除图片导致数量<4张时，服务端拒绝该次删除（api/domain/qa/admin）。
- 图片/报告访问链接为公开直链、无鉴权，车辆下架不联动清理存储文件（api/domain/qa/miniapp）。
- 单车图片数超100张仅告警不阻断上传（api/qa/admin）。
- 批量拖拽上传遵循"部分失败不影响其余"原则（api/qa/admin）。
- 评估报告点击后新标签页打开原文件，微信内置浏览器下对PDF大概率触发系统下载而非预览，本期按ADR-011判定为可接受降级、不做额外开发（miniapp）。

## 冲突项

### C-1 报告是否需要额外字段区分同一车辆下的多份报告
- 各方主张：domain 主张报告实体应补充"评估机构名称/报告类型"等字段，否则管理员无法在列表快速区分多份报告 ／ api、admin 的方案均未涉及此字段，api 仅建议排序键用创建时间+自增ID保证稳定，未提区分字段需求
- 分歧根因：domain 认为这是领域完整性缺陷（实体缺字段），api/admin 未将其视为必需项
- 选项 A：现状不加字段，仅靠文件名/上传时间区分 — 代价：多份报告需打开文件才能分辨，管理员操作成本高
- 选项 B：报告实体新增"评估机构/报告类型"字段 — 代价：涉及 contracts 变更、上传表单增加输入项

### C-2 删除跌破4张下限时前端是否需要预判提示
- 各方主张：admin 主张需要明确前端能否在勾选删除阶段就禁用/提示"当前4张，无法继续删除" ／ api 主张不做前端预先拦截判断，统一依赖服务端拒绝后在弹窗内展示服务端返回的原因，避免前后端校验口径不一致
- 分歧根因：admin 从体验角度希望提前拦截，api 从前后端一致性角度反对预判
- 选项 A：前端不做预判，仅展示服务端拒绝原因 — 代价：管理员需要点击确认后才知道操作会被拒绝，体验较差
- 选项 B：前端根据当前图片数提前禁用删除按钮/给出提示 — 代价：前端需要维护与后端一致的下限校验逻辑，存在口径不一致风险

### C-3 公开直链是否需要防盗链/Referer 白名单
- 各方主张：miniapp 主张后续应考虑加防盗链或限速策略（含微信域名白名单），因分享链接会被微信预取/缓存放大CDN流量、影响月度云支出上限 ／ api 主张已按 ADR-009 定稿为公开直链不做鉴权，服务端实现上无需额外工作（不做referer校验）
- 分歧根因：miniapp 从成本敏感角度提出新增防护需求，api 认为该问题已在 ADR-009 定稿范围内、不属于本期工作
- 选项 A：维持 ADR-009 现状，不加防盗链/Referer校验 — 代价：分享放大导致的CDN流量成本不受控
- 选项 B：追加防盗链/Referer白名单（含微信域名） — 代价：需要额外开发与维护白名单，且需与 ADR-009 已定稿口径协调，可能误伤正常分享场景

## 无人认领的空白

- 预签名/confirm 接口如何校验"文件确实属于所申请的 vehicleId"（防跨车串号机制）：domain 判定这是零容忍项遗漏、qa 判定是无法写自动化断言的阻塞点，但 api 的方案倾向中未提出具体校验实现，无人给出确认机制的落地方案。
- 客户端直传成功但从未调用 confirm 产生的"孤儿文件"：api、qa 都提出该风险且都不确定处理方式，均倾向"留给 F-005"，但没有任何一方确认这就是最终结论，也没人认领本期是否需要至少做兜底防护。
- 已删除（回收站）车辆与已下架车辆在图片/报告可见性上的口径是否一致：domain 指出现状 spec 只写"/public/*不返回已下架数据"，未覆盖"已删除"状态，没有 api/qa 明确回应 /public/* 接口是否已覆盖该状态。
- 单车图片数超100张的"告警"具体落地渠道：api、qa、admin 都提出该问题，三方都没有给出方案，也没人确认这属于谁的职责（产品裁定还是工程默认）。
- 批量上传部分失败的响应契约与前端呈现方式：admin 要求 server 返回逐文件级别的成功/失败结果，api 的方案倾向只说"逐文件独立调用，服务端不做批量事务打包"，未明确响应结构是否满足 admin 的展示需求，两边未对齐具体字段。
- 图片说明文案（caption）的长度上限与是否允许空字符串：domain 建议应定工程默认上限，qa 明确列为无法确定的边界用例，但没有任何角色给出具体数值或规则。
- `adminReorderVehicleImages` 传入图片ID列表与该车实际图片集合不一致（缺失/多余/重复ID）时的服务端行为：qa 提出该问题，api/domain 均未回应应拒绝整批还是部分生效。
- CDN/对象存储域名的微信安全策略自查（ADR-011 提及的"域名确定后检查一次"）由谁在什么阶段执行：miniapp 提出但未有任何角色认领执行人和时机，也未确认是否需要列入验收清单。
- 报告/图片列表是否展示"上传人"字段：admin 提出该问题依赖操作日志查询能力，未有 api 或其他角色确认是否提供该查询接口。
- 排序保存的触发方式（拖拽后自动保存 或 需显式点击"保存排序"按钮）：admin 提出但无人（含 api）给出结论。

## 需要用户裁决的问题

1. 预签名/confirm 接口如何校验上传文件确实归属所申请的车辆（防跨车串号），本期需要明确具体校验机制吗？
2. 客户端直传成功但从未调用 confirm 产生的孤儿文件，本期是否需要任何处理（如TTL回收/定时清理），还是完全不管、留给 F-005？
3. 已删除（回收站）车辆的图片/报告，`/public/*` 接口是否需要与"已下架"车辆同口径过滤？
4. 评估报告是否需要新增"评估机构名称/报告类型"等字段，用于区分同一车辆下的多份报告？
5. 图片说明文案（caption）是否需要长度上限？是否允许为空字符串？
6. `adminReorderVehicleImages` 传入的图片ID列表与该车实际图片集合不一致（缺失/多余/重复ID）时，服务端应拒绝整个请求还是部分生效？
7. 单车图片数超100张的"告警"应落地为什么渠道（仅操作日志 / 后台可见提示 / 运维通知）？
8. 已上架车辆删除图片被拒绝（<4张）时，前端是否需要在勾选/操作阶段提前禁用或提示，还是完全依赖服务端拒绝后展示原因？
9. 批量拖拽上传的响应契约是否需要包含逐文件成功/失败结果，前端是否需要支持单文件失败重试，还是仅做整体"N张失败请重新上传"提示？
10. 公开直链是否需要追加防盗链/Referer白名单（含微信域名）以控制CDN流量成本，还是维持 ADR-009 现状不做任何校验？
11. CDN/对象存储域名的微信安全策略自查（ADR-011 遗留项）由谁执行、在什么阶段执行，是否需要列入本 feature 验收清单？
12. 评估报告/图片列表是否需要展示"上传人"（操作人）字段？
13. 拖拽排序后是自动保存，还是需要管理员显式点击"保存排序"按钮？
