## 一致项

- 车辆软删除用正交字段 `trashedAt`/`purged`，不并入 F-001 三态状态机（api/domain/qa 一致）。
- 公开可见性 = `published AND trashedAt IS NULL`，公开端一律零缓存（TTL=0）返回 404（api/domain/qa/miniapp 一致）。
- 恢复请求需优先于尚未跑完的清除任务，但落地机制/竞态窗口未定（api/domain/qa 均提出为风险，无人给出具体方案）。
- 删除/恢复接口对称、幂等、带乐观锁（version 字段）（api/domain/qa/admin 一致）。
- 回收站列表独立于在管列表，只读、不做批量操作与导出（qa/admin 一致）。
- 彻底清除只置 `purged=true`，主记录物理保留，对象存储异步删除，价格记录不级联删（api/domain/qa 一致）。
- 对象存储异步补偿删除缺少重试上限/终止条件/告警机制，属已知风险，建议实现时补充（api/domain 一致）。
- 回收站中记录彻底只读，删除需二次确认，恢复不需要（qa/admin 一致）。
- F-006 账号停用后需"立刻"使已登录管理员删除/恢复会话失效，但"立刻"的具体机制未定（qa/admin 均提出，均判定为跨 feature 依赖，非本端可独立解决）。

## 冲突项

（本轮评审各方未出现直接对立的方案主张，分歧均表现为"同一处规则各方各自提出风险但未给出互斥方案"，已归入下方空白/待裁决。）

## 无人认领的空白

- **清除任务与恢复请求竞态的具体实现机制**：api/domain/qa 三方都指出"清除任务扫描后、恢复先落库"存在竞态窗口，都建议"乐观锁或二次校验"作为方向，但没有一方声明由自己（服务端实现）落地具体的锁粒度/校验点，qa 额外指出这直接决定该场景能否自动化测试，目前无人认领具体设计。
- **对象存储异步删除失败的补偿日志/告警落地**：api 建议"记一条本地补偿日志"，domain 建议"补充最大重试次数与告警"，但两者都表述为"建议实现时补充"，没有人确认由谁（服务端哪个模块）实现、何时实现。
- **半清除窗口内前台仍可能命中直链的时间上限**：qa 提出"短暂"需要一个可断言的阈值（如 N 分钟），api/domain/miniapp 均只是复述"已知限制，书面接受"，没有一方给出具体数值或声明该数值由谁定义。
- **404 详情页在微信内置浏览器的降级 UI**：miniapp 明确提出"这属于前台展示层，非本 feature 直接负责"，未指明由哪个 feature/角色负责设计该降级 UI，前台侧无人回应认领。
- **回收站列表是否会返回 `purged=true` 的已清除记录、与"按 id 检索已清除记录"是否为同一接口**：admin 两次提出该问题（对其他端的隐含要求 + 我需要别人回答的问题），api/domain 未回应，接口设计归属空白。
- **VIN/主键彻底清除后唯一性约束是否覆盖 `purged=true` 记录**：api 提出该风险（需确认唯一索引范围），domain 提到这是已拍板的业务约束（ADR-030），但没有人确认唯一索引层面的技术实现是否已核实覆盖。
- **管理后台"剩余保留天数"取整规则（向上/向下）**：qa 提出该问题，admin 只说"直接用服务端返回字段渲染，不做前端计算"，即隐含服务端应给出取整后的天数，但服务端侧（api/domain）未回应该取整规则具体是什么。
- **重复删除幂等成功时的前端提示文案**：qa 提出"是否需要提示保留期未变"，admin 未提及此点，无人认领该文案设计。
- **回收站关键字搜索覆盖字段范围**：qa 提出该问题，api 只说"建议复用 F-001 现有搜索实现"但未列出具体字段范围，未有人给出明确清单。

## 需要用户裁决的问题

1. 清除任务与恢复请求并发竞态的具体互斥机制（乐观锁 or 处理前二次校验 trashedAt）如何设计，以及该机制是否需要提供可测试的触发/时钟注入方式供自动化验证「恢复优先」。
2. 对象存储异步补偿删除的最大重试次数、失败后的日志/告警方式是否在本期实现，还是留作已知限制不做。
3. 半清除窗口内前台仍可能短暂命中直链的时间窗口是否需要设定明确上限阈值（如 N 分钟内完成）作为验收标准，还是仅作为已知限制不设阈值。
4. 微信内置浏览器/前台详情页对已删除/已清除车辆的 404 降级 UI，是否属于本 feature 交付范围，还是留给前台其他 feature 处理。
5. 管理后台回收站列表分页接口是否会一并返回 `purged=true` 的已清除记录，还是已清除记录只能通过单独的按 id 检索查看；回收站列表与已清除车辆检索是否为同一接口。
6. VIN/主键唯一性约束（唯一索引）是否覆盖 `purged=true` 的已清除记录，防止未来新建车辆与已清除记录的 VIN 冲突。
7. 管理后台「剩余保留天数」展示的取整规则（向上取整/向下取整）。
8. 重复删除已在回收站的车辆（幂等成功、保留期不刷新）时，管理后台是否需要专门提示文案告知用户保留期未变。
9. 回收站列表关键字搜索的匹配字段范围（是否与在管列表搜索规则一致）。
