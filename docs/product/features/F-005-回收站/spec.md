## 背景

管理后台需要软删除能力：车辆从在管列表删除后进入回收站而非当场物理抹掉，保留约 1 个月
后自动彻底清除。前台可见性零容忍——进回收站后必须立刻从公开端消失。
F-001 本期未预留软删除字段，本 feature 落地时需为 `vehicles` 表迁移新增 `trashedAt` 字段。

## 用户故事

- 作为管理员，我误建了一台草稿车，能把它删掉而不留在在管列表里碍事。
- 作为管理员，我把一台已上架车删错了，能在回收站里找到并恢复它。
- 作为管理员，我在回收站列表能看到每辆车还剩几天会被永久清除。
- 作为访客，车辆一旦被删除，我立刻在前台看不到它，即使我手上有旧链接。

## 状态机

回收站**不并入** F-001 的 `status` 三态状态机，采用**正交字段** `trashedAt`（可空时间戳）：

| trashedAt | purged | 含义 | 公开可见性 |
|---|---|---|---|
| NULL | false | 在管，正常走 F-001 三态 | 依 `status=published` 判断 |
| 有值 | false | 回收站中 | 一律不可见（404） |
| 有值 | true | 已彻底清除 | 一律不可见（404），管理端只读可查 |

- 公开过滤条件为 `published AND trashedAt IS NULL`（ADR-019/023）。
- 所有在管列表、写接口（发布/下架/改核心字段/改价/改图/F-003 附件上传）**必须**额外排除
  `trashedAt IS NOT NULL` 的车辆。

### 转换规则（ADR-023）

| 动作 | 允许的源状态 | 结果 |
|---|---|---|
| 删除进站 | 草稿 / 已上架 / 已下架（三态均可） | `trashedAt = now`；已上架车辆额外记「下架」日志 |
| 恢复 | 回收站中（`purged=false`） | **一律落草稿**，`trashedAt = NULL` |
| 到期彻底清除 | 回收站中且已过保留期 | `purged = true`，主记录保留，对象存储文件删除 |

- 重复删除（对已在站内的车再次删除）：幂等成功，**不刷新** `trashedAt`。
- 重复恢复（对已恢复的车再次恢复）：幂等成功。
- 同一辆车允许不限次数「删除 → 恢复」循环，每次删除**重新计算**一个月保留期。
- 已被清除（`purged=true`）的车辆调用恢复：返回专用错误码，不允许恢复。

## 各端职责

### 服务端
- 删除 / 恢复接口带乐观锁（`version`），与 F-001 现有写接口一致，避免并发覆盖。
- 定时清除任务**每日执行一次**，扫描 `trashedAt + 30×24h ≤ now`（Asia/Shanghai）且未清除的记录，
  可重入、失败自动重试；**恢复请求优先于**尚未跑完的清除任务：任务处理每条到期记录时，
  在同一事务内二次校验其仍处于回收站中才置 `purged=true`，若已被恢复则跳过，不视为错误（ADR-086）。
- 彻底清除时：主记录**不物理删除**，置 `purged=true`；对象存储图片/报告**异步删除、可补偿重试**；
  价格记录**不级联删除**。对象存储删除在同一次任务执行内同步发起，正常情况下目标
  60 秒内完成（保守参考值，非强 SLA）；失败进入补偿重试（1/5/30 分钟三次），
  三次均失败后停止自动重试仅记日志，半清除窗口极端情况下最长约 36 分钟（ADR-087）。
- 车辆技术主键与 VIN **彻底清除后禁止复用**。
- 公开接口对回收站中及已清除车辆一律 `404 VEHICLE_NOT_FOUND`，遵循 ADR-019 零缓存（TTL=0）。

### 管理后台
- 回收站为**独立列表页**，与在管列表互斥，展示：车辆基本信息、原状态、删除时间、
  到期日/剩余保留天数（服务端计算，向下取整，不足一天按 0 天展示）；
  支持关键字搜索（字段范围与 F-001 在管列表一致）、分页；排序为删除时间倒序。
- 回收站分页列表**只返回** `purged=false` 的进行中记录，`purged=true` 的已清除记录
  不出现在分页列表中，只能通过按已清除车辆 id 检索单独查看（ADR-089）。
- 回收站内车辆**完全只读**：可查看图片/报告/完整价格历史，**禁止**任何编辑、发布、下架、改价、改图。
- 删除操作需**二次确认**；**恢复为草稿同样需要二次确认**（ADR-112，推翻 ADR-025
  「恢复不需要」）。重复删除已在站内的车辆时，追加非阻断提示"该车辆已在回收站中，
  保留期不变"（ADR-090）。
- 列表接分页控件（默认每页 20 条，接口上限 100）；须展示「第 x–y 辆，共 z 辆」。
  「查看详情」在当前行就地展开并高亮来源行，不把只读卡丢到页面底部不管。
- 任何已登录管理员权限相同，可操作全部回收站记录（不限本人删除的）。
- 支持按已清除车辆 id 检索，只读展示其主记录信息与全量历史价格。
- 不做批量删除/批量恢复、不做回收站导出。

### 前台
- 不改前台展示逻辑本身，继续只打 `/public/*`；回收站不可见性由服务端过滤保证。
- 已删除/已清除车辆的前台 404 降级 UI（含微信内置浏览器下的展示）不属于本 feature 交付范围，
  推迟到 F-002 负责通用的"车辆不存在"降级页面设计，不阻塞本 feature（ADR-088）。

## 边界与限制

### 明确不做
- 不做从回收站以外的「彻底删除」快捷入口，也不做站内「立即彻底清除」——只走到期自动任务，
  任务失败靠下一次调度自动重试，无手动补救入口。
- 不做批量删除 / 批量恢复。
- 不做回收站导出。
- 不做微信小程序入口（ADR-001）；删除 / 恢复仅限管理后台会话。

### 已知限制
- 彻底清除的对象存储删除为异步补偿，半清除窗口内直链可能短暂仍可访问。
- 定时任务每日一次，到期后最多有一天清除延迟。
- 微信分享卡片标题/封面无法强制撤回，删除后旧卡片可能仍显示原内容，书面接受。
- 表中车辆记录只增不减（`purged` 行永久保留），长期需归档策略，本期不做。
- 权限不区分「谁删的」，任何管理员可恢复/再删他人操作的记录，本期不做记录级权限控制。

### 与其他 feature 的联动
- F-006 账号停用后，该账号**立刻**不能再执行删除/恢复（会话失效同步）。
- 恢复后再次发布仍需通过 ADR-003 的发布前置校验（图片 ≥4 张、已填价）。
- 恢复为草稿后若再次发布，复用同一个公开 URL（基于车辆 id 天然稳定）。

## 接口边界（ADR-030）

- `trash`/`restore` 完全对称，均支持 If-Match 或 body.version 乐观锁。
- 检查顺序（两接口一致）：车辆不存在 → 已彻底清除 → 幂等短路（不比对 version）→
  restore 特有的"从未进回收站"分支（409 VEHICLE_NOT_IN_RECYCLE_BIN）→ 乐观锁校验。
- `AdminRecycleBinItem` 不含 `status`（用 `originalStatus` 表达）、不含价格（价格走
  `price-records`），含 `version` 字段供前端调用 restore。
- `AdminVehicle` 新增非 required 的 `trashedAt`/`purged` 只读字段，供管理后台判断可编辑性。
- 回收站列表：`trashedAt` 倒序 + `id` 二级排序；`keyword`/分页越界/无匹配均返回空结果不报错。
- 新增错误码：`RECYCLE_BIN_ITEM_PURGED`（404）、`VEHICLE_NOT_IN_RECYCLE_BIN`（409）、
  `VEHICLE_IN_RECYCLE_BIN`（409）。
