## 我理解的需求

管理后台要把车辆从「在管列表」挪进回收站，而不是当场物理抹掉。普通管理员与超级管理员都能删、都能恢复。进回收站后前台必须立刻不可见。回收站保留约 1 个月后自动彻底清除，清除后不可恢复。不做回收站以外的彻底删除入口、不做批量删除/恢复、不做回收站导出。恢复后车辆一律进入草稿。价格记录不随删除级联抹掉。F-001 未预留软删除字段，本 feature 要做表迁移。删除允许作用于哪些状态以及对象存储是否随彻底清除删除，须在本评审裁决。

## 我的方案倾向

- 在管列表排除回收站中的车；回收站做成独立页。单条「删除到回收站」与「恢复」。删除建议二次确认。
- 草稿、已上架、已下架都应允许进回收站（倾向，待裁决）。已上架删除时由服务端保证前台立即不可见。
- 恢复只恢复为草稿，不自动上架。回收站内不允许改核心字段、改价、改图。
- 权限：已登录的管理员与超级管理员权限相同。
- 回收站列表按删除时间倒序；建议展示到期日。
- 删除进站、恢复、到期彻底清除写入操作日志。彻底清除只走到期自动任务。
- 彻底清除时倾向删对象存储文件；停留期内不删以便恢复。此条必须用户拍板。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 删除允许的源状态未定 | 若不允许删草稿，误建草稿将永久占列表。 |
| 高 | 在管列表若未排除回收站车辆 | 运营会在 F-001 列表里对已删车点编辑/上架。 |
| 高 | 越权与不可追溯 | 删除/恢复若不记操作日志，误删无法举证。 |
| 中 | 恢复=草稿 vs ADR-004 | 必须写成显式转换（回收站 → 草稿），否则实现会按 ADR-004 拒绝恢复。 |
| 中 | 保留期与自动任务失败 | 「1 个月」是自然月还是 30 天未写。 |
| 中 | 存储清理与公开直链 | 不删对象则成本高；删除则恢复窗口内必须保证文件仍在。 |
| 中 | 价格记录孤儿 | 车彻底清除后价格永久保留，后台如何展示未定。 |
| 低 | 无批量、无导出、UI 不精致 | 百台以内可接受。 |

## 对其他端的隐含要求

- **服务端：** `/admin/*` 在管列表不得返回回收站车辆；`/public/*` 必须硬过滤回收站及已彻底清除车辆。
- **F-001：** 需扩展「回收站中」以及恢复→草稿。对回收站车辆发布/下架/改价应报错。
- **F-003：** 停留期内图/报告必须仍可在恢复后使用。彻底清除是否删对象存储与本 feature 同一裁决。
- **F-004：** 进回收站与彻底清除都不级联删价格记录。
- **F-002：** 不改展示逻辑；旧详情 URL 应对已删车表现为不存在。
- **F-006：** 停用账号必须立刻不能再删除/恢复。

## 我需要别人回答的问题

1. 删除到回收站允许哪些源状态：仅已下架、已上架+已下架、还是草稿+已上架+已下架？（F-001 问题 25）
2. 「1 个月」按自然月还是 30×24 小时？时区？
3. 彻底清除时是否删除对象存储中的图片和评估报告？
4. 车被彻底清除后，孤儿价格记录在管理后台要不要可查？
5. 回收站内能否查看（只读）图片、报告、价格？
6. 删除是否必须二次确认？恢复是否要确认？
7. 自动清除失败时运营有无补救（立即清除）？
8. 对已在回收站的车辆重复点删除应提示失败还是当成功？
9. 恢复与到期清除同时发生，谁赢？
10. 回收站列表是否要关键字搜索、是否展示原状态与剩余保留天数？
11. 已上架车辆直接删除时，是否还写一条「下架」日志？
12. 车辆技术主键在彻底清除后是否允许被新车复用？
