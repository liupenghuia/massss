## 我理解的需求

F-005 给管理后台补「软删除 → 回收站 → 到期彻底清除 / 人工恢复」，并保证前台 `/public/*` 在删除生效后立刻不再返回该车。F-001 未预留软删除字段，必须对 `vehicles` 做兼容迁移。恢复后车辆回到 draft。保留期 1 个月。不做批量、不做导出、不改前台逻辑。价格记录不级联删除。必须定稿：哪些状态可删；对象存储是否随彻底清除删除。

## 我的方案倾向

- 回收站用独立字段（如 `trashedAt`），不要做成第四个业务 status。`/public/*` 过滤「published 且 trashedAt IS NULL」。
- 删除/恢复带乐观锁。对已在回收站的车重复删除幂等成功、不刷新 `trashedAt`。
- 接口：`POST /admin/vehicles/{id}/trash`、`POST /admin/vehicles/{id}/restore`、`GET /admin/recycle-bin`。现有在管列表默认排除回收站。
- 回收站内只读，禁止 publish/unpublish/改核心字段/改价/改图。
- 1 个月建议 30×24h，从 `trashedAt` 起算。彻底清除：价格行不删；对象删除走异步补偿。
- 迁移：`trashed_at` 可空，存量 NULL。契约变更先 RFC。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | `/public/*` 与公开直链双通道 | 接口可立刻不返回，但直链仍可能打开图/报告。 |
| 高 | 删除与发布/改价/改图竞态 | 无乐观锁可能「已 published 同时 trashedAt」。 |
| 高 | 到期清除失败导致半清除 | 对象删除不可与 DB 同事务。 |
| 中 | 把回收站做成 `status=trashed` | 改 ADR-004 三态，迁移面大。 |
| 中 | 在管列表未排除回收站 | 已删的 published 车会仍出现在「已上架」里。 |
| 中 | 价格记录永久保留 vs 车行已物理删除 | 主键复用会导致价格挂到新车上。 |
| 低 | 「1 个月」边界与对象存储费用 | 不删对象会一直占存储。 |

## 对其他端的隐含要求

- **F-001：** 列表、详情、PATCH、publish、unpublish 必须把「在回收站」视为不可运营态。
- **F-002 / public：** 回收站中的车对所有公开子资源 404。
- **管理后台：** 回收站页 + 在管删除入口；删除/恢复带 version。
- **F-003：** 停留期内元数据保留；彻底清除是否删对象由本评审裁决。
- **F-004：** 删除/恢复/清除都不写新价格、不删历史。
- **F-006：** 只校验已登录 admin。
- **定时任务：** 可重入扫描；失败重试。

## 我需要别人回答的问题

1. 删除允许作用于哪些状态——仅 published/unpublished，还是 draft 也可以？
2. 彻底清除时图片/报告对象存储是否删除？元数据是否删除？
3. 「1 个月」按 30 天还是自然月？任务最多延迟一个调度周期是否可接受？
4. 回收站内是否允许查看/编辑字段、改价、增删图片？
5. 恢复是否必须回到 draft（即使删之前是 published）？
6. 在管列表是否强制排除回收站？
7. 车辆物理删除后，按原 vehicleId 查价格记录保留还是 404？
8. 是否维持禁止站外彻底删除？
9. 回收站列表展示哪些字段？剩余天数由谁计算？
10. 重复删除是否不得刷新 trashedAt？
11. 定时清除与正在点恢复冲突，谁赢？
12. 公开直链在入站后是否仍保持不失效直到对象被删？
