## 我理解的需求

管理员把车辆移入回收站，前台立刻查不到。回收站可查看、可恢复为草稿。约 1 个月后自动彻底清除。不做批量、不做导出、不改前台逻辑。价格记录不随删除级联抹掉。删除允许哪些状态、对象存储是否随彻底清除删除，必须裁决。

## 我的方案倾向

- 把「在管 / 回收站 / 已彻底清除」当成可断言的可见性矩阵写进验收。
- 自动清除用可测的截止规则，验收必须能用时间夹具跑，禁止只靠人工等 30 天。
- 彻底清除后同一车辆 id 在管理端、回收站、公开端均不可再操作。
- 价格记录：删除进站、恢复草稿、到期清除三条路径都要断言历史价策略。
- 发布恢复车必须复用 F-001 前置校验，不得因曾经上架过而绕过。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 删除允许的源状态未定义 | 自动化无法写合法/非法转换用例。 |
| 高 | 「立即不可见」无时间与一致性定义 | 无法变成「删除 200 后第 N 次 public GET 必失败」。 |
| 高 | 「1 个月」不可测 | 自然月 vs 30×24h、时区、任务失败均未定义。 |
| 高 | 彻底清除与价格/文件的关系未裁完 | 无法断言对象存储残留与串号。 |
| 中 | 恢复后草稿的并发与幂等 | 重复恢复等无错误码。 |
| 中 | 回收站列表可测字段不足 | UI 可带上线但不等于接口无契约。 |
| 低 | 权限只写普通管理员也能删除 | 恢复、看回收站范围未写。 |

## 对其他端的隐含要求

- **服务端：** 软删迁移；公开端已删车不得出现；错误码需区分非法状态删除、重复删除、对已清除恢复。
- **F-001：** 在管列表排除回收站；恢复后为草稿。
- **F-002：** `/public/*` 过滤必须在服务端完成。
- **F-003：** 进站期间附件写是否允许未定义；彻底清除与错配零容忍。
- **F-004：** 删除/恢复不得打乱价格时间序；禁止新车复用旧 id 看到旧价。
- **F-006：** 须明确谁能进回收站、谁能恢复。

## 我需要别人回答的问题

1. 删除允许作用于哪些状态？对不允许的状态返回什么？
2. 「1 个月」的精确规则：30×24 小时还是日历月？时区？
3. 自动清除任务的频率、失败重试、到期但任务未跑期间恢复是否仍允许？
4. 彻底清除后价格记录保留还是删除？按车辆 id 查询应 404 还是仍返回历史？
5. 彻底清除是否删除该车全部图片/报告对象存储？
6. 回收站内是否允许改信息、改价、改图，还是只读直到恢复？
7. 恢复是否幂等？
8. 已上架车辆删除时是否允许不先下架？
9. 车辆 id / VIN 在彻底清除后能否被新车复用？
10. 普通管理员对回收站的权限范围：全部车辆还是仅自己删除的？
11. 删除是否要二次确认？是否绝对不做加速销毁？
12. 回收站列表的排序、分页、搜索、展示字段、是否显示剩余天数？
13. 「立即不可见」是否允许最多 N 秒缓存？N 是多少？
14. 进行中的公开请求删除后刷新是否必须失败？
15. 软删字段形态：独立 status 还是 deletedAt 可空？
