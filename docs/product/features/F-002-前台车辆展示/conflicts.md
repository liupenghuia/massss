# F-002 前台车辆展示 — 评审对照表

> 由 /conflicts 生成，机械提取。不含整理者判断。
> 来源：reviewer-admin / reviewer-api / reviewer-domain / reviewer-miniapp / reviewer-qa（2026-08-19）

## 一致项
<!-- 各方无异议，可直接进 spec -->

- 本 feature 是访客侧只读展示：不登录、打开链接即可看已上架车辆的列表与详情。
- 前台是哑终端：只渲染 `/public/*` 已返回的数据；不做上架/状态过滤；不做「面谈 vs 数字」业务判断。
- 不改任何车辆/图片/价格写入接口；不新增车辆 CRUD。
- 交付形态为 Web（ADR-001）；明确不做微信小程序、不做仅微信可用的专属能力（admin/api/domain 按 Web 边界写；miniapp/qa 明文不做小程序）。
- 可见性唯一信服务端 `published` 硬过滤；草稿 / 已下架对前台不可见；前台禁止传 `status`、禁止二次判断。
- 前台只消费 `/public/*`，禁止请求 `/admin/*`，禁止用管理接口补公开列表缺的图/价。
- 公开响应禁止出现 VIN / vinMasked、操作人 / operatorId；admin 另写后台备注类字段不得进公开响应；qa 另写 version 不得出现在公开端展示。
- 图片按公开接口返回顺序与直链展示，前台不得重排；评估报告用返回的原文件 URL、新标签打开（ADR-010），服务端不转码、不代理、不内嵌 PDF 预览（qa/api）。
- 当前价格由 F-004 公开接口给出，当前价须等于最新一条记录的变动后值；前台不得自行计算当前价。
- 价格公开结构为类型 + 金额（现契约）；展示条数、是否分页、面谈文案须在本 feature 内定稿，且不得把已作废的 ADR-014「最近 20 条 / 面议」当未裁决默认实现。
- 对象存储公开直链在下架后不失效（ADR-009）；「车辆对 `/public/*` 不可见」与「文件直链仍可打开」不是同一件事。
- 已上架编辑立即进入前台投影（ADR-004/008）；F-002 无独立状态机、无「延迟发布」。
- 公开接口无用户体系：无登录、无 Cookie/Authorization 依赖、不获取 openid、不走微信网页授权（miniapp 明文；api/domain/qa 禁止公开端绑管理员会话）。
- 本包不给管理后台加新菜单、筛选、批量、导出、前台置顶/推荐位（admin 明文；他角色未主张加运营配置台）。
- 契约变更（列表聚合字段、下文案、分页默认值等）须 RFC 后改 `contracts/`，实现期不得私自加未契约字段。

## 冲突项

### C-1 面谈文案：服务端下发 vs 前台写死；用词是否与后台一致
- 各方主张：api 主张公开价格响应增加服务端展示字符串、前台只渲染 ／ domain 主张要么服务端下发展示字段，要么契约写死唯一映射且前台零分支 ／ admin 主张价格仍给结构化类型、文案可在前台写死但必须本包定稿，且后台与前台应用同一词 ／ miniapp 主张展示形态由接口数据表达，不要按微信环境改文案 ／ qa 主张精确文案未定则无法断言；若前端写死则契约不得中途改成下文案，若服务端下文案必须先 RFC
- 分歧根因：brief 要求本 feature 定稿文案；ADR-017 / 现契约规定 F-004 只给 type+amount、不下发文案；principles 要求前端不做业务判断。
- 选项 A：公开 DTO 增展示字符串（或等价 display），前台零分支 — 代价：须 RFC 改 F-004/公开契约；与现「只给类型+金额」不一致
- 选项 B：前台对 `type` 唯一死映射（如写成「面议」） — 代价：api/domain 视为违反哑终端；admin 指出若后台写「面谈」、前台写「面议」则培训与验收会对不上

### C-2 公开列表卡片要不要封面/当前价，以及是否扩列表契约
- 各方主张：api 主张移动端优先时倾向服务端下发展示所需最小聚合（封面 URL、当前价 type/amount、面谈展示文案），是否改契约须用户裁决 ／ domain 主张现 `publicListVehicles` 不含价/图，若产品期望列表出价或出图则当前读模型不够，不能前台拼 admin ／ qa 主张必须先写清卡片字段；问是否允许每卡再打 images/price，以及某辆价 404 如何展示 ／ miniapp 主张首屏要轻、缩略图 URL 由服务端/CDN 给出，并问服务端是否保证缩略图字段还是前端/CDN 拼参数 ／ admin 未主张列表必须出图出价，但主张公开列表不要做运营级筛选/排序配置台
- 分歧根因：成功标准写「能浏览列表」，契约明确列表无价格/图片；N+1 与改契约两条路都未授权。
- 选项 A：扩 `GET /public/vehicles` 聚合封面/价格（及可选文案） — 代价：RFC 改契约；api 称须保持字段只增不改语义
- 选项 B：维持列表无图无价，前台对每条再打 images/price — 代价：api 称放大失败面与竞态（列表仍在、price 已 404）；qa 称须另定请求上限与单条失败展示；miniapp 称一百台内仍要防首屏拉全量原图

### C-3 非 published 详情 URL 的产品语义：统一当不存在 vs 「已下架」
- 各方主张：api 主张非 published 或不存在一律 `404 VEHICLE_NOT_FOUND`，禁止 403；并问是否一律当「不存在」还是可区分文案（仍不能暗示车曾存在） ／ domain 主张访客侧只有能读到或一律视为不存在，避免「已下架」等前台伪状态 ／ admin 将选项列为 404、空态文案或提示「已下架」，并要求列表与详情一致不可见 ／ qa 问统一 404 文案还是空白，以及正在看详情时被下架下一步看到什么 ／ miniapp 主张未上架/草稿/回收站不得出现在公开接口
- 分歧根因：契约/原则用 404 防止枚举状态；运营对客可能需要「已下架」话术（admin）。
- 选项 A：接口与页面一律当不存在（404/找不到），不区分下架/回收/乱猜 id — 代价：admin/qa 称无法展示「已下架」；运营可能误判
- 选项 B：页面对访客提示「已下架」或可区分文案 — 代价：domain 视为前台伪状态；api 称可能暗示车曾存在、与禁止 403/枚举状态的意图冲突

### C-4 公开列表排序键：沿用契约 id 降序 vs 产品另定运营排序
- 各方主张：api 主张现契约列表默认 `id` 降序，按可增长规模做分页 ／ domain 主张默认排序与契约一致（id 降序）时前台不得改排序语义 ／ admin 主张排序必须由服务端数据决定，并问规则是上架时间、改价时间还是后台手动顺序、要不要置顶；brief 未写不能默认 ／ qa 问是否固定为公开接口 id 降序、前台是否禁止任何本地重排/筛选 ／ miniapp 未主张另一套排序键
- 分歧根因：OpenAPI 已有默认排序；brief 未写运营期望。
- 选项 A：前台顺序 = 公开列表 id 降序，禁止本地重排/筛选 — 代价：admin 称无「最近上架/改价/置顶」；若运营要先发某几台，当前状态机只有上下架
- 选项 B：改为上架时间/更新时间/手动顺序或置顶 — 代价：api/domain 称须改公开车辆契约与索引；admin 称置顶/推荐位是新运营能力，应另开需求

### C-5 分享卡片（标题/摘要/封面）是否纳入本包
- 各方主张：miniapp 主张分享即复制当前 URL 或系统分享，不实现微信自定义分享卡片、不调用 JS-SDK ／ qa 主张微信内置浏览器仅当普通手机浏览器测，不做 JS-SDK/分享卡片；ADR-017 分享信息若要做须另裁 ／ admin 主张若做只能用公开字段，brief 未写死不能假定有 OG 配置台 ／ api 主张 ADR-017 将微信打开与分享信息归 F-002，现公开契约无分享元信息 ／ domain 主张分享出去的是 Web URL；卡片若要做属于本读模型衍生，不得另造「分享专用价」
- 分歧根因：brief「不做微信专属能力」与 ADR-017「分享信息归 F-002」并列表述。
- 选项 A：本包只保证链接能打开，用系统默认分享 — 代价：admin 称运营只能发裸 URL
- 选项 B：本包做标题/描述/封面（公开字段或静态页/HTML 头） — 代价：miniapp 称自定义分享要公众号绑定、JS 安全域名、鉴权，等于半个用户运营系统；与「不做仅微信可用能力」冲突

### C-6 未上架内部预览 vs 禁止 admin cookie 当公开预览
- 各方主张：admin 主张后台车辆详情提供「打开前台页」（仅 published 可打开，否则明确不可用），用同一套 `/public/*`；并问未上架是否允许内部预览（走 admin 预览而非 public） ／ domain 主张禁止把 admin cookie 复用到公开页当「内部预览」而不做独立、显式的预览模型（brief 未要预览） ／ api 主张 F-002 无草稿预览；不要假设前台还会显示「已下架」占位 ／ qa 未要求预览入口 ／ miniapp 未要求预览
- 分歧根因：运营「发链接前先当访客看一遍」（admin）与 brief 未要预览、公开端无身份（domain）。
- 选项 A：仅对 published 生成与访客相同的 public URL，未上架不可预览 — 代价：admin 称已上架编辑立即对客生效，没有「预览未发布稿」
- 选项 B：未上架走独立 admin 预览模型 — 代价：domain 称须显式预览模型，不能复用 admin cookie 冒充 `/public`；本包范围扩大

### C-7 公开 GET 缓存：短 TTL vs ADR-005「无缓存延迟」
- 各方主张：api 主张公开 GET 可短缓存，但下架必须尽快失效；问是否允许 CDN/HTTP 缓存及改价/下架后最长可见延迟 ／ domain 主张下架后立即从公开读模型消失，不做缓存延迟（并引用 ADR-005） ／ qa 主张测试需要「下架后立刻打公开接口」；若 CDN 缓存 HTML/接口则与 ADR-005 冲突，必须给出可测 TTL/禁用范围 ／ admin 问已上架改价后客户打开中的详情要不要强调以刷新后服务端为准、缓存头/CDN 策略让运营知道「改完最多多久能看到」 ／ miniapp 主张不要假设存在「审核中缓存版本」
- 分歧根因：性能/CDN 短缓存（api）与零容忍「下架仍可见 / 价格错误」（ADR-005、qa）。
- 选项 A：公开接口禁止缓存或 TTL=0，下架/改价立即以新 GET 为准 — 代价：api 称索引与成本、移动端重复拉全量
- 选项 B：允许短缓存并规定最长可见延迟 — 代价：domain/qa 称与「立即不可见」验收口径冲突；错误价格可能在 TTL 内继续被看到

### C-8 列表分页策略：按可增长分页 vs 一百台一页倒完
- 各方主张：api 主张列表分页按可增长规模设计，一百台是当前规模不是硬上限（ADR-007） ／ domain 主张不按「一百台」一次拉全量 ／ admin 问列表一页多少条、是否分页、一百台是否一页倒完，称手机优先默认策略要产品定、管理后台不代定 ／ qa 称分页 size、列表深链未定义 ／ miniapp 主张防首屏拉全量原图，未主张列表车辆一次拉完
- 分歧根因：ADR-007 可增长 vs 当前一百台规模的产品默认未写。
- 选项 A：列表必须分页，禁止按一百台一次拉全量 — 代价：须定 pageSize 与深链规则（qa）
- 选项 B：一百台内一页倒完 — 代价：api/domain 称与可增长设计不一致，规模上去后实现要推翻

### C-9 空值/空字段：原样渲染 vs 按空不展示
- 各方主张：domain 主张前台若自行隐藏空字段即业务判断，若原样渲染可能出空白行；问能源联动空字段、无评估报告、价格历史仅「未填写→首价」一条时如何展示、谁定义「空」 ／ qa 主张排量/电耗/电池空值是隐藏行、显示「-」还是空字符串未定；里程 0、过户 0、超长车况截断未定 ／ admin 问图片说明为空时是否留空、是否允许不填说明就上架（发布校验目前只卡张数） ／ api 未单独主张空值 UI，但主张前台不得猜字段 ／ miniapp 未主张空值行策略
- 分歧根因：哑终端「数据决定可见性」与契约未给「是否展示」标志。
- 选项 A：原样展示服务端字段（空也渲染） — 代价：domain/qa 称可能空白行
- 选项 B：按空值不渲染或显示「-」 — 代价：domain/qa 称前端自行判断可见性，与 brief 哑终端冲突，除非本包写死映射表并作为测试夹具

### C-10 「回收站不可见」是否纳入本 feature 当前验收
- 各方主张：qa 主张 F-005 尚未上线、F-001 本期无软删除字段，「回收站」本 feature 无法验收；公开过滤只能测 draft/unpublished，除非 F-005 已约定删除模型 ／ domain 主张 brief 把回收站当作已存在的不可见源，域上可能不存在该状态；问本期是否只约束 draft/unpublished ／ api 主张回收站（F-005）若引入删除态，公开查询必须继续排除，与未上架相同 404 ／ admin 主张进回收站后前台必须不可见，文件级回收属 F-005/存储 ／ miniapp 主张删除后仍返回即零容忍
- 分歧根因：brief 成功标准含回收站；F-005 未落地。
- 选项 A：F-002 当前只验收 draft / unpublished，回收站等 F-005 后补 — 代价：brief 字面成功标准本包不能勾完（qa）
- 选项 B：本包验收必须含回收站不可见 — 代价：qa/domain 称没有独立状态可测；须先有 F-005 删除模型

### C-11 微信内「新标签打开报告」失败是否算本包失败
- 各方主张：miniapp 主张 iOS 微信常内嵌预览或下载拦截，ADR-010 在微信里可能变成当前 WebView 打开或失败，需产品确认可接受降级（当前页打开 / 提示用系统浏览器），不要为保存去申请文件权限 ／ qa 问新标签被浏览器拦截算不算失败；微信当普通浏览器测 ／ admin/api/domain 按 ADR-010 新标签打开原文件写要求，未写微信降级
- 分歧根因：ADR-010 的浏览器语义 vs 微信 WebView 行为。
- 选项 A：微信内必须仍「新标签打开」否则验收失败 — 代价：miniapp 称端表现不一致，可能不可控
- 选项 B：接受当前 WebView 预览或提示系统浏览器 — 代价：与 ADR-010 字面不完全一致，须产品定降级文案（miniapp）

## 无人认领的空白
<!-- 所有角色都默认别人会处理的事。这一节最有价值，务必仔细找 -->

以下条目：**没有任何角色写明由本角色负责定稿或实现**，只出现在「问题 / 对其他端要求 / 风险」里。

1. **面谈精确对外文案**（是否唯一「面议」、是否允许多种文案）以及 **具体金额格式**（小数位、千分位、是否带「万」/货币符号、面谈时金额为空是否禁止显示 0）。admin 要求两端用词一致但不代写文案；api/domain 只争归属；qa 声明没有定稿值就无法测。
2. **价格变动记录的默认条数、是否全量、分页 vs 加载更多 vs 仅截断、pageSize 上限、排序方向（新到旧/旧到新）、每条是否展示类型+金额+时间**。五份评审都指出 ADR-014 已废、须本包定稿，无人给出数字或声明「由我写入契约」。
3. **后台详情是否必须比前台看到更多价格历史条数**（仅 admin 提问）。无人认领后台全量 vs 公开截断的合同。
4. **列表卡片必须展示的字段清单**（不要图/价时访客如何点选）。qa 要求可勾选表格；admin/api/domain/miniapp 均未提交一份字段表。
5. **除价格/图片/报告外的「核心字段」是否超出 F-001 公开 schema**（仅 api 提问）。无人认领「访客必须多看到的字段」。
6. **空列表（一台都未上架）的页面文案、是否允许空态上线**（仅 qa 提问）。无人认领文案。
7. **详情深链 / 列表分页深链的 URL 规则**；链接标识用内部车辆 ID 还是别的；ID 可被遍历是否可接受（admin 问标识；qa 问 URL 规则）。无人认领路由方案。
8. **浏览中途车辆被下架：整页失败态、是否禁止用部分成功数据拼出「车还在、价没有」**。qa 要求统一失败态但写明「未定义则列为问题」；api 只称列表已发出、详情稍后 404 属正确行为，未定义页面文案。无人认领用户可见文案。
9. **接口 5xx / 超时 / 部分资源失败的用户可见文案与重试是否属于本 feature 验收**（qa 提问；api 仅说前台对 5xx 可重试 GET、对 404 不得当成功）。无人认领文案与验收边界。
10. **无评估报告时入口隐藏还是展示不可点；多份如何列出（文件名、上传时间）；是否展示上传人；是否要「主报告」标记；详情默认打开哪一份**（admin/api/qa/domain 各问一段）。无人认领报告信息架构。
11. **图片说明为空是否仍占位；点击图是灯箱还是原链新开；桌面是否才有灯箱**（qa/admin）。无人认领交互。

## 需要用户裁决的问题

1. 「面谈」对访客的唯一文案是什么？由公开接口下发字符串，还是允许前台对 `type` 做唯一死映射？是否允许多种文案？后台是否必须与前台用同一词？
2. 具体金额如何格式化（小数位、千分位、「万」、货币符号）？面谈且金额为空时前台如何渲染（且不得显示 0 是否成立）？
3. 价格变动记录默认展示几条？超出是分页、加载更多，还是仅截断且不提供更早记录？是否允许访客看全部历史？pageSize 上限？排序新到旧还是旧到新？每条是否展示类型+金额+时间？后台是否必须能看到比前台更多条数？
4. 公开价格历史是否禁止展示操作人、操作账号、任何内部备注？
5. 列表卡片必须展示哪些字段？要不要封面图、要不要当前价？若要，是扩展 `GET /public/vehicles`，还是允许前台对每条再打 images/price（含 N 辆请求上限与单条 404 展示）？
6. 服务端是否保证缩略图字段，还是同一原图 URL 由前端/CDN 拼参数？
7. 公开列表排序规则是什么（id 降序 / 上架时间 / 改价时间 / 手动顺序）？要不要置顶？前台是否禁止任何本地重排/筛选/搜索？
8. 列表一页多少条、是否分页？一百台是否允许一页倒完？列表/详情分页深链 URL 规则是什么？
9. 访客打开已下架/回收站/乱猜 id 的详情时：一律当不存在，还是可区分文案（含是否提示「已下架」）？正在看详情时车辆被下架，用户下一步看到什么？
10. 下架后旧图片/报告直链仍能打开，产品是否接受？测试判通过还是失败？页面 404 与文件仍 200 如何写进联调用例？
11. F-005 上线前，「回收站中不可见」如何验收？本 feature 是否先只验收 draft / unpublished？
12. 运营发链接前，是否需要管理后台「以访客身份打开前台页」？未上架车辆是否允许内部预览（独立 admin 预览，而非 public）？是否提供可复制的单车前台链接？标识用内部车辆 ID 还是别的？ID 可被遍历是否可接受？
13. 微信/浏览器分享卡片的标题、描述、封面是否本包要做？字段从车辆哪几个已有属性来，还是新增只读投影？若不做，是否确认运营只发裸 URL？与「不做微信专属能力」如何划分？
14. 评估报告：无报告时入口隐藏还是不可点？多份如何列出（文件名、上传时间、是否上传人）？是否要「主报告」？默认打开哪一份？微信内无法新标签、只能当前 WebView 预览或提示系统浏览器是否可接受？新标签被拦截算不算失败？
