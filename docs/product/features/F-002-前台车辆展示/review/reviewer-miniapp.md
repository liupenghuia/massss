## 我理解的需求

F-002 面向访客，无登录，用手机打开链接浏览已上架车辆的列表与详情：公开字段、图片及说明、评估报告、当前价格与价格记录。前台是哑终端，只渲染 `/public/*` 已返回的数据，不上架过滤、不做「面谈还是数字」判断。交付形态为 Web（ADR-001），**明确不做微信小程序、不做仅微信可用的专属能力**。草稿/下架/回收站车辆前台不可见依赖服务端 `published` 过滤。评估报告按 ADR-010 新标签打开原文件。手机竖屏第一，桌面兼容。

本角色结论与原则一致：**本期不应引入小程序技术栈**。评审范围转为：若将来误做成小程序会踩哪些审核/隐私坑，以及**当前 Web 在微信内置浏览器里打开链接**时必须满足的隐含约束（这才是真实流量路径）。

## 我的方案倾向

- **不做小程序。** 与 principles、brief、ADR-001 一致。车辆展示 + 发链接给客户看，H5 足够；做小程序会引入类目资质、用户隐私保护指引、登录/openid 压力，且与「前台无用户体系」直接冲突。
- **微信内 H5 当一等公民。** 客户点链接大概率在微信 WebView。不要用 `wx.miniProgram`、`wx.getUserProfile`、仅小程序可用的开放标签。分享、打开 PDF、图片预览都按普通浏览器能力设计。
- **不获取 openid/unionid，不静默登录。** 前台无用户体系。H5 也不要走微信网页授权（snsapi_base / userinfo），否则等于偷偷建用户身份，违反原则。
- **不申请位置、相机、相册写入、通讯录等隐私接口。** 浏览列表/详情不需要。图片用 CDN 直链 + 页面内预览即可；评估报告用新窗口打开原文件 URL，不要拉起「保存到微信文件」之类仅微信能力。
- **包体积/分包不适用小程序包规范。** 落到 Web：首屏列表要轻（缩略图 URL 由服务端/CDN 给出，前端不本地拼业务规则）；详情图按公开接口顺序懒加载。一百台以内仍要防首屏拉全量原图。
- **审核类目：无小程序则无微信审核。** 若有人提议「顺便做个小程序方便转发」，二手车/汽车销售类目通常要营业执照及对应资质，且小程序主体与业务要一致——成本与「月度云支出 500、质量优先」不匹配，应拒绝。

## 反对/风险

| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 把前台做成小程序或「小程序壳套 H5」 | 与 ADR-001、brief「明确不做」冲突；会逼出登录态、openid、类目资质、隐私弹窗，且审核周期不可控。 |
| 高 | 微信内 H5 为拿分享统计/静默标识去走 OAuth | 获取 openid 即用户身份，违反「前台无用户体系」。且网页授权域名、备案、回调都要配，超出本 feature。 |
| 中 | 评估报告 PDF 在微信 WebView 内「新标签打开」行为不一致 | iOS 微信常内嵌预览或下载拦截，Android 表现不同。ADR-010 的「新标签打开原文件」在微信里可能变成当前 WebView 打开或失败。需产品确认可接受降级（当前页打开 / 提示用系统浏览器），前端不要为了「微信可保存」去申请文件权限。 |
| 中 | 长图/多图预览在微信里被手势或内存限制打断 | 每车最少 4 张、数量无上限。微信 WebView 对大图、连续预览更易白屏。服务端必须给可直接展示的公开直链和明确顺序；前端不做业务过滤，但必须按返回顺序懒加载。错图属于零容忍，不能靠前端「猜默认图」。 |
| 中 | 误用微信 JS-SDK（分享自定义卡片、预览图片 wx.previewImage） | brief 写明不做仅微信可用专属能力。自定义分享标题/封面要公众号绑定、JS 安全域名、鉴权接口，等于半个用户运营系统。应使用系统默认链接分享。 |
| 低 | 把「手机竖屏第一」理解成小程序 rpx/胶囊对齐 | 本期是响应式 Web。安全区、微信底部工具栏遮挡属于 H5 布局问题，不要用小程序自定义 tabBar 思路。 |
| 低 | 包体积焦虑导致把图片打进前端仓库 | 原则已要求对象存储 + CDN。小程序主包 2MB 限制在此不适用；Web 同样禁止把车图打进静态资源。 |

## 对其他端的隐含要求

**对服务端（/public/*）**

- 列表/详情必须是**无需 Cookie、无需 Authorization、无需微信 code** 的公开接口。带鉴权头则微信内 H5、普通浏览器、复制链接转发全部失败。
- 未上架/草稿/回收站不得出现在公开接口；前台不做状态判断。删除后仍返回即零容忍。
- 图片字段必须是 **CDN/对象存储 HTTPS 直链**，顺序即展示顺序。不要返回需微信临时 token、防盗链按 Referer 卡死微信域名的 URL（微信 WebView Referer 与外部浏览器不同，易出现「浏览器能看、微信里裂图」——裂图叠加错配风险）。
- 评估报告给出**可匿名 GET 的原文件 URL**（HTTPS）。不要依赖小程序 `wx.downloadFile` 或需登录的 `/admin` 下载。
- 价格与价格记录的展示形态（条数、分页、面议文案）由接口数据表达，不要让前端根据「微信环境」改文案或藏价格。
- 不要为「识别微信用户」加静默 code 换 openid 的旁路接口。

**对前台 Web**

- User-Agent 含 MicroMessenger 时：**不引导「去小程序打开」、不调用 wx 对象、不弹获取用户信息。**
- 分享即复制当前 URL 或系统分享；不实现微信自定义分享卡片。
- 文件预览/外链在微信内可能被拦截：失败时的提示文案需产品定，但不能改成「请授权文件权限」。
- 不读写剪贴板、不获取位置「附近车辆」。

**对管理后台**

- 上架即对「可能在微信里打开的公开链接」生效。后台选图、写图片说明、传评估报告必须保证公开 URL 与车辆绑定正确（错配零容忍）。
- 不要在公开页嵌入仅后台能带 cookie 访问的图/PDF。
- 改价/下架后公开接口立即与前台所见一致；不要假设小程序有「审核中缓存版本」。

**对运维/域名**

- 公开页、API、CDN 均 HTTPS。微信内混合内容会直接拦图和 PDF。
- 不需要配置小程序 request 合法域名、业务域名、webview 业务域名——因为没有小程序。若有人加这些配置，视为范围蔓延。
- 对象存储防盗链白名单若要做，须包含微信相关 Referer 形态或改为签名 URL（签名过期策略需产品+服务端定，本评审不编造 TTL）。

**对产品/运营发链接方式**

- 成功标准是「发链接给客户看」，默认场景是微信聊天点开 H5，不是搜小程序。落地页必须是可复制的 https URL，不能是 `pages/index/index` 路径。

**对 F-001 / F-004 契约**

- 车辆状态过滤、价格类型（数字 vs 面谈）只在服务端/契约完成。小程序端（本角色）不要求、也不允许前端用环境变量做第二套判断。

## 我需要别人回答的问题

1. 微信聊天里打开评估报告 PDF，若无法「新标签」、只能当前 WebView 预览或提示用系统浏览器，是否可接受？（ADR-010 在微信内的降级策略谁定？）
2. 对象存储/CDN 是否计划开 Referer 防盗链？若开，微信内置浏览器 Referer 是否已纳入白名单方案？
3. 价格记录「展示条数、是否分页、面议文案」是否已在 F-004/契约定稿？本 feature 成功标准写「本 feature 内定稿」，若未定，前台无法只做哑渲染。
4. 是否确认任何里程碑都不做小程序（含「仅用于转发的壳」）？若有人另开小程序需求，是否必须新 feature + 改 principles，而不是塞进 F-002？
5. 公开图片/报告 URL 是否允许过期签名？过期后微信里长驻详情页的客户会看到裂图——可接受的过期时间与刷新策略是什么？（不确定则不要默认永久公开或默认 1 小时。）
6. 列表首屏：服务端是否保证返回缩略图字段，还是同一原图 URL 由前端/CDN 拼参数？拼参数算不算「前端加逻辑」？（原则倾向后台加字段。）
7. 桌面端「兼容」在微信 PC 客户端内置浏览器是否要测，还是只测手机微信 + 系统浏览器 + 桌面 Chrome？
