## 我理解的需求

访客不登录，用手机浏览器打开链接，浏览**已上架**车辆的列表与详情。前台是哑终端：只渲染 `/public/*` 已返回的数据，不做上架过滤、不做价格类型（面谈 vs 数字）判断。交付形态为 Web（ADR-001），不是小程序。

成功标准覆盖：列表可见；详情含公开字段、图片及说明、评估报告、当前价格；能看价格变动记录（条数、分页、面谈文案须在本 feature 定稿）；草稿 / 已下架 / 回收站车辆前台不可见（依赖服务端 published 过滤）；评估报告新标签打开原文件（ADR-010）；图片按公开接口顺序与直链展示；手机竖屏优先、桌面兼容。

明确不做：登录注册收藏询价对比下单支付、SEO/SSR、小程序及微信专属能力、前台状态过滤与价格类型判断、任何写入接口。

## 我的方案倾向

- 验收必须拆成「页面渲染契约」与「服务端过滤契约」两层：前台只断言「接口给什么就画什么」；「非 published 不可见、VIN 永不出现、下架立即不可见」全部落在 `/public/*` 的自动化接口测试上，禁止用前端二次过滤冒充通过。
- 零容忍项（价格错显、图车错配、报告串号、已删/未上架仍可见）每条都要有可重复的端到端路径：管理端造数 → 公开接口断言 → 页面断言。展示层瑕疵（缩略图裁切、加载顺序）可降级为人工抽检，不阻塞上线。
- 本 feature 必须先把「列表卡片字段、详情字段、价格文案、价格记录条数与分页、空态/404、分享链接形态」写成可勾选表格，否则无法转自动化用例。未定稿前不要把 ADR-014 已作废的「最近 20 条 / 面议」当默认实现。
- 列表公开接口不含价格与图片（现有契约），前台若要在卡片上展示价/图，必须明确是「多次请求拼装」还是「本 feature 提契约变更」；测试按最终拼装规则写，禁止前端猜字段。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 价格展示规则未定稿，无法写断言 | 成功标准写「展示条数、是否分页、面谈文案在本 feature 内定稿」，但 brief 本身没有定稿值。金额精度、千分位、货币符号、面谈时金额为空如何渲染、历史记录排序方向、默认条数、加载更多 vs 翻页，全部缺失。价格错显是零容忍，缺规则等于无法测。 |
| 高 | 非 published 不可见缺少操作路径与时序 | 「草稿、已下架、回收站不可见」依赖服务端。F-005 尚未上线、F-001 明确本期无软删除字段，「回收站」本 feature 无法验收。下架后「立即」不可见（ADR-005 不做缓存延迟）需要：列表、详情、图片、报告、价格、历史六类公开接口同时 404/不出现；浏览中途被下架的页面行为未定义。 |
| 高 | 图车错配 / 报告串号缺少验收切口 | 只说按公开接口顺序和直链展示、新标签打开原文件。未规定：详情页图片集合必须全部属于该车辆 id；说明文案与图一一对应；报告 URL 必须绑定该车；直链在车辆下架后页面是否仍可打开（ADR-010：下架后接口不返回，已生成直链不失效）。错配是零容忍，没有「错误直链不得渲染」的负向用例。 |
| 中 | 列表与详情信息架构未定义 | 列表排序（契约默认 id 降序是否即前台顺序）、分页 size、空列表文案、卡片点进详情的 URL 形态、深链打开已下架车、刷新、返回列表滚动位置，均无说明。移动端优先也未给出最小可测布局（首屏必须看到的字段、图是否进列表）。 |
| 中 | 公开字段与选填空值如何展示未定义 | 公开车辆含能源联动选填（排量/电耗/电池）。空值是隐藏行、显示「-」、还是原样空字符串？车况长文本、里程 0、过户 0 的展示未定。哑终端原则下应由数据决定可见性，但契约未给「是否展示」标志时，前端难免自己判断，与 brief 冲突。 |
| 中 | 无用户态下的异常与安全不可测项未写清 | 无登录。未规定：公开接口是否禁止缓存私人字段；query 传 status 必须被忽略；伪造 id、超大 page、并发刷列表的预期。越权属后台零容忍，前台侧对应「VIN/操作人/内部错误细节不得出现在任何公开响应或页面」。 |
| 低 | 桌面兼容无验收口径 | 「桌面端兼容」没有最小宽度、是否允许双栏、图片灯箱是否桌面才有。与移动优先冲突时以手机为准，但桌面「通过」无法自动化。 |

## 对其他端的隐含要求

**服务端 / `/public/*`（F-001、F-003、F-004 契约）**
- 列表、详情、图片、报告、当前价、价格历史：非 published（含不存在）一律按公开端约定失败（现契约详情为 404 `VEHICLE_NOT_FOUND`，禁止 403），且不得返回 vin / vinMasked / version / operatorId。
- 不接受客户端传 status 做过滤；列表默认排序与分页参数稳定，便于前台不做业务排序。
- 下架后上述接口立即不再返回该车；测试需要「下架后立刻打公开接口」的时序保证，不能依赖 CDN/应用缓存脏读。
- 价格接口只给类型 + 金额；若 F-002 选定「面议」等文案由前端写死，则契约不得中途改成下文案，否则用例双源。若改为服务端下文案，必须 RFC 改契约后再测。
- 图片列表顺序即展示顺序；每张含说明字段（可空规则要可断言）；报告为原文件 URL，可在新标签打开，不要求服务端转码/内嵌预览。
- 直链在下架后是否仍 200：服务端与对象存储策略必须写进联调用例，避免「页面已 404 但链接还能打开原图/原报告」与产品预期不一致时无法判失败。
- F-005 回收站未交付前，服务端不能承诺「回收站车辆不可见」的独立状态；公开过滤只能测 draft / unpublished。若删除是物理删，则按 404 测，需 F-005 定稿后补用例。

**管理后台**
- 必须能稳定造数：至少 4 张图 + 已填价格才能发布（ADR-003）；能分别造「具体金额」与「面谈」车辆；能对同一车追加足够多条价格历史以测分页；能下架/再上架供可见性对测。
- 后台改图顺序、改说明、换报告、改价后，前台刷新看到的必须是公开接口最新数据；需要后台操作时间戳/版本便于对账（公开端不展示 version）。
- 后台不得把 VIN 完整值打进任何会被前台误用的公开字段。
- 图片与车辆绑定、报告与车辆绑定的维护正确性是前台「不错配」的前置；前台测试发现错配应先归后台/服务端数据，而不是让前台做校验逻辑。

**前台 Web**
- 零业务判断：不根据 status 隐藏卡片、不根据价格类型分支（除非本 feature 明文规定的纯展示映射表，且映射表是测试夹具的一部分）。
- 详情页并发请求多资源时，任一资源因下架 404，整页失败态必须统一（未定义则列为问题）；禁止用部分成功数据拼出「车还在、价没有」的错误价格印象。
- 评估报告：`target` 新标签 + 原 URL，不在页内 PDF 预览；微信内置浏览器仅当普通手机浏览器测，不做 JS-SDK/分享卡片（brief 明确不做微信专属能力，ADR-017 分享信息若要做须另裁）。
- 移动竖屏为默认视口写用例；桌面只做冒烟。
- 不调用 `/admin/*`，不带登录态；页面源码与网络面板不得出现内部错误栈。

**对象存储 / CDN**
- 公开直链可匿名 GET；内容类型正确（图 vs PDF）。
- 流量与缓存头影响「下架立即不可见」：若 CDN 缓存 HTML/接口，与 ADR-005 冲突，必须在本 feature 或基础设施侧给出可测的 TTL/禁用缓存范围。
- 图片成本取向不改变正确性：懒加载失败不能显示成其他车的图。

**F-001 车辆**
- 公开列表/详情字段集即前台唯一字段来源；选填空值语义要在契约或本 feature 展示表里二选一写死。
- 发布前置不满足的车根本不会出现在前台，前台不做「图不足 4 张」的补偿 UI。

**F-003 图片与报告**
- 顺序、说明、直链、新标签打开是前台用例的预言机；变更顺序的后台操作必须反映到公开 GET。
- 已上架删图不得跌破 4 张（ADR-010）——前台可做「发布车辆详情图数量 ≥ 4」的不变量抽检。

**F-004 价格**
- 当前价与历史两条公开接口是价格用例的预言机；前台不得自己算「当前价」。
- 分页参数预留但默认策略在 F-002：联调前必须把 page/size/排序字段写成合同，否则历史用例无法稳定。

**F-005 / F-006**
- 回收站不可见不能作为 F-002 当前通过条件，除非 F-005 已约定删除模型。
- 前台无账号；F-006 越权用例不在本 feature，但公开面泄漏内部字段要纳入 F-002 安全冒烟。

## 我需要别人回答的问题

1. 面谈类价格在列表和详情的**精确文案**是什么（「面议」或其他）？具体金额的格式（小数位、千分位、是否带「万」/货币符号）以谁为准？
2. 价格变动记录默认展示几条？超出是分页、加载更多，还是不允许超出？排序是新到旧还是旧到新？是否展示每条的类型+金额+时间？
3. 列表卡片**必须**展示哪些字段？要不要图、要不要当前价？不要的话访客如何从列表判断点哪辆车？
4. 公开列表不含图和价（现契约）时，前台是否允许为每张卡片额外请求图片/价格接口？若允许，N 辆车的请求上限与失败（某辆价 404）如何展示？
5. 详情深链、列表分页深链的 URL 规则？打开非 published 或不存在 id 时，页面是统一 404 文案还是空白？正在看详情时车辆被下架，下一步用户看到什么？
6. 「回收站中的车辆前台不可见」在 F-005 上线前如何验收？本 feature 是否先只验收 draft / unpublished？
7. 评估报告：无报告时入口隐藏还是展示不可点？多份报告如何进页面？新标签被浏览器拦截算不算失败？
8. 图片说明为空时是否仍占位？0 张图是否可能出现在已上架详情（与发布前置矛盾时以谁为准）？点击图是灯箱还是原链新开？
9. 能源选填字段为空时行级显示策略？里程 0、过户 0、超长车况的展示与截断？
10. 微信/其他 App 内置浏览器打开链接：是否纳入必测矩阵，还是只保证系统 Safari/Chrome？要不要分享标题/缩略图（与「不做微信专属能力」如何划分）？
11. 下架后图片/报告直链仍可打开，产品是否接受？测试判通过还是失败？
12. 空列表（一台都未上架）的页面文案与是否允许空态上线？
13. 列表排序是否固定为公开接口的 id 降序，前台是否禁止任何本地重排/筛选？
14. 接口 500、超时、部分资源失败时的用户可见文案与重试，是否属于本 feature 验收？
15. 自动化以接口契约为主还是必须含浏览器 E2E？手机竖屏的目标机型/宽度下限？
