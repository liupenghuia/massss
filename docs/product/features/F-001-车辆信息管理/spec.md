## 状态机

见 ADR-004。三态：草稿(draft) / 已上架(published) / 已下架(unpublished)。

- 草稿 → 已上架：发布（需满足 ADR-003 发布前置条件）
- 已上架 → 已下架：下架
- 已下架 → 已上架：重新上架（同样需满足发布前置条件）
- 不支持"已下架 → 草稿"
- 编辑操作与状态转换解耦，编辑不改变当前状态
- 非法转换（如对草稿执行"重新上架"）返回错误；对已处于目标状态的重复调用视为幂等，返回成功

## 核心字段

见 ADR-002。

**必填**：品牌、车型、上牌年份、里程、颜色、车况描述、能源类型（汽油/纯电/插电混动/增程式）、过户次数（手数）

**选填（与能源类型联动）**：排量（油车/插混/增程适用）、电耗（纯电/插混/增程适用）、电池度数（纯电/插混/增程适用）

**后台专用**：车架号（VIN）——仅管理后台录入和展示，前台不展示，展示时只露后六位，不要求全局唯一

**不做**：车牌号、变速箱、排放标准、事故记录

## 发布前置条件

见 ADR-003。发布（草稿→已上架、已下架→重新上架）时强制校验：
- 图片数量 ≥ 4 张（依赖 F-003 数据）
- 价格已填写（依赖 F-004 数据，允许填具体数值或"面谈"，只要求非空）

任一条件不满足则拒绝发布，返回明确的缺失项提示。校验逻辑在 F-001 的发布动作里执行。

## 各端职责

**服务端**：车辆用系统自动生成的技术主键作跨 feature 关联锚点；编辑接口加乐观锁防覆盖写、
创建接口加幂等键防重复提交；`/public/*` 接口严格按 status 过滤，下架后前台立即不可见，
不做缓存延迟；记录基本操作日志（操作人/时间/车辆ID/状态变更），只落库不做查看页面。见 ADR-005、ADR-006。

**管理后台**：列表页支持按状态筛选、按关键字搜索；不做导出功能；不含价格字段（价格归 F-004）。
见 ADR-006、ADR-007。

## 边界与限制

- 本期不为 F-005（回收站）预留软删除字段，F-005 上线时需对 vehicles 表做迁移（ADR-005）
- 草稿数据在 F-005 上线前无法清除/作废，是已知限制（ADR-006）
- 不做车辆清单导出（ADR-006）
- 车辆卡片不含价格字段，价格完全归 F-004（ADR-007）
- 车辆规模"100 台以内"是当前值非长期上限，技术方案需按可增长设计（ADR-007）
- 管理后台权限：只有一种管理员角色，无只读/审核账号，不设审批流程（已在 docs/product/overview.md
  角色部分确认，对应 /conflicts 问题 9）
- 遗留待办（不阻塞本 feature，留给对应 feature 处理）：车辆下架时 F-003 图片是否需联动处理
  （问题 24，留给 F-003 评审）；F-005 删除操作允许作用于哪些状态的车辆（问题 25，留给 F-005 评审）
