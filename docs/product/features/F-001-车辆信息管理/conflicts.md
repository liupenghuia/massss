## 一致项

- 车辆以系统自动生成的技术主键作为跨 feature 关联锚点，VIN 不做唯一性约束、不作为主键（api、domain）。
- 状态机为三态（草稿/已上架/已下架），编辑与状态转换解耦，全程无审核（api、domain、qa、admin）。
- 价格、图片/报告、删除恢复分别归 F-004/F-003/F-005，本 feature 只管车辆基础信息与状态（全员）。
- 发布前置条件（图片≥4张、价格非空）依赖 F-003/F-004 数据，应由 F-001 发布接口同步查询/联表校验，不要求 F-003/F-004 反向推送状态标志位（api、domain）。
- 状态转换接口对已处于目标状态的重复调用应幂等返回成功，对非法转换返回明确错误，二者需区分（api、admin、qa均以此为测试/交互基础）。
- 编辑接口用乐观锁（版本号）防并发覆盖写，创建接口用幂等键防重复建卡（api、admin、qa均认可此设计并据此设计交互/用例）。
- VIN 为后台专用字段，仅展示后六位（domain、admin、miniapp）。
- 管理后台按响应式 Web 实现，微信内置浏览器不做小程序化改造，本场景仅涉及管理员手机操作后台，不涉及前台微信体验（miniapp）。

## 冲突项

（本次评审各方未见直接对立的方案主张，分歧多表现为"是否需要在 spec 中明确说明某已裁决设计的边界"，已并入下方"无人认领的空白"与"待裁决问题"。）

## 无人认领的空白

- 已上架车辆的图片/价格被 F-003/F-004 事后改动到不再满足前置条件（如图片降到4张以下、价格清空）：domain 指出这是"最终一致性缺口"，建议在 spec 中明确写为有意选择，但未见 api/admin/qa 对此表态谁来补这句说明、或是否需要兜底提示。
- 相同 VIN 录入到两台不同车辆是否允许保存：qa 提出问题，api/domain/admin 均未回应是否需要提示或如何提示。
- 能源类型与排量/电耗/电池度数联动的校验强度（服务端强校验字段组合 vs 仅前端展示/隐藏）：qa 提出为可测性缺口，api/domain/admin 均未给出实现归属或方案。
- 里程、上牌年份、过户次数（手数）的取值范围/格式限制，车况描述是否有长度上限：qa 提出，无角色回应校验规则由谁定义、放在 spec 还是 contracts。
- 草稿保存时必填字段是否强制非空校验：qa 提出，api/domain/admin 均未表态。
- 乐观锁冲突（VEHICLE_VERSION_CONFLICT）触发条件与响应体格式（是否返回最新数据供前端合并展示）：api 和 qa 都提到 contracts 未明确，但都是"需要别人回答"，未见谁承诺补充该契约细节。
- 测试/联调环境下如何独立构造 F-003 图片数量、F-004 价格数据（测试夹具或允许直接写库）：qa 提出为高严重度可测性缺口，api（服务端视角）未在其"对其他端的隐含要求"中回应是否提供测试夹具。
- 管理后台在微信内置浏览器（X5 内核）下的登录态持久化策略（session/cookie 行为差异）：miniapp 提出风险，但"对其他端的隐含要求"中写给服务端的建议未见 api 侧回应或承接。
- 车辆表单在手机竖屏下的字段分组/折叠方案：miniapp 提出要求，admin（管理后台开发）评审中未涉及移动端布局细节，仅讨论了信息架构层面的字段与操作入口。
- 操作日志的保留期与清理策略：api 提出为非阻塞项，admin 也提到"无查看页面"是已知限制，但两者都未认领谁负责后续制定归档策略。
- 草稿在列表默认视图中是否排除、以及缓解草稿堆积体验的具体方案：admin 提出但未给出结论，其他角色未涉及。

## 需要用户裁决的问题

1. "车况描述"字段与 overview.md 术语表中的"车辆描述"是否为同一字段；若不同，两者各自的用途和展示位置是什么？（domain）
2. 能源类型与排量/电耗/电池度数的联动，是否要求服务端强校验字段组合（如纯电禁止填排量），还是仅前端展示/隐藏？（qa）
3. 里程、上牌年份、过户次数（手数）是否有取值范围或格式限制（如年份区间、里程非负、手数计数起点），车况描述是否有长度上限？（qa、domain）
4. 草稿保存时，必填字段（品牌/车型/年份等）是否也强制非空，还是仅发布时才校验？（qa）
5. 两台车录入相同 VIN 是否允许保存，是否需要给出非阻断提示？（qa）
6. VIN 仅展示后六位这一规则是仅详情页还是列表页也适用；列表页关键字搜索对 VIN 是按完整车架号匹配还是按展示的后六位匹配（进而影响索引设计）？（admin、api）
7. 已上架车辆的图片/价格被 F-003/F-004 改动到不再满足发布前置条件后，是维持已上架状态不变（并在 spec 中明确记为有意选择），还是需要某种兜底提示/联动降级？（domain）
8. 乐观锁冲突（VEHICLE_VERSION_CONFLICT）的触发条件与响应体格式是否需要返回最新数据供前端合并展示，还是仅报错要求刷新重试，此契约细节由谁补充？（api、qa）
9. 测试/联调环境下，F-001 发布前置校验用例如何独立构造 F-003 图片数量与 F-004 价格数据（是否提供测试夹具或允许直接写库）？（qa）
10. 车辆列表页在管理后台默认是否排除草稿状态，还是完全交给筛选器由用户自行选择？（admin）
11. 操作日志是否需要保留期/清理策略（当前为"只落库不做查看页面"）？（api）
12. 管理后台在微信内置浏览器下的登录态持久化策略是否需要专门处理（session/cookie 行为与普通浏览器存在差异）？（miniapp）
