# ADR-021 F-002 范围边界与测试矩阵

Status: Accepted
Date: 2026-08-19
Feature: F-002
Related: ADR-001（走 Web 不做小程序）

## Context

`/conflicts F-002` 冲突项 C-10，以及需用户裁决问题 11、20、21。
「回收站不可见」写在 brief 成功标准里但 F-005 未落地；否定范围（不做统计、不做小程序等）
被多方提及却无人认领写成可验收条款。本文件定稿本包的范围边界与测试口径。

## Decision

### 回收站验收
- 本期**只验收 `draft` / `unpublished` 对公开端不可见**。
- 「回收站中不可见」记为 **F-005 上线时的回归项**，不阻塞 F-002 交付。
- spec 中写明不变量：**任何未来引入的删除态都必须同样被公开查询排除**，与未上架同为 404。

### 否定范围（写入 spec，作为可验收的否定条款）
- **不做**前台访问统计：浏览次数、链接打开统计、访问审计一律不做；
  更不得为统计走微信 OAuth 获取身份。
- **任何里程碑都不做微信小程序**，含转发壳。若将来要做，必须新开 feature 并同步修改
  `docs/principles.md`，不得在本包或后续实现中夹带。
- **不做**前台置顶 / 推荐位，不加管理后台新菜单、批量操作、导出、运营配置台。

### 测试矩阵
- 自动化以**公开接口契约测试为主**，覆盖可见性过滤、404 语义、分页、字段泄漏。
- 浏览器侧为**手动抽检**：微信 iOS / 微信 Android 内置浏览器 + 系统 Safari / Chrome。
- 微信 PC 端**不必测**。
- 响应式口径：手机竖屏最小宽度 **375px**，桌面最小宽度 **1024px**。
- 不引入浏览器 E2E 自动化框架。

## Consequences

+ F-002 不再被未落地的 F-005 阻塞，可独立交付。
+ 否定范围成为可验收条款，实现期不会被「顺手加个统计」侵蚀。
+ 测试口径明确，QA 不必为无法自动化的端兼容性背锅。
- brief 字面成功标准中的「回收站」本包无法勾完，需在 F-005 验收时补齐。
- 无访问统计意味着运营拿不到前台流量数据，若将来需要须另开 feature。
- 浏览器兼容性依赖手动抽检，存在回归遗漏风险，属已知接受的代价。
