# ADR-087 F-005 对象存储异步删除补偿与半清除窗口目标

Status: Accepted
Date: 2026-08-21
Feature: F-005
Supersedes: -

## Context
第二轮评审（api/domain 一致）指出对象存储异步补偿删除缺少重试上限、终止条件、告警机制；
qa 另提出"半清除窗口内前台仍可能短暂命中直链"需要一个可断言的时间阈值，否则无法验收。
spec.md 已把该窗口列为"已知限制"但未给数值。按 principles.md 默认协议，
无人认领时给出范围更小、能自证收敛的保守默认值。

## Decision
- 彻底清除任务标记 `purged=true` 后，在**同一次任务执行内**同步发起对象存储删除请求
  （不额外排队等待），失败则进入补偿重试：间隔 1 分钟、5 分钟、30 分钟三次重试，
  三次均失败后停止自动重试，仅记录一条错误日志（不接入独立告警渠道，本期告警只做到日志级别）。
- 正常情况下（无失败重试）对象存储文件应在标记 `purged=true` 后 **60 秒内**完成删除，
  这是保守目标值，不是强 SLA，供实现和验收参考；三次重试全部失败的极端情况下，
  半清除窗口最长可达约 36 分钟（1+5+30），期间直链可能仍可访问，接受为已知限制。

## Consequences
+ 把"已知限制"从无边界的模糊描述变成有具体数值的目标，验收时可以断言"60 秒内正常应删除完成"。
+ 补偿重试有明确终止条件，不会无限重试拖累后台任务队列。
- 三次重试全部失败时无人工介入通道（本期不做独立告警渠道），需要运维定期抽查错误日志才能发现，
  是本期接受的代价，后续如需更强保障可升级为接入告警系统（需另开 RFC/ADR）。
