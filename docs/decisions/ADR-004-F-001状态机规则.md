# ADR-004 F-001 状态机规则

Status: Accepted
Date: 2026-08-19
Feature: F-001
Supersedes: -

## Context

`/conflicts F-001` 问题 6、7、8：编辑是否改变车辆状态、非法状态转换如何处理、
已下架能否退回草稿，评审中 api/qa/domain 各有不同倾向，需要用户裁决统一规则。

## Decision

- 编辑操作与状态转换解耦：编辑车辆核心字段不会改变当前状态（已上架车辆编辑后仍是已上架、
  已下架车辆编辑后仍是已下架），状态变化只能通过管理员显式点击"发布 / 下架 / 重新上架"触发。
- 非法状态转换（如对"草稿"执行"重新上架"）返回明确错误，不允许静默忽略或无提示失败。
- 对已处于目标状态重复调用同一动作（如已上架车辆再次调用"发布"）视为幂等操作，返回成功且无副作用。
- 状态机固定为 草稿 → 已上架 ⇄ 已下架，不支持"已下架退回草稿"这条路径；如需大改车辆信息，
  直接编辑内容即可，不需要退回草稿这个动作。

## Consequences

+ 编辑与状态解耦，避免"改了个错别字车辆意外被下架"这类意外副作用。
+ 幂等的发布/下架接口对前端重试、网络抖动更健壮。
+ 状态机简单固定，实现和测试成本低。
- 非法转换与幂等转换的边界需要实现时用明确的状态转换表校验（例如对"草稿"调用"下架"应报错，
  而非静默成功），实现者需要仔细处理每一种组合。
