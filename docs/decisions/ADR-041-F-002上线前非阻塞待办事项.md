# ADR-041 F-002 上线前非阻塞待办事项（域名合规、真机验证、部署配置）

Status: Accepted
Date: 2026-08-21
Feature: F-002
Supersedes: -

## Context
第二轮评审（miniapp/admin 视角）提出三项不是代码能解决、也不是本 feature 范围内技术决策的事项：
1. 主站与 OSS（图片/评估报告）域名是否已完成 ICP 备案、是否需要在微信安全中心做域名检测/申诉。
2. 评估报告「新标签→当前 WebView→提示手动打开」三级降级链是否已在微信 iOS/Android 真机上验证过。
3. 管理后台运行环境是否已有前台生产域名的环境变量（`PUBLIC_WEB_ORIGIN`）可用。

按 principles.md 默认协议「无人认领 → 写入『明确不做』，或推迟到该管的 feature，并写明不阻塞本 feature」，
这三项都不阻塞 F-002 的开发与代码验收，记录为上线前必须完成、但不写代码的运营/部署待办。

## Decision
1. 域名 ICP 备案与微信安全中心自查：本期不做任何代码层面的兜底（如自建拦截检测），
   由运营在正式对外发布前自行核实，属于部署上线清单的一项，不阻塞本 feature 开发与代码验收。
2. 评估报告三级降级链的微信真机验证：纳入手动抽检测试矩阵（spec 已有"测试矩阵"章节），
   在正式发布前必须至少人工验证一次 PDF 与图片两种文件类型，不要求本 feature 开发阶段完成，
   但发布前必须补测，缺失时视为发布阻塞项（区别于开发阻塞项）。
3. `PUBLIC_WEB_ORIGIN` 环境变量：作为部署配置项，由部署时提供，不在本 feature 代码中写死默认值；
   变量缺失时管理后台"复制前台链接"入口应能明确提示配置缺失，而不是拼出一个错误的空前缀链接。

## Consequences
+ 三项都不阻塞当前开发进度，responsibility 明确写清楚是"谁在什么阶段做"，不再是无主的空白。
- 如果运营在上线前忘记核实域名备案/微信安全中心状态，或忘记做真机验证，问题会在生产环境才暴露，
  ADR 只是把责任讲清楚，不能替代实际执行，需要在发布清单（非本 ADR 范围）里再次确认这三项。
