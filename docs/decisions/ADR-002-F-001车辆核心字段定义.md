# ADR-002 F-001 车辆核心字段定义

Status: Accepted
Date: 2026-08-19
Feature: F-001
Supersedes: -

## Context

F-001 的 5 方评审一致指出"车辆卡片核心字段"未列出具体清单（reviewer-api Q1、reviewer-admin Q3、
reviewer-domain Q1、reviewer-qa Q1），是 contracts/ 与测试用例设计的阻塞项，对应
`/conflicts F-001`「需要用户裁决的问题」第 1、2 条。

## Decision

车辆核心字段定为：

**必填字段：**
- 品牌
- 车型
- 上牌年份
- 里程
- 颜色
- 车况描述
- 能源类型（汽油 / 纯电 / 插电混动 / 增程式）
- 过户次数（手数）

**选填字段（与能源类型联动）：**
- 排量（能源类型为汽油 / 插混 / 增程时适用）
- 电耗（能源类型为纯电 / 插混 / 增程时适用）
- 电池度数（能源类型为纯电 / 插混 / 增程时适用）

**后台专用字段：**
- 车架号（VIN）：仅在管理后台录入和展示，前台不展示；展示时只露后六位；不要求系统内全局唯一

**明确不做：**
- 车牌号（不采集）
- 变速箱字段（不做）
- 排放标准、事故记录等字段（超出当前范围，不做）

## Consequences

+ 字段清单确定后，contracts/ 可以定义车辆实体 schema，reviewer-api/domain/qa 提出的阻塞项解除。
+ 能源类型字段为排量/电耗/电池度数提供判断依据，避免录入时两个都填或都不填的歧义。
+ 车架号仅后台可见且部分打码，符合隐私/防越权取向，同时不要求唯一，实现简单，不引入查重逻辑。
- 不采集车牌号意味着无法用车牌做检索或去重，若未来运营需要按车牌找车，需重新评估。
- 车架号不唯一意味着系统无法通过车架号自动识别重复录入，长期运营存在重复车辆卡片的可能性（已知代价，用户已确认接受）。
