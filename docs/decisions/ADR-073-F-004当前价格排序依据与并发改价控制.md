# ADR-073 F-004 当前价格排序依据与并发改价控制

Status: Accepted
Date: 2026-08-21
Feature: F-004
Supersedes: -

## Context
第二轮评审对 F-004 数据模型提出两个相关的实现风险，均直接关系到 principles.md
零容忍项"价格历史记录丢失或错乱"：

1. "当前价格 = 最新一条记录"的排序依据用 created_at 时间戳还是单调递增序号，
   domain 视角指出并发写入或服务器时钟回拨会让时间戳排序取到错误的当前价格。
2. 同一车辆被多个管理员几乎同时提交不同价格时，是否需要事务/行锁等并发控制，
   还是接受"后写入者生效"。

按 principles.md 默认协议，未裁且不踩零容忍时选更小/更安全的一档；这两条都属于
"用更严格的工程手段消除价格错乱风险"，不是回避风险，因此按默认协议直接裁决，
不升级为需要用户明示的问题。

## Decision
1. 价格记录表用数据库自增主键（单调递增序号）作为排序依据，取该车辆记录中序号最大的一条
   作为当前价格；不使用 created_at 时间戳排序，created_at 仅作展示用途。
2. 改价写入采用"读当前最新记录 → 比较 → 条件写入"的流程，整体包在一个数据库事务内，
   并对该车辆行加行级锁（或等效的乐观锁校验），防止并发提交产生记录错乱或互相覆盖。

## Consequences
+ 排序不受服务器时钟回拨、多实例时钟不同步影响，当前价格永远可确定。
+ 并发改价场景下价格记录链不会因竞态产生错误的"变动前值"，直接兜住零容忍红线。
- 每次改价多了一次行锁开销，在车辆规模（百台以内）下可忽略；未来若车辆量级大幅上升
  需要重新评估锁粒度。
- 若未来引入分布式/多写节点部署，自增序号需要改为全局唯一的单调序列，
  当前假设是单一服务端合一部署（与 principles.md「服务端合一」一致）。
