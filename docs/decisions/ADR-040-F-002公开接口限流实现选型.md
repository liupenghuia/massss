# ADR-040 F-002 公开接口限流实现选型

Status: Accepted
Date: 2026-08-21
Feature: F-002
Supersedes: -

## Context
第二轮评审（api 视角）提出：公开接口 IP 级限流的存储载体（进程内存 vs 集中式如 Redis）
未定，与部署形态（单实例 vs 多实例水平扩展）耦合。当前实现（server/src/lib/ipRateLimit.ts、
server/src/middleware/publicGuard.ts）已经是进程内存实现。按 principles.md 默认协议，
选范围更小、本期能上线的一档，本 ADR 对既成实现补一条正式记录。

## Decision
IP 级限流本期采用单实例进程内存计数，不引入 Redis 等集中式存储。
接口设计上保持可替换（限流逻辑独立于路由层），未来如需水平扩展多实例部署，
再切换为集中式存储实现，不需要改动调用方。

## Consequences
+ 不引入新依赖（Redis），符合 principles.md "不要用feature flags/不必要的抽象" 与
  "不引入新依赖，确实需要时先问" 的取向，当前 100 台规模、单实例部署下够用。
- 多实例水平扩展后，各实例限流计数互不可见，实际限流阈值等于「单实例阈值 × 实例数」，
  达不到设计时预期的总量控制，需要在真正扩容前记得切换实现，否则限流形同虚设。
