# ADR-112 UI 改造第一批交互与入口规则

Status: Accepted
Date: 2026-08-24
Feature: F-001, F-002, F-003, F-005, F-006
Supersedes: ADR-025（仅「恢复不需要二次确认」一条）；ADR-020（仅前台 5xx/超时错误文案一条）

## Context

管理后台与前台已按 Organic 设计系统落地。第一阶段体检与第二阶段方案要求补齐入口可达性、
破坏性操作确认一致性、字段就地校验、回收站分页控件与前台失败文案。实现只改前端，
不改 `server/` 与契约。若干条款与既有 spec/ADR 字面冲突，需要写明新口径。

## Decision

1. **自行改密入口（F-006）**  
   能力不变（权限矩阵「修改自己的密码」管理员与超管均为 ✅）。入口从超管专属的账号管理页
   拆出：所有已登录账号经顶栏「我的资料」（`/profile`）改自己的密码；`/accounts` 只保留
   超管对他人账号的生命周期操作。强制首次改密仍走 `/password`，规则不变。

2. **破坏性操作确认（F-003 / F-005 / F-006）**  
   一律用站内对话框（`.dialog`），不再使用 `window.confirm`。  
   - 删除图片/报告、移入回收站、重置他人密码：继续要二次确认。  
   - **恢复为草稿：改为需要二次确认**（推翻 ADR-025「恢复不需要」）。  
   - **停用账号：需要二次确认**。启用账号不需要。  
   - 改价仍不二次确认（ADR-013 不变）。

3. **封面与排序（F-003）**  
   第一张图仍是封面。新增「设为封面」与键盘左右移，均调用既有 `adminReorderVehicleImages`，
   不新增接口。拖拽排序自动保存规则不变。

4. **录入就地校验（F-001）**  
   草稿保存仍不强制品牌/车型非空（ADR-035）；界面标「建议填写」，不拦创建。  
   管理后台对上牌年、里程、过户次数做控件级边界与字段下错误提示：上牌年 1980–当年、
   里程 ≥0、过户 0–20。服务端取值范围仍以 ADR-038 为准（上牌年 1980–2100、过户为非负整数、
   无 20 次上限）。VIN 创建后只读，界面说明「创建后不可修改」。  
   新建流程在界面标明两段式（先创建再传图），不改变「图片要求车辆已存在」的既有规则。

5. **回收站列表（F-005）**  
   前端接上既有分页接口，默认 `pageSize=20`（接口上限 100）。超过一页的记录必须能翻到。  
   「查看详情」在当前行就地展开并高亮来源行。

6. **前台失败与空结果文案（F-002）**  
   网络断开、服务端失败、筛选无结果分成三套用户能看懂的下一步文案，不再统一写
   「加载失败，请重试」。列表完全无在售车辆仍用「暂无在售车辆」，不视为系统错误。  
   详情价格记录按接口分页拉取（`pageSize=100`）；若 `total` 大于本页条数，提示
   「仅显示最近 N 条」，本期不做「查看更多」。

## Consequences

+ 普通管理员能改自己的密码，不再依赖超管重置。  
+ 破坏性操作确认规则可预测，恢复/停用不易误触。  
+ 回收站超过 20 条不再在界面上「消失」。  
+ 前台失败时用户知道该重试还是换条件。  

- 恢复多一次确认，高频误恢复场景变慢（当前车行规模可接受）。  
- 过户次数控件上限 20、上牌年上限「当年」严于服务端；合法但少见的值（如期货年上牌年、
  过户 >20）会被控件拦住，需改服务端或放宽控件时另开 ADR。  
- 价格记录超过 100 条时前台不再承诺「全量展示」（部分覆盖 F-002 原验收「无分页」）。  
- 列表封面仍依赖每车一次 images 请求（契约未加 `coverUrl`），只消除了逐条 setState 闪动。
