# ADR-074 F-004 金额存储与数值归一化规则

Status: Accepted
Date: 2026-08-21
Feature: F-004
Supersedes: -

## Context
第二轮评审提出金额的存储类型未定（decimal/整数分/浮点），以及"变动判定"中数值相同的
精确等价类未定义（如 10.1 与 10.10 是否算同一金额），可能导致精度丢失或误判为"有变动"
而多写入记录。属于纯技术实现细节，未涉及业务口径分歧，按默认协议选更小范围的方案直接裁决。

## Decision
金额以最小货币单位（分）的整数形式存储，即以人民币元为单位、最多 2 位小数的输入值
乘以 100 后存为整数。"变动判定"直接比较这个整数值是否相等，天然消除小数精度与
表示法差异（10.1 与 10.10 输入后归一化为同一个整数，判定为无变动，不写记录）。
接口输入输出层仍以"元"为单位的数值/字符串对外呈现，内部存储与比较用整数分。

## Consequences
+ 彻底避免浮点数精度丢失问题，"变动判定"结果确定、可测试。
+ 不需要额外维护小数位归一化逻辑，转换规则单一（乘/除 100）。
- 接口边界需要做一次单位换算（元 ↔ 分），需要在入参校验时确认换算前后precision 一致，
  超出 2 位小数的输入应在换算前就被 VALIDATION_ERROR 拒绝，不能依赖换算兜底。
