# ADR-012 F-004 价格记录数据模型与生命周期规则

Status: Accepted
Date: 2026-08-19
Feature: F-004
Supersedes: -

## Context

`/conflicts F-004` 问题 3、4、5、6、7、8、9、10、17、20：价格数据模型、"已填写"判定依据、
首次设价与面谈互转是否算变动、重复提交处理、纠错机制、价格能否清空、数值规则、
备注字段、创建时能否直接带初始价格，是本 feature 数据模型和生命周期层面的一组决策。

## Decision

- 不单独建"当前价格"快照表，当前价格 = 该车最新一条价格记录的"变动后值"。
- "价格是否已填写"（供 ADR-003 发布校验使用）= 该车价格记录表中是否存在至少一条记录。
- 首次设置价格算一次变动，生成一条记录，"变动前值"用显式"未填写"占位（不是 0 或空字符串）。
- "面谈"与具体数值之间互相切换，算一次变动，生成记录。
- 提交与当前价格完全相同的值时，拦截提交，不生成"无变化"记录。
- 不提供任何编辑/删除已生成价格记录的入口；改错价格没有特殊纠错手段，只能再次改价覆盖，
  错误记录会永久保留在历史里。
- 价格一旦设置，不允许清空回"未填写"状态，只能改成另一个值（具体数值或"面谈"）。
- 价格单位为人民币元，只允许整数，不允许 0 或负数，暂不设上限。
- 价格记录不设备注/原因字段，只存变动前值、变动后值、变动时间、操作人四项。
- 车辆创建时可以在同一次提交里直接带初始价格，内部同步调用一次改价逻辑生成第一条记录。

## Consequences

+ 数据模型简单（只有历史表，无快照表），当前价格永远与历史记录一致，不存在双表不同步风险。
+ 价格不可清空，避免"已上架车辆价格未填写"这类与 ADR-004 状态机冲突的悖论状态。
+ 拦截重复提交、不做"无变化"记录，价格历史保持干净，只反映真实变动。
- 没有纠错手段意味着运营手误改错价格后，错误记录会永久留在前台可见的历史里，
  这是"历史记录不可篡改"零容忍项的直接代价，用户已知悉并接受。
- 不设价格上限，极端异常输入（如多输入几个 0）没有系统层面的拦截，依赖运营自己核对。
