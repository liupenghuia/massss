# ADR-058 F-003 批量上传逐文件响应契约

Status: Accepted
Date: 2026-08-21
Feature: F-003
Supersedes: -

## Context
第二轮评审（admin/api 视角）指出：批量拖拽上传"部分失败不影响其余"已定稿（ADR-008），
但服务端响应是否包含逐文件级别的成功/失败结果、前端是否支持单文件重试，未明确，
影响 admin-web 的失败呈现方式。

## Decision
批量上传时，每个文件仍是独立的预签名+确认调用（不做批量事务打包，维持 ADR-009 现状），
但前端在本地聚合每次调用的结果，按文件展示"成功/失败+失败原因"的逐项列表。
不做单文件自动重试功能，失败的文件由管理员手动重新选择上传，不新增专门的"重试"入口。

## Consequences
+ 管理员能看清楚具体哪几个文件失败、原因是什么，不用靠"N张失败请重新上传"这种笼统提示猜测。
- 前端需要维护一份本次批量上传的逐文件状态列表（进行中/成功/失败），比整体进度条复杂；
  失败文件需要管理员手动找回并重新拖拽，没有一键重试，操作步骤略多。
