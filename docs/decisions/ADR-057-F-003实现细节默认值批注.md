# ADR-057 F-003 实现细节默认值批注（第二轮评审收尾）

Status: Accepted
Date: 2026-08-21
Feature: F-003
Supersedes: -

## Context
第二轮评审（api/domain/qa/admin/miniapp 视角）提出一批非零容忍、非状态机/权限/价格类的
实现细节问题，均未在 principles.md/overview.md/已有 ADR 中写明。按 principles.md
「评审与改需求的默认协议」，无人明确认领且不踩零容忍红线时，选择范围更小、本期能上线的一档。

## Decision
1. **孤儿文件**：客户端直传成功但从未调用 confirm 产生的孤儿对象，本期不做任何清理
   （不设 TTL 回收、不做定时任务），写入"明确不做"，推迟到后续评估，不阻塞本 feature。
2. **评估报告区分字段**：不新增"评估机构名称/报告类型"等字段，维持现状仅靠上传时间和
   文件名区分同一车辆下的多份报告。
3. **图片说明文案（caption）**：长度上限 200 字符，允许空字符串。超出长度返回 VALIDATION_ERROR。
4. **单车图片数超 100 张告警**：仅写入操作日志（沿用 ADR-006/ADR-009 的操作日志机制），
   不做后台可见提示、不做运维通知，最小实现。
5. **删除跌破 4 张下限的前端预判**：前端不做提前禁用/预判提示，统一依赖服务端拒绝
   （PUBLISHED_IMAGE_MIN）后在弹窗内展示服务端返回的原因，避免前后端校验口径不一致。
6. **域名微信安全策略自查（ADR-011 遗留项）**：作为部署阶段前置条件，由负责部署的人员
   在域名最终确定后自查一次并留痕，不列入本 feature 的自动化验收清单，处理方式与
   ADR-011 已定的"域名备案"同一挂钩点。
7. **上传人字段**：图片/评估报告列表本期不展示"上传人"字段，与现状操作日志"只落库不做
   查看页面"（ADR-006）保持一致。
8. **拖拽排序保存方式**：拖拽完成后自动保存，不需要管理员显式点击"保存排序"按钮。

`adminReorderVehicleImages` 传入图片 ID 列表与该车实际图片集合不一致时的处理，
以及公开直链是否加防盗链/Referer 白名单这两点，contracts/errors.yaml 已有
IMAGE_ORDER_MISMATCH（拒绝整批，不部分生效）与 ADR-009（维持公开直链现状，不做校验）
两条已定稿口径可以直接对应，不属于本轮新决策，仅在 open-questions.md 中标注引用。

## Consequences
+ 八项均按"更小范围、更快上线"的默认值收敛，避免非核心问题阻塞开工。
- 第1项意味着孤儿文件会在对象存储里长期累积，产生存储成本浪费，后续需要专项清理机制。
- 第4项意味着超量图片目前无法被主动发现，只能靠管理员自行注意或事后翻查操作日志。
- 第6项把责任放在人工流程上，如果部署人员遗漏，域名被微信拦截的风险要到上线后才会暴露。
