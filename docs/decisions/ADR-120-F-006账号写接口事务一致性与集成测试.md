# ADR-120 F-006 账号写接口事务一致性与集成测试

Status: Accepted
Date: 2026-08-25
Feature: F-006
Supersedes: -

## Context

ADR-119 落地账号删除功能后，实测发现一个真实 bug：`listAccounts()`（读路径）漏加了
`deleted_at IS NULL` 过滤，导致已删除账号仍显示在列表里，误导用户重复点击删除并触发
"账号不存在"报错。排查过程中系统性摸排 `server/src/routes/adminAccounts.ts`，发现角色变更
（`/role`）、重置密码（`/password-reset`）两个接口存在同一类风险：主变更（`setAccountRole`/
`updatePassword`）在事务外直接执行（自动提交），审计记录（`insertOperationLog`）再单独开一个
事务写入——若审计写入失败，主变更已经落库但接口向调用方返回错误，造成"数据已变、响应说没变"
的不一致。删除接口本身在 ADR-119 落地时也是同一种写法。

同时摸排发现 `server/src/routes/*.ts` 下所有路由文件完全没有集成测试覆盖，现有测试只在
`lib/`、`services/` 的纯函数上，路由层的权限、状态转换、事务边界这类编排逻辑没有自动化验证——
这次的 bug 如果有一个基本的路由测试，本可以在提交前拦下。

## Decision

### 事务一致性
- 账号写接口（角色变更 `/role`、重置密码 `/password-reset`、删除 `/delete`）统一改为：
  主变更 + 审计写入在**同一个事务**内提交，与 `status` 接口原有的正确写法对齐。
  `setAccountRole`、`updatePassword`、`deleteAccount`、`revokeAllSessionsForAccount`
  均新增可选 `client: PoolClient` 参数，供调用方传入同一事务连接；不传时退化为独立
  `pool.query`（保持 `adminAuth.ts` 里自助改密等既有调用不受影响）。
- 任一环节失败，整个事务回滚，不会出现"主变更生效但响应报错"的中间态。

### 集成测试基础设施
- 新增本机独立测试库 `mallsss_test`（与开发库 `mallsss` 完全隔离），跑同一套
  `server/migrations/*.sql`。
- 新增 `supertest`（devDependency）对 Express `app` 实例直接发请求，不需要真实监听端口；
  为此将 `server/src/index.ts` 中的 app 定义拆分到 `server/src/app.ts`，`index.ts` 只保留
  种子脚本 + `app.listen`。
- 新增 `vitest.integration.config.ts`，独立于单测配置（`src/**/*.integration.test.ts`，
  单测配置显式排除该 glob），通过 `npm run test:integration` 单独执行，不进入默认
  `npm test`（本仓库无 CI，集成测试需要本机数据库，不适合作为默认门禁的一部分）。
- 首批集成测试覆盖 `adminAccounts` 路由：删除接口的核心场景（含专门复现"列表未过滤已删除
  账号"这次 bug 的回归用例）、角色变更与密码重置的事务一致性、权限校验。其余路由模块
  （vehicles/images/reports/prices/recycle）暂不覆盖，后续按需补齐。

## Consequences

+ 消除了账号写接口"数据已变、响应说没变"的不一致窗口，三个接口（role/password-reset/delete）
  与 status 接口现在遵循同一套正确的事务模式。
+ 新增的回归测试实测验证有效：手动改回有 bug 的 `listAccounts` 实现重跑测试，测试如预期失败
  （`expected [...] to not include <id>`），证明这套测试基础设施真的能拦住这类问题。
+ 为后续给其他路由模块（vehicles/images/reports/prices/recycle）补集成测试铺好了基础设施
  （测试库、`app.ts` 拆分、vitest 集成配置），边际成本更低。
- 集成测试依赖本机手动创建的 `mallsss_test` 库和迁移，新加入的开发者需要额外一步环境搭建
  （`createdb mallsss_test && PGDATABASE=mallsss_test npm run migrate:up`），未自动化建库。
- 仍只覆盖 `adminAccounts` 一个模块，其余 9 个路由文件依然零集成测试覆盖，这次只是打通
  基础设施，没有解决"路由层整体测试覆盖不足"的问题。
- 无 CI，集成测试和单测一样仍然依赖人工在本地主动执行，不会自动拦截未经测试验证就提交的改动。
