# ADR-009 F-003 服务端与存储规则

Status: Accepted
Date: 2026-08-19
Feature: F-003
Supersedes: -

## Context

`/conflicts F-003` 问题 6、7、8、11、12、13、14、20：上传路径、文件格式/大小限制、
访问链接策略、跨 feature 查询方式、操作日志、权限、删除后存储清理、敏感信息处理，
是本 feature 服务端与存储层面的一组相关决策。

## Decision

- 图片/评估报告上传采用客户端直传对象存储 + 预签名 URL，服务端只做元数据落库确认。
- 文件限制（工程默认值，后续可按实际情况调整）：图片支持 jpg/png/webp，单张 ≤10MB；
  评估报告 PDF/PNG/jpeg，单份 ≤20MB；单车图片数超过 100 张只告警不阻断。
- 图片/评估报告的对象存储访问链接为公开直链，不做签名/鉴权；车辆下架后已生成的链接
  不做失效处理，只保证 `/public/*` 查询接口不返回已下架车辆的数据。
- F-003 向 F-001 暴露"车辆当前图片数量"的查询能力做成进程内方法调用（服务端合一，
  不走 HTTP），供 ADR-003 的发布校验使用。
- F-003 的上传/删除/排序操作纳入 ADR-006 已定的操作日志机制，同一口径
  （操作人、操作时间、车辆ID、操作类型），只落库不做查看页面。
- F-003 的操作权限与 F-001 保持一致，本期按"单一管理员角色，全权限"处理，
  待 F-006 定义角色分级后再收紧。
- 车辆进回收站/被删除后，关联的图片/评估报告文件本期不从对象存储同步清理，
  留给 F-005 设计落地时处理。
- 评估报告内容本期不做敏感信息识别或访问限制，与图片同等对待。

## Consequences

+ 直传方案减少服务端带宽/内存压力，符合"图片是主要成本项"的既有取向。
+ 操作日志、权限模型与 F-001 保持一致的口径，降低认知成本和实现成本。
+ 公开直链实现简单、成本低。
- 公开直链意味着已下架车辆的图片/报告文件理论上仍可被持有旧链接的人直接访问到，
  这是用简单换来的已知代价。
- 不清理已删除车辆的存储文件，会在 F-005 上线前造成存储成本的隐性增长，
  与 ADR-005 对 F-001 表结构"本期不预留、届时迁移"的取舍一致。
- 文件大小/数量限制是工程侧给出的默认值，不是业务侧给出的精确值，后续可能需要调整。
