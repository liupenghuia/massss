# ADR-114 管理后台列表聚合封面与当前价

Status: Accepted
Date: 2026-08-24
Feature: F-001, F-004
Supersedes: ADR-113 第 1 条（「禁止为此改列表契约 / 卡片走独立价格接口」）；不推翻「价格不落车辆表」

## Context

后台列表卡片要核价、看封面。ADR-113 在禁止改契约的前提下用前端 2N 请求兜底。
用户批准 RFC `docs/rfc/2026-08-24-F-001-管理后台列表聚合封面与当前价.md`：列表读模型一次带回封面与当前价。

## Decision

1. **`GET /admin/vehicles` 的 items 改为 `AdminVehicleSummary`。**  
   现有 `AdminVehicle` 全部字段 + 只读 `coverImageUrl`、`currentPrice`。字段名与公开列表
   `PublicVehicleSummary` 对齐。详情 `GET /admin/vehicles/{id}` 仍返回 `AdminVehicle`，不加这两字段。

2. **`currentPrice` 口径。**  
   等于该车最新一条价格记录的变动后值，排序键与 `GET /admin/vehicles/{id}/price` 的 `current` 相同
   （价格记录自增主键最大者，ADR-073）。从未设价为 JSON `null`（键必须在），不用 `unset`。
   面谈为 `{ type: negotiable, amount: null }`。不在 `vehicles` 表加价格列或封面列。

3. **`coverImageUrl`。**  
   与 F-003 顺序第一张相同；无图为 `null`。键必须在。

4. **回收站列表本期不加封面/当前价。** 要做另开 RFC。

5. **不做**按价格筛选/排序、不做批量下架。查询参数不变。

6. 契约落地后，管理后台删除列表项上的并行 images/price 请求。单车 null 不得整页失败。
   列表数据源不得接到编辑表单。

7. 服务端必须对当前页 id **批量**取图与价，禁止把 N+1 搬进 Node 循环查库。

## Consequences

+ 列表翻页请求约 41→1，封面与价一起出现。  
+ 价格仍只来自价格记录，零容忍口径与详情一致。  
+ 详情接口表面不膨胀。  

- 契约 `$ref` 切换后 typed 后台须与契约同发。  
- 须为「每车第一张图 / 每车最新价」准备按 `vehicle_id` 的查询，否则页一大就扫表。  
- ADR-113 的 2N 兜底在契约落地前仍可用；落地后作废。
