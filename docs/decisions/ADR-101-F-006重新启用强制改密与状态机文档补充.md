# ADR-101 F-006 重新启用强制改密与状态机文档补充

Status: Accepted
Date: 2026-08-21
Feature: F-006
Supersedes: -

## Context
第二轮评审（domain 视角）提出两点：
1. `mustChangePassword` 实际是账号的第三个状态位，但只散落在"各端职责"里，没有集中写进 spec 的状态机章节。
2. 账号从 `disabled` 重新 `active` 后，`mustChangePassword` 是否需要重置为 `true` 未定义——如果账号停用期间密码疑似泄露，仅恢复启用而不强制改密是个安全口子。

均未在 principles.md/已有 ADR 中写明，按默认协议选择更安全、范围更小的一档。

## Decision
1. `mustChangePassword` 正式作为账号状态的第三个维度写入 spec 状态机章节（与角色、启用状态并列）。
2. 账号从 `disabled` 重新 `active` 时，`mustChangePassword` 强制置为 `true`，等同一次密码重置——
   即启用操作本身不改密码，但会要求该账号下次登录必须改密。

## Consequences
+ 补上停用期间凭证疑似泄露的安全口子，重新启用后强制过一次改密流程。
+ 状态机文档更完整，减少后续实现遗漏第三个维度的风险。
- 超管重新启用一个账号后，该账号所有者需要多走一次改密流程，即使密码本身没有问题；
  属于安全默认值换来的轻微体验代价，可接受。
