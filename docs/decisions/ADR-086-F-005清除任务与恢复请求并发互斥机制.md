# ADR-086 F-005 清除任务与恢复请求并发互斥机制

Status: Accepted
Date: 2026-08-21
Feature: F-005
Supersedes: -

## Context
spec.md 已定"恢复请求优先于尚未跑完的清除任务"这一原则（ADR-024/030），
但第二轮评审（api/domain/qa 一致指出）具体互斥机制未落地：定时清除任务扫描到期记录后，
到真正执行 `purged=true` 之间存在窗口，如果这段窗口内用户发起恢复，需要明确谁赢，
否则该场景无法写出确定性的自动化验收用例。按 principles.md 默认协议，
既有方向已定（恢复优先），本决定把隐含的技术方案显式化，不是新business决策。

## Decision
定时清除任务处理每条到期记录时，在同一数据库事务内先重新读取该记录当前的 `trashedAt`
（或复用现有乐观锁 `version` 字段），确认其仍处于回收站中（`trashedAt` 不为空且未被恢复请求置空）
后才将其标记为 `purged=true`；若发现该记录已被恢复（`trashedAt` 已变为 NULL），
跳过本条清除，不视为错误。恢复接口本身不需要感知清除任务的存在，只需正常走既有乐观锁流程。

## Consequences
+ "恢复优先"从原则变成可实现、可测试的具体机制：测试可以在清除任务执行前人为插入一次恢复请求，
  断言该记录未被清除。
- 清除任务需要多一次事务内的二次校验读，扫描到期记录量级不大（车辆规模百台以内）时性能影响可忽略。
