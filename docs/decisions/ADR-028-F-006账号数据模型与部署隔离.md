# ADR-028 F-006 账号数据模型与部署隔离

Status: Accepted
Date: 2026-08-19
Feature: F-006, F-001, F-004, F-005

## Context

`/conflicts F-006` 冲突项 C-4（登录名与操作人展示部分），用户裁决问题 5-7、14、15。
停用后账号是否可逆、登录名能否复用、操作人字段如何落库展示、账号生命周期是否审计、
前后台部署是否同域，是账号模型落地前必须钉死的细节。本文件定稿。

## Decision

### 账号生命周期
- 停用是**状态转移，不做物理删除**。账号行永久保留，可**重新启用**。
- 不提供账号删除功能。
- 账号列表**默认展示全部账号（含已停用）**，带状态标签，不做单独的「已停用」隐藏视图。

### 登录名规则
- 登录名**全局唯一，创建后不可修改**。
- 账号停用后，其登录名**永久占用、不可被新账号复用**，避免新人收到旧人相关的历史消息/审计混淆。

### 操作人字段
- F-001 / F-003 / F-004 / F-005 的操作日志与价格记录**落库时只存账号的稳定 ID**（不存登录名快照）。
- 页面展示操作人时，**实时**用该 ID 查询当前登录名并渲染。
- 因登录名创建后不可修改、停用后不可复用，实时查询结果与「当时」的登录名天然一致，
  不需要额外的展示名快照字段。

### 账号生命周期审计
- 账号的创建、停用、重新启用、密码重置**均落库审计**（操作人、被操作账号、时间、动作类型）。
- **本期不做**审计查看页面，出现问题时由开发直接查库排查。

### 部署隔离
- 管理后台与前台**不同域部署**（如 `admin.example.com` 与 `www.example.com`）。
- 无需额外设计 Cookie 分区方案，会话 Cookie 天然不会被前台请求带上，
  与 brief「前台无用户体系、不得复用后台会话」的要求直接吻合。

## Consequences

+ 登录名永久唯一 + 操作人实时查询，省掉了「展示名快照」这个额外字段，模型更简单。
+ 不同域部署零成本满足了会话隔离要求，不需要处理 Cookie Domain/Path/SameSite 的复杂组合。
+ 生命周期审计兜底了「谁在何时开通/停用了谁」的可追溯性，与操作日志同源同形态。
- 登录名永久占用意味着账号一旦建错名字或人员离职，该登录名永久作废，无法回收复用。
- 无审计查看页，出问题时只能靠开发查库，运营自己无法自助排查账号变更历史。
- 不同域部署要求基础设施提前规划好两个域名及证书，需要在上线前确认。
