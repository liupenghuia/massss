# ADR-113 后台列表价格兜底与表单单一 draft

Status: Accepted
Date: 2026-08-24
Feature: F-001, F-004
Supersedes: ADR-007（仅「管理后台车辆列表卡片不展示价格」的展示口径）；不推翻「价格不落车辆表 / 列表契约不加价格字段」

## Context

管理后台车辆列表已改为 Organic 卡片网格。运营需要在卡片上看到当前价，但
`adminListVehicles` 仍无 `price` / `coverUrl`（契约未改，本阶段禁止改 `server/`）。
同时车辆新建与编辑曾拆成 `editing` 与 `form` 两份状态，易双写不同步。

## Decision

1. **列表卡片展示当前价，数据不来自列表响应。**  
   拉完车辆列表后，前端对每台车并行请求既有 `GET` 当前价接口（及封面所需的 images 接口），
   结果收成**一次** `setState` 再渲染。请求数会随列表条数上升，仅作契约未加字段前的兜底。  
   **禁止**为此改列表契约、禁止在车辆表加价格列、禁止声称「列表接口已返回价格」。

2. **品牌/车型仍非强制必填（草稿）。**  
   与 ADR-035 / ADR-112 一致：界面可标「建议填写」，草稿保存允许空；发布仍走 ADR-003。

3. **新建/编辑合并为单一 draft 状态。**  
   仅前端实现重构，消除双写。能力、校验时机、接口调用方式不变。

4. **批量下架仍明确不做。** 下架只针对单车。

## Consequences

+ 运营在列表即可扫到当前价，不必进详情。  
+ 契约与价格归属（F-004）保持不变，零容忍项仍走价格接口。  
+ 单一 draft 减少新建/编辑字段不同步。  

- 列表页对 N 台车额外 2N 次请求（价 + 图），百台规模可接受，再增长会变慢或打满限流。  
- 某车价格请求失败时卡片可能无价或短暂不一致，须有占位，不得把列表整页判失败。  
- 未改契约意味着后续若要排序/筛价，仍不能靠列表响应，需另开 RFC。
