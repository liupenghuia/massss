# ADR-038 F-001 实现细节默认值批注（第二轮评审收尾）

Status: Accepted
Date: 2026-08-21
Feature: F-001
Supersedes: -

## Context
第二轮评审（qa/api/domain 视角）提出一批非零容忍、非状态机/权限/价格类的实现细节问题，
均未在 principles.md/overview.md/已有 ADR 中写明。按 principles.md「评审与改需求的默认协议」，
无人明确认领且不踩零容忍红线时，选择范围更小、本期能上线的一档，作批量记录。

## Decision
1. **能源类型字段联动**：排量/电耗/电池度数与能源类型的适用关系，本期仅由前端根据
   能源类型展示/隐藏对应输入项，服务端不做"字段组合是否匹配能源类型"的强校验。
2. **数值字段取值范围**：里程为非负整数；上牌年份区间 1980–2100（与 ADR-029 公开端筛选口径一致）；
   过户次数（手数）为非负整数，起点为 0；车况描述长度上限 500 字。超出范围按 VALIDATION_ERROR 处理。
3. **发布前置条件事后失效**：已上架车辆若因 F-003/F-004 数据变动（如图片被删至 4 张以下）
   导致不再满足发布前置条件，维持已上架状态不变，不做自动降级或强制提示，这是有意选择而非遗漏。
4. **乐观锁冲突响应**：VEHICLE_VERSION_CONFLICT 仅返回错误，不在 details 中回传服务端当前最新数据，
   前端提示用户刷新后重试。
5. **管理后台列表默认视图**：默认展示全部状态（含草稿），不做默认过滤，由筛选器交给管理员自行选择。
6. **操作日志**：维持 ADR-006 已定的"只落库不做查看页面"，本期不设保留期/清理策略。

## Consequences
+ 六项均按"更小范围、更快上线"的默认值收敛，避免因非核心问题阻塞开工。
- 第1项后续如出现脏数据（能源类型与填写字段不匹配）需要人工清理，之后可能需要升级为服务端强校验。
- 第3项意味着已上架车辆的展示可能与"理论上应满足的前置条件"脱节，如需改为联动降级，需另开 RFC。
- 第4项要求前端在冲突后引导用户刷新重新编辑，不支持自动合并，用户体验上有一次额外操作成本。
