# ADR-003 F-001 发布前置校验规则

Status: Accepted
Date: 2026-08-19
Feature: F-001（发布逻辑），关联 F-003（图片数量）、F-004（价格是否已填写）
Supersedes: -

## Context

`/conflicts F-001` 第 3、4 条：车辆在没有图片（F-003）/ 没有价格（F-004）的情况下能否直接发布上架。
`docs/principles.md` 强调"每车最少 4 张"图片、"内容准确 > 功能丰富，有疑问时砍功能不砍校验"，
但未明确这是否为发布的硬性门槛。5 方评审均指出该校验目前没有归属。

## Decision

发布（草稿 → 已上架、已下架 → 重新上架）时强制校验：

- 图片数量 ≥ 4 张（依赖 F-003 数据）
- 价格已填写（依赖 F-004 数据）——价格允许填具体数值，也允许填"面谈"，不强制要求实际报价数字，
  只要求该字段非空即可通过校验

任一条件不满足则拒绝发布，返回明确的缺失项提示。

校验逻辑放在 F-001 的发布动作（publish / 重新上架端点）里执行，由 F-001 在执行发布前反查
F-003（图片表）、F-004（价格记录）的数据，而不是等待 F-003/F-004 各自反向拦截。

## Consequences

+ 落实了 principles.md「内容准确 > 功能丰富」的红线，避免前台出现无图或无价的车辆卡片。
+ 校验逻辑集中在发布动作里，职责清晰，F-003/F-004 不需要反向感知 F-001 的状态流转。
+ "价格可填面谈"给运营留了灵活度，不强制所有车都标具体数字价格。
- F-001 的发布接口对 F-003、F-004 的数据产生了读依赖，三个 feature 的开发顺序/联调需要协调
  （F-001 发布逻辑在 F-003、F-004 契约定稿前无法完整实现和测试）。
- F-004 的价格字段设计需要同时支持"面谈"这类非数值占位与具体数值，价格记录如何存储这个分支，
  留给 F-004 自己的评审决定。
