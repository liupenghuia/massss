# ADR-102 F-006 会话失效延迟 SLA 澄清

Status: Accepted
Date: 2026-08-21
Feature: F-006
Supersedes: -

## Context
第二轮评审（qa 视角）标为高严重度：停用/改密后会话失效的最大允许延迟未量化为具体数值，
无法据此设置自动化验收用例的断言超时。api 视角只描述了架构原则（不加缓存、每请求查库），
未给出数值型 SLA。

## Decision
现有架构本身就是"每次 `/admin/*` 请求实时查库校验账号未停用/口令版本"，不存在会话缓存层，
因此停用/改密后的失效不是"传播延迟"问题，而是"下一次请求立即生效"。
SLA 定义为：停用/改密动作提交成功（服务端事务提交完成）之后，该账号发起的**下一次** `/admin/*`
请求必须被拒绝（401/403），不允许任何形式的短暂缓存窗口。验收用例可直接断言"提交后立即发起
下一请求即失败"，不需要额外等待时间。

## Consequences
+ 明确了可写入自动化用例的确定性验收标准，不依赖模糊的时间阈值。
- 要求实现上严格杜绝任何本地/进程内的会话缓存优化（哪怕是为了性能），
  后续如果因性能问题想加缓存层，需要重新评估这条 SLA 是否还能满足。
