# ADR-016 F-004 查询权限与后台范围修正

Status: Accepted
Date: 2026-08-19
Feature: F-004
Supersedes: ADR-013

## Context

`/conflicts F-004` 问题 1、2、11、12、15、16、18、19、21。用户确认的「同意本包」相对 ADR-013
收窄了后台能力：ADR-013 要求按价格状态筛选车辆并支持批量 ID 查询；本包只要进程内反查、
可供验收的只读查询、某车价格记录列表，复杂筛选可以不做。本文件整份取代 ADR-013。

## Decision

- 价格记录补「操作人」，口径对齐 ADR-006：本期用登录账号标识，不等 F-006 角色模型定稿。
- 改价权限本期不分级：任何已登录管理员可改价，待 F-006 后再收紧。
- F-001 发布动作反查「是否已填写」用**进程内方法**（服务端合一），不走 HTTP。
- 另提供管理端只读查询（单车），供验收/联调断言；本期**不做**按一批车辆 ID 批量查价。
- 反查或只读查询自身失败（如数据库异常）时，F-001 **阻塞发布并报错**，不得当成「未填写」。
- 车辆进回收站或删除后，价格记录**不级联删除、永久保留**；前台是否仍可见等细节留给 F-005，
  不阻塞 F-004。
- 管理后台在车辆详情内可查看该车价格记录列表（最低限度）。本期不做独立价格历史页，
  不做按「未填价 / 面谈 / 已定价」筛选车辆。
- 本期不做价格记录导出。
- 明确不做批量改价；逐台改的成本本期可接受。
- 改价不做二次确认弹窗。

## Consequences

+ 与 F-001/F-003「进程内反查 + 单一管理员」口径一致，发布路径少一层网络失败。
+ 单车只读查询让 QA 不必依赖内部函数即可写联调用例。
+ 后台只做详情内列表，范围小于 ADR-013，减少本期待建页面。
- 运营不能在列表上筛「还没定价的车」，只能进详情或等以后加筛选。
- 任何登录管理员都能改价，是越权红线在 F-006 落地前的已知敞口。
- 删除车辆后价格仍占库，清理策略取决于 F-005。
