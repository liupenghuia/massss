# ADR-056 F-003 确认接口防串号强绑定校验

Status: Accepted
Date: 2026-08-21
Feature: F-003
Supersedes: -

## Context
第二轮评审（domain/qa 视角）指出：spec 已定稿"客户端直传对象存储 + 服务端 confirm 接口
做元数据落库确认"的两段式流程（ADR-009），但 confirm 接口是否校验上传文件确实归属
所申请的 vehicleId，spec 正文未显式写出。这直接关系到零容忍项"图片与车辆错配
（A 车展示了 B 车的图）""评估报告文件损坏或串号"，属于既有流程理应包含、但未落笔的隐含要求，
不是需要业务方重新拍板的新决策。

## Decision
adminConfirmVehicleImage / adminConfirmVehicleReport 接口必须校验请求体中的 objectKey
确实是"该车辆此前申请预签名时签发的 key"，且未被其他车辆的确认请求使用过。
校验失败返回 contracts/errors.yaml 已有的 INVALID_OBJECT_KEY（objectKey 无效或不属于该车辆）。
本决定是把既有预签名+确认流程的隐含约束显式写入 spec，不新增接口、不改变现有错误码定义。

## Consequences
+ 堵住"确认接口未做归属校验导致跨车串号"这一潜在零容忍红线漏洞，实现时有明确依据可查。
- 预签名阶段需要服务端记录"哪个 vehicleId 签发了哪个 objectKey"，confirm 时才有依据比对，
  如果预签名记录的存储/过期策略此前未设计，需要补一张轻量记录表或等效机制。
