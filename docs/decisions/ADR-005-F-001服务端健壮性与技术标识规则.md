# ADR-005 F-001 服务端健壮性与技术标识规则

Status: Accepted
Date: 2026-08-19
Feature: F-001
Supersedes: -

## Context

`/conflicts F-001` 问题 11、15、16、17：并发编辑、车辆唯一标识、下架可见延迟、
软删除字段预留，均属于纯技术判断，已按建议方案取得用户确认。

## Decision

- 编辑接口加乐观锁（`version` / `updatedAt` 比对），冲突返回明确错误提示"该车辆已被修改，
  请刷新后重试"；创建接口要求幂等键，防止网络重试在服务端产生重复车辆记录。
- 车辆使用系统自动生成的技术主键（如自增 ID）作为跨 feature（F-003/F-004/F-005）关联锚点，
  不使用车架号作锚点（车架号不要求唯一，见 ADR-002）。
- 下架后车辆在前台立即不可见，不做缓存延迟，由服务端保证强一致查询
  （`/public/*` 接口严格按 status 过滤）。
- 本期不为 F-005 预留软删除字段，F-005 设计落地时再对 `vehicles` 表做迁移。

## Consequences

+ 并发写和重复提交都有防护，避免数据静默丢失或重复记录。
+ 技术主键稳定、不受业务字段变化影响，F-003/F-004/F-005 挂载的数据不会因编辑车辆信息而错位。
+ 下架实时生效，符合 principles.md「已删除/已下架车辆仍在前台可见」的零容忍精神。
- 不预留软删除字段意味着 F-005 上线时需要对 `vehicles` 表和现有接口做一次兼容迁移，
  这是已知代价，用户已接受。
