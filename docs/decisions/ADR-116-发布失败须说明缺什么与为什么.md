# ADR-116 发布失败须说明缺什么与为什么

Status: Accepted
Date: 2026-08-24
Feature: F-001
Supersedes: -

## Context

`PUBLISH_PRECONDITION_FAILED` 的契约 message 固定为「不满足发布前置条件」。details 已有 `missing`、`imageCount`、`priceFilled`、`missingCoreFields`，但管理后台曾把 message 原样展示。操作人不知道是缺图、缺价还是核心字段空。

## Decision

1. 契约 message 维持固定短句，不改 `errors.yaml`。
2. 管理后台必须根据 `details` 译成中文：**缺哪条规则、当前差在哪、为何拦发布**。多条缺失用分号并列。
   - 图片：至少 4 张才能上架，并写出当前张数。
   - 价格：还没填（标价或面谈均可）。
   - 核心字段：列出中文名，并说明草稿可空、上架前必须填齐。
3. 同类笼统码同样展开：`ILLEGAL_STATUS_TRANSITION`、`PUBLISHED_IMAGE_MIN`、`VEHICLE_VERSION_CONFLICT`。有 details 却只展示 code/短 message 视为缺陷。
4. 文案写在操作区（与 ADR-115 同一位置）。

## Consequences

+ 发布被拒时操作人知道下一步补什么。  
+ 不改契约、不改服务端 message，前后端错误码仍可对账。  

- 前端文案与 details 字段名耦合；服务端若增 missing 项，前端漏译会退回兜底句，须同步改 `describeError`。
