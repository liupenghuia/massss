# ADR-036 F-001 VIN 重复保存策略修正

Status: Accepted
Date: 2026-08-21
Feature: F-001
Supersedes: ADR-002（部分：车架号唯一性约束）

## Context
ADR-002 原决定"车架号（VIN）不要求全局唯一"。第二轮评审（qa 视角）重新提出
"两台车录入相同 VIN 是否允许保存"，用户裁决改为不允许，与 ADR-002 原决定相反。

## Decision
车架号（VIN）在保存（创建/编辑）时校验唯一性，与已存在的其他车辆 VIN 重复则拒绝保存。
本决定修正 ADR-002 中"不要求全局唯一"这一条，ADR-002 其余内容（VIN 不作为业务主键、
仅后台展示后六位、系统自动生成技术主键作跨 feature 关联锚点）保持不变。

## Consequences
+ 避免同一辆车被误录入两次形成重复卡片，数据更贴近真实业务约束（VIN 本身具备唯一性）。
- 需要在创建/编辑接口加唯一性校验（数据库唯一索引或应用层查重），
  录入环节如果 VIN 抄录有误会被拦截，需给出清晰的冲突提示而非笼统报错。
- 与 F-005 回收站的交互需要额外确认：车辆进回收站/被彻底清除后，
  其 VIN 是否释放供新车复用，此问题超出本 ADR 范围，留待 F-005 相关裁决处理
  （F-005 conflicts.md 问题 6 已提出类似问题，建议合并处理）。
