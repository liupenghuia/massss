# ADR-023 F-005 状态建模与生命周期

Status: Accepted
Date: 2026-08-19
Feature: F-005, F-001
Related: ADR-004（F-001 状态机）

## Context

`/conflicts F-005` 冲突项 C-1、C-2、C-3、C-9、C-16，用户裁决问题 1-4、15-17。
回收站是否并入 F-001 三态状态机、允许哪些车辆进站、恢复后落到哪个状态，直接决定
F-001 现网接口的迁移面。本文件定稿建模与生命周期规则。

## Decision

### 建模
- 新增**正交字段** `trashedAt`（可空时间戳），**不**在 `status` 上加第四个值。
- 公开可见性过滤为 `published AND trashedAt IS NULL`（ADR-004 状态机本身不变）。
- 所有在管列表、写接口（发布/下架/改核心字段/改价/改图）**必须额外排除 `trashedAt IS NOT NULL`** 的车辆。

### 允许进站的源状态
- `草稿`、`已上架`、`已下架` **三态均可**直接删除进入回收站。
- 已上架车辆删除**不需要**先下架，删除动作本身即时生效（前台立即不可见）。
- 已上架车辆被直接删除时，**额外写一条「下架」操作日志**，与「进回收站」日志分开记录，
  保留完整审计轨迹。
- 不允许的源状态（当前无，三态已覆盖全部业务状态）不适用。

### 恢复
- 恢复**一律落草稿**，不保留删除前的原状态（即使原本是已上架）。
- 恢复后需重新走 ADR-003 发布前置校验才能再次上架，不自动发布。
- 恢复本身是**幂等**操作：对已恢复（`trashedAt` 为空）的车辆重复调用恢复接口，
  返回幂等成功，不报错。

### 重复删除与多次循环
- 对已在回收站的车辆（`trashedAt` 已有值）重复调用删除接口，**幂等成功，不刷新 `trashedAt`**。
- 同一辆车允许**不限次数**「删除 → 恢复 → 再删除」；每次新的删除动作**重新计算一个月保留期**
  （即每次都写入新的 `trashedAt`）。

## Consequences

+ 正交字段避免了 ADR-004 状态机改形，F-001 现有状态转换矩阵不用重写。
+ 三态均可删除堵住了「误建草稿无出口」和「已上架必须先下架才能删」两个已知缺口。
+ 幂等设计让前端不必对「已经删过」做特殊报错处理。
- 所有 F-001 现有的在管列表与写接口都要追加一条 `trashedAt IS NULL` 过滤，遗漏则回收站车辆会重新出现在在管列表或可被误改。
- 已上架误删后恢复只能落草稿，运营必须记得手动重新发布，误删代价较高。
- 不限次数重算保留期意味着车辆理论上可以被无限期留在回收站边缘（每次清除前一天恢复再删），
  本期接受此代价，不做次数上限。
