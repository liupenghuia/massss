# RFC: F-001 发布前置校验扩展核心字段

Status: Accepted
Feature: F-001
相关 ADR: ADR-035

## 背景
ADR-035 裁决草稿保存不强制校验核心字段（品牌/车型/年份等）是否非空，仅在发布时才校验。
落地这条裁决要求：
1. `vehicles` 表核心字段列（brand/model/registration_year/mileage_km/color/
   condition_desc/energy_type/transfer_count）从 `NOT NULL` 改为可空。
2. 发布前置校验（`evaluatePublishPrecondition`）在原有"图片≥4张、价格已填写"基础上，
   新增"核心字段全部已填写"这一条，缺失时同样拒绝发布。

第2点需要扩展 `contracts/errors.yaml` 里 `PublishPreconditionFailedDetails.missing` 的枚举，
目前只有 `[images, price]`，需要新增 `coreFields`，以及需要一个新字段列出具体缺失了哪些
核心字段名，供前端展示明确提示。

## 提案
在 `contracts/errors.yaml`：
- `PublishPreconditionFailedDetails.missing` 的 enum 新增 `coreFields`
- `PublishPreconditionFailedDetails` 新增可选属性 `missingCoreFields`：
  `{ type: array, items: { type: string }, description: "missing 含 coreFields 时，列出具体缺失的核心字段名（camelCase），否则省略" }`
- `PUBLISH_PRECONDITION_FAILED` 的 note 补充一句：核心字段缺失同样归入本码，
  与图片/价格缺失可以同时出现在同一次 missing 数组里。

`contracts/openapi.yaml` 若对 `PublishPreconditionFailedDetails` 有独立 schema 引用，
需要同步补充上述字段（预计只是 `$ref` 到 errors.yaml 对应 schema，若如此则该文件本身
不需要改动，请 contract-keeper 核实）。

本提案仅描述诉求，不直接改 contracts/。
