# RFC: F-001 车辆核心字段契约放开可空

Status: Accepted
Feature: F-001
相关 ADR: ADR-035

## 背景
ADR-035 裁决草稿保存不强制核心字段非空，实现阶段已经把数据库列
（brand/model/registration_year/mileage_km/color/condition_desc/energy_type/transfer_count）
改为可空，服务端校验也相应放宽。但 `contracts/openapi.yaml` 里 `AdminVehicle`、`PublicVehicle`、
`AdminRecycleBinItem` 这几个 schema 的对应字段仍声明为必填 `string`/`integer`（非 nullable），
导致草稿车辆缺字段时，GET 接口实际返回的 JSON（字段为 null）不符合它自己声明的契约。
代码侧目前用 TypeScript 类型断言（`as string`）绕过了编译期类型检查，属于临时过渡状态。

## 提案
在 `contracts/openapi.yaml` 里，对 `AdminVehicle` schema 的以下字段放开为可空
（`type: [string, "null"]` 或对应 nullable 写法，含 integer 字段同理）：
`brand`、`model`、`registrationYear`、`mileageKm`、`color`、`conditionDesc`、`energyType`、`transferCount`。

`PublicVehicle` schema：只有已上架（published）车辆才会通过公开接口对外，理论上已上架车辆
核心字段一定齐全（发布前置校验已保证），可以不放开，维持必填更安全——但请 contract-keeper
核实 `PublicVehicle` 是否与 `AdminVehicle` 共享同一底层 schema 定义，如果是同一份定义则需要一并处理，
否则会因为共享定义被迫放开、削弱公开接口的契约保证；如果二者是独立定义，`PublicVehicle` 维持不变即可。

`AdminRecycleBinItem`：回收站车辆可能是草稿态被删的，同样可能缺核心字段，需要同步放开，
处理方式与 `AdminVehicle` 一致。

## 附带修复（不属于本次裁决，但顺手处理）
`contracts/openapi.yaml` 中 `PriceFrom` 的 description 里裸写了 `{ type: unset }`，
未加引号导致 YAML 解析在生成类型时报错，`npm run generate:types` 完全跑不动。
请顺手给这段 description 文本加引号修好，这是纯 YAML 语法修复，不改变任何字段语义。

修完后请重新跑一次 `npm run generate:types`（在 server/ 目录下），确认 
`server/src/generated/openapi-types.ts` 能被正常重新生成，替换掉当前手工过渡版本。

本提案仅描述诉求，不直接改 contracts/ 以外的文件（generate:types 生成结果除外，
这是从契约自动生成的产物，理应由 contract-keeper 顺手跑一次使其与契约同步）。
