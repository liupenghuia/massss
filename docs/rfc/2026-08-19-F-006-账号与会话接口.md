# F-006 账号与会话接口：登录/登出/建号/停用/启用/角色变更/改密/重置密码/账号列表

## 动机

F-006 spec（v1.1，ADR-026/027/028 已裁决）需要一整套账号与会话接口。当前
`contracts/openapi.yaml` 里 `adminAuth` 只是一个占位 securityScheme（`本 scheme 仅为
OpenAPI 占位，不规定登录方式...鉴权由 F-006 定稿`），`errors.yaml` 里 `UNAUTHORIZED` 的
note 也明确写着"不在本期定义 403 角色分权"——本 RFC 把这些占位全部实体化，并新增账号管理
接口。这是 F-006 实现前的硬前置依赖。

## 提议

### 1. 鉴权模型实体化

`adminAuth` securityScheme 改为 cookie 会话（ADR-027：服务端会话，客户端持不透明标识）：

```yaml
securitySchemes:
  adminAuth:
    type: apiKey
    in: cookie
    name: admin_session
    description: |
      服务端会话（ADR-027），不透明会话标识，客户端不解析。8 小时滑动过期，同账号允许多端登录。
      账号停用或改密后，该账号全部现有会话作废——吊销判定必须**同步一致读**（每次请求查会话
      存储判定是否已被吊销），不允许"内存缓存+定期刷新"引入延迟窗口，否则违反 ADR-027 的
      「停用立即生效」零容忍要求。

      Cookie 属性（安全定稿，reviewer-security 阻塞项）：`HttpOnly; Secure; SameSite=Strict;
      Path=/admin`。管理后台前端与本 API 同源部署（同域名，不同于 ADR-028 里"前台与后台
      不同域"——那是前台公开站点与后台的隔离，后台前端与后台 API 视为同一部署单元），
      因此不需要跨域 CORS credentials 配置，`SameSite=Strict` 天然覆盖大部分 CSRF 场景。

      CSRF 防护（安全定稿）：除 `SameSite=Strict` 外，全部状态变更接口（POST/PUT/DELETE）
      额外校验请求的 `Origin` header 必须等于部署域名，不一致则 403 FORBIDDEN，双重防护。

      密码存储：服务端用 **argon2id**（或 bcrypt，cost factor ≥ 12）存储密码哈希，
      **禁止**明文或 MD5/SHA256 直接摘要落库。全部 `/admin/*` 接口强制 HTTPS 传输，
      不接受明文 HTTP。密码比对使用哈希库自带的恒定时间比较，避免时序侧信道。

      未携带有效会话 → 401 UNAUTHORIZED。
      已登录但角色不足（如管理员访问超管专属接口）→ 403 FORBIDDEN。
      已登录但账号已被停用（会话吊销前的极短竞态窗口内）→ 401 UNAUTHORIZED（视为会话已失效，
      不使用 403，避免与"角色不足"混淆）。
      已登录但 mustChangePassword=true 且调用的不是改密接口本身 → 403 MUST_CHANGE_PASSWORD。
```

新增错误码 `FORBIDDEN`（403，仅用于"已登录但角色不足"）、`MUST_CHANGE_PASSWORD`（403）、
`INVALID_CREDENTIALS`（403，登录密码错误或账号不存在，**统一返回同一提示，不区分**，
防止账号枚举）、`ACCOUNT_DISABLED`（403，登录时账号已停用）、`ACCOUNT_LOCKED`（403，
登录失败次数超限）。`UNAUTHORIZED` 的 note 更新为"鉴权已由 F-006 定稿"。

**登录失败锁定的并发与窗口规则**：失败计数器按账号维度落库，用数据库原子自增
（如 `UPDATE ... SET fail_count = fail_count + 1`）保证并发安全；锁定窗口为**固定 15
分钟**（不是滑动窗口，简化实现与测试）；成功登录后计数器清零；服务端**先做密码比对
再判断是否已达锁定阈值**（避免通过"锁定判断跳过密码校验"的响应时间差侧信道泄露账号是否存在）；
登录接口额外加**基础 IP 级速率限制**（与 F-002 公开接口的既有防护模式一致），防止对大量不同
loginName 各尝试低于账号锁定阈值的次数来撞库枚举。

### 2. 新增接口

```yaml
/admin/auth/login:
  post:
    operationId: adminLogin
    summary: 登录
    description: |
      匿名可访问（唯一不需要 adminAuth 的 /admin/* 接口）。
      登录名+密码，恒定时间比较。连续 5 次失败（固定窗口，DB 原子计数）锁定该账号 15 分钟，
      锁定期内即使密码正确也拒绝，返回 403 ACCOUNT_LOCKED；成功登录后计数器清零。
      加基础 IP 级速率限制，防止跨账号撞库枚举。
      账号不存在或密码错误：403 INVALID_CREDENTIALS，两种情况返回完全相同的响应体，
      不给出任何可区分账号是否存在的信息。
      账号 disabled 时，即使密码正确也拒绝登录：403 ACCOUNT_DISABLED（与密码错误可区分，
      因为调用方已经知道自己在用哪个 loginName 登录，不构成新的枚举面）。
      成功后 Set-Cookie 下发会话（8 小时滑动过期，HttpOnly/Secure/SameSite=Strict，见
      securityScheme 定义）。
      mustChangePassword=true（首次登录或密码被重置后）时，登录仍然成功，响应体标注该字段，
      前端必须强制跳转改密页；改密前调用除 `/admin/auth/password`、`/admin/auth/logout` 外的
      任何 /admin/* 接口返回 403 MUST_CHANGE_PASSWORD。
    security: []
    requestBody:
      required: true
      content:
        application/json:
          schema:
            type: object
            additionalProperties: false
            required: [loginName, password]
            properties:
              loginName: { type: string, minLength: 1 }
              password: { type: string, minLength: 1 }
    responses:
      "200":
        description: 登录成功
        headers:
          Set-Cookie:
            description: HttpOnly; Secure; SameSite=Strict; Path=/admin 会话 cookie
            schema: { type: string }
        content:
          application/json:
            schema: { $ref: '#/components/schemas/AdminSessionInfo' }
      "400": { $ref: '#/components/responses/BadRequest' }
      "403":
        description: 密码错误或账号不存在（INVALID_CREDENTIALS）/ 账号已停用（ACCOUNT_DISABLED）/ 账号被锁定（ACCOUNT_LOCKED）
        content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } }
      "500": { $ref: '#/components/responses/InternalError' }

/admin/auth/logout:
  post:
    operationId: adminLogout
    summary: 登出
    description: 作废当前会话（仅当前这一个，不影响该账号其他设备的会话）。
    security: [{ adminAuth: [] }]
    responses:
      "200": { description: 已登出 }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "500": { $ref: '#/components/responses/InternalError' }

/admin/auth/password:
  post:
    operationId: adminChangeOwnPassword
    summary: 修改自己的密码
    description: |
      需提供当前密码。新密码最少 8 位，需同时含字母与数字。
      成功后作废该账号全部现有会话（含当前这次请求的会话），响应体不再提示重新登录信息，
      客户端需引导用户用新密码重新登录。mustChangePassword 置为 false。
    security: [{ adminAuth: [] }]
    requestBody:
      required: true
      content:
        application/json:
          schema:
            type: object
            additionalProperties: false
            required: [currentPassword, newPassword]
            properties:
              currentPassword: { type: string, minLength: 1 }
              newPassword: { type: string, minLength: 8 }
    responses:
      "200": { description: 修改成功，全部会话已作废 }
      "400": { $ref: '#/components/responses/BadRequest' }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "403": { description: 当前密码错误（INVALID_CREDENTIALS）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "500": { $ref: '#/components/responses/InternalError' }

/admin/accounts:
  post:
    operationId: adminCreateAccount
    summary: 新建管理员账号（仅超管）
    description: |
      仅 super_admin 可调用。填 loginName + role，系统生成随机初始口令，仅在本次响应体里
      明文返回一次（不落库明文、不可再查看）。新账号 mustChangePassword=true。
      loginName 全局唯一，创建后不可修改；已停用账号的 loginName 永久占用不可复用。

      **不提供 Idempotency-Key**：与 F-001 建车辆不同，若网络超时导致客户端未收到这次响应，
      账号在服务端已创建成功但客户端拿不到那个一次性口令——这种情况**接受**（ADR-026 已裁决
      流程），恢复路径是超管再调用一次 `POST /admin/accounts/{accountId}/password-reset`
      重新生成一个新口令，不做"重放返回同一口令"的幂等设计（会破坏"口令不落库明文、不可再查"
      的安全承诺）。
      **网关/日志系统要求**：本接口响应体含明文口令，网关、APM、错误监控、反向代理日志
      **禁止记录本接口与 password-reset 接口的响应体**，仅记录状态码与耗时。
    security: [{ adminAuth: [] }]
    requestBody:
      required: true
      content:
        application/json:
          schema:
            type: object
            additionalProperties: false
            required: [loginName, role]
            properties:
              loginName: { type: string, minLength: 1, maxLength: 50 }
              role: { type: string, enum: [admin, super_admin] }
    responses:
      "201":
        description: 创建成功，含一次性明文初始口令
        content:
          application/json:
            schema: { $ref: '#/components/schemas/AdminAccountCreatedResponse' }
      "400": { $ref: '#/components/responses/BadRequest' }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "403": { description: 非超管调用（FORBIDDEN）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "409": { description: loginName 已被占用（含已停用账号）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "500": { $ref: '#/components/responses/InternalError' }

  get:
    operationId: adminListAccounts
    summary: 账号列表（仅超管）
    description: |
      默认展示全部账号（含已停用），带角色与启用状态标签。仅 super_admin 可调用。
      默认排序：id 升序（创建顺序）。
    security: [{ adminAuth: [] }]
    parameters:
      - $ref: '#/components/parameters/Page'
      - $ref: '#/components/parameters/PageSize'
    responses:
      "200": { description: 账号列表, content: { application/json: { schema: { $ref: '#/components/schemas/AdminAccountList' } } } }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "403": { description: 非超管调用（FORBIDDEN）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "500": { $ref: '#/components/responses/InternalError' }

/admin/accounts/{accountId}/status:
  post:
    operationId: adminSetAccountStatus
    summary: 停用 / 启用账号（仅超管）
    description: |
      body.enabled=false 为停用，true 为启用。仅 super_admin 可调用。
      用单一端点 + 布尔值而非 F-001 式的独立动词端点（publish/unpublish），是因为启用/停用只有
      两态、无中间态、无前置校验，用布尔值更省；F-001 的多态转换更适合动词端点，两种风格在本
      仓库内并存是刻意选择，不是遗漏。

      检查顺序（先后如下，前面命中即短路）：
      1. 非 super_admin 调用 → 403 FORBIDDEN
      2. 目标账号不存在 → 404
      3. 目标账号是调用者自己 → 403 CANNOT_DISABLE_SELF（无论 enabled 传 true 还是 false，
         只要目标是自己就拒绝，简化规则，不必区分"停用自己"与"启用自己"这种理论上无意义的组合）
      4. 已是目标状态（enabled 与当前一致）→ 200 幂等成功，不再往下检查
      5. enabled=false 且目标是系统里最后一个启用状态的 super_admin → 409 LAST_SUPER_ADMIN
      6. 以上均不命中 → 执行变更，停用时作废该账号全部现有会话（同步一致失效，见 securityScheme）
    security: [{ adminAuth: [] }]
    parameters:
      - name: accountId
        in: path
        required: true
        schema: { type: integer, format: int64, minimum: 1 }
    requestBody:
      required: true
      content:
        application/json:
          schema:
            type: object
            additionalProperties: false
            required: [enabled]
            properties:
              enabled: { type: boolean }
    responses:
      "200": { description: 已生效（含幂等重复调用）, content: { application/json: { schema: { $ref: '#/components/schemas/AdminAccount' } } } }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "403": { description: 非超管调用（FORBIDDEN），或对自己调用（CANNOT_DISABLE_SELF）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "404": { description: 账号不存在, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "409": { description: 尝试停用最后一个启用超管, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "500": { $ref: '#/components/responses/InternalError' }

/admin/accounts/{accountId}/role:
  post:
    operationId: adminSetAccountRole
    summary: 修改账号角色（仅超管，ADR-026 允许升降级）
    description: |
      仅 super_admin 可调用。

      检查顺序（先后如下，前面命中即短路）：
      1. 非 super_admin 调用 → 403 FORBIDDEN
      2. 目标账号不存在 → 404
      3. 已是目标角色 → 200 幂等成功，不再往下检查
      4. role=admin（降级）且目标是系统里最后一个启用状态的 super_admin → 409 LAST_SUPER_ADMIN
      5. 以上均不命中 → 执行变更（不影响会话，角色变更不强制下线，下一次鉴权即按新角色生效）
    security: [{ adminAuth: [] }]
    parameters:
      - name: accountId
        in: path
        required: true
        schema: { type: integer, format: int64, minimum: 1 }
    requestBody:
      required: true
      content:
        application/json:
          schema:
            type: object
            additionalProperties: false
            required: [role]
            properties:
              role: { type: string, enum: [admin, super_admin] }
    responses:
      "200": { description: 已生效（含幂等重复调用）, content: { application/json: { schema: { $ref: '#/components/schemas/AdminAccount' } } } }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "403": { description: 非超管调用（FORBIDDEN）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "404": { description: 账号不存在, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "409": { description: 尝试降级最后一个启用超管, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "500": { $ref: '#/components/responses/InternalError' }

/admin/accounts/{accountId}/password-reset:
  post:
    operationId: adminResetAccountPassword
    summary: 重置他人密码（仅超管）
    description: |
      仅 super_admin 可调用。生成新随机口令，仅在本次响应体里明文返回一次。
      重置后该账号 mustChangePassword 置为 true，且全部现有会话作废。
      同样不提供 Idempotency-Key，网络超时未收到口令时可重复调用本接口生成新口令
      （本接口天然可重复调用，语义上比建号更安全）。
      网关/日志系统同样禁止记录本接口响应体（见 adminCreateAccount 的日志脱敏要求）。
    security: [{ adminAuth: [] }]
    parameters:
      - name: accountId
        in: path
        required: true
        schema: { type: integer, format: int64, minimum: 1 }
    responses:
      "200": { description: 重置成功，含一次性明文新口令, content: { application/json: { schema: { $ref: '#/components/schemas/AdminAccountCreatedResponse' } } } }
      "401": { $ref: '#/components/responses/Unauthorized' }
      "403": { description: 非超管调用（FORBIDDEN）, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "404": { description: 账号不存在, content: { application/json: { schema: { $ref: './errors.yaml#/components/schemas/ErrorResponse' } } } }
      "500": { $ref: '#/components/responses/InternalError' }
```

### 3. 新增 schema

```yaml
AdminSessionInfo:
  type: object
  additionalProperties: false
  required: [accountId, loginName, role, mustChangePassword]
  properties:
    accountId: { type: integer, format: int64, minimum: 1 }
    loginName: { type: string }
    role: { type: string, enum: [admin, super_admin] }
    mustChangePassword:
      type: boolean
      description: true 时前端必须强制跳转改密页面，此前调用其他接口返回 403

AdminAccount:
  type: object
  additionalProperties: false
  description: 账号资源。不含密码/密码哈希。
  required: [id, loginName, role, enabled, mustChangePassword, createdAt, updatedAt]
  properties:
    id: { type: integer, format: int64, minimum: 1 }
    loginName: { type: string }
    role: { type: string, enum: [admin, super_admin] }
    enabled: { type: boolean }
    mustChangePassword: { type: boolean }
    createdAt: { type: string, format: date-time }
    updatedAt: { type: string, format: date-time }

AdminAccountList:
  type: object
  additionalProperties: false
  required: [items, page, pageSize, total]
  properties:
    items: { type: array, items: { $ref: '#/components/schemas/AdminAccount' } }
    page: { type: integer, minimum: 1 }
    pageSize: { type: integer, minimum: 1 }
    total: { type: integer, minimum: 0 }

AdminAccountCreatedResponse:
  type: object
  additionalProperties: false
  description: 新建账号或重置密码后的一次性响应，initialPassword 只在本次返回，不再可查。
  required: [account, initialPassword]
  properties:
    account: { $ref: '#/components/schemas/AdminAccount' }
    initialPassword:
      type: string
      description: 一次性明文初始口令，仅本次响应体携带，服务端不落库明文
```

### 4. 新增错误码（并入 `errors.yaml`）

| code | HTTP | 场景 |
|---|---|---|
| `FORBIDDEN` | 403 | 已登录但角色不足（非超管调用超管专属接口）；也用于 CSRF Origin 校验失败 |
| `MUST_CHANGE_PASSWORD` | 403 | mustChangePassword=true 时调用改密/登出以外的接口 |
| `INVALID_CREDENTIALS` | 403 | 登录时密码错误或账号不存在（统一码，防枚举） |
| `ACCOUNT_DISABLED` | 403 | 登录时账号已停用 |
| `ACCOUNT_LOCKED` | 403 | 连续 5 次登录失败后的 15 分钟锁定期内登录 |
| `ACCOUNT_LOGIN_NAME_TAKEN` | 409 | 新建账号时 loginName 已被占用（含已停用账号） |
| `CANNOT_DISABLE_SELF` | 403 | 超管对自己调用停用/启用 |
| `LAST_SUPER_ADMIN` | 409 | 尝试停用或降级系统里最后一个启用状态的超管 |

## 影响面

| 端 | 影响 |
|---|---|
| 服务端 | 新增 9 个接口；新增 accounts 表（迁移，非契约）；`adminAuth` securityScheme 从占位改为 cookie 会话实体化（HttpOnly/Secure/SameSite=Strict + Origin 校验双重 CSRF 防护）；所有 `/admin/*` 接口的 401/403/MUST_CHANGE_PASSWORD 语义首次被正式定义；**部署侧需要种子脚本创建首个超级管理员**（ADR-026 已裁决口令来源为环境变量注入，但创建脚本本身不在任何契约里，是本 RFC 之外的部署前置动作，必须在服务上线前完成，否则无人能调用 adminCreateAccount）；网关/日志系统需对建号与重置密码两个接口做响应体脱敏 |
| 管理后台 | 新增登录页、改密页、账号管理页（超管专属）；所有页面需处理 401（未登录/会话过期，跳登录页）与 403（角色不足/账号停用/需要改密/CSRF 校验失败，各自独立提示，不能合并成一种"无权限"文案）；请求层需带 `credentials: same-origin`（同源部署，非跨域） |
| 前台 | 无影响，`/public/*` 本就 `security: []` |
| F-001/F-003/F-004/F-005 | 无 schema 变更，但所有 `/admin/*` 写接口的操作日志 `operatorId` 来源从"假设已登录"变为真实会话 `accountId`；**只记账号级 accountId，不记 sessionId**（同账号多端操作时日志不细分到具体设备/会话） |

## 契约变更

- `contracts/openapi.yaml`：
  - `adminAuth` securityScheme 从 apiKey/header 占位改为 apiKey/cookie，description 更新为
    ADR-027 定稿的会话规则
  - 新增路径：`/admin/auth/login`、`/admin/auth/logout`、`/admin/auth/password`、
    `/admin/accounts`（POST+GET）、`/admin/accounts/{accountId}/status`、
    `/admin/accounts/{accountId}/role`、`/admin/accounts/{accountId}/password-reset`
  - 新增 schema：`AdminSessionInfo`、`AdminAccount`、`AdminAccountList`、
    `AdminAccountCreatedResponse`
  - 现有 `Unauthorized` 响应组件不变；新增 `Forbidden` 响应组件（403，指向 FORBIDDEN 系错误码）
- `contracts/errors.yaml`：
  - 新增 `FORBIDDEN`、`MUST_CHANGE_PASSWORD`、`INVALID_CREDENTIALS`、`ACCOUNT_DISABLED`、
    `ACCOUNT_LOCKED`、`ACCOUNT_LOGIN_NAME_TAKEN`、`CANNOT_DISABLE_SELF`、`LAST_SUPER_ADMIN`
  - `UNAUTHORIZED` 的 note 更新为"鉴权已由 F-006 定稿"，去掉"不在本期定义 403"的旧注

## 部署前置依赖（非契约，但阻塞上线）

- **首个超级管理员种子脚本**：ADR-026 已裁决口令来源为环境变量注入，但脚本本身需要在部署
  流程里实现（不在本 RFC 的接口契约范围内）。没有这一步，`adminCreateAccount` 永远无法被
  首次调用（鸡生蛋问题，reviewer-api 指出）。
- **HTTPS 强制**：全部 `/admin/*` 流量必须走 HTTPS，反向代理/网关层配置，非应用层契约能保证。

## 不做的替代方案

- **JWT 无状态会话**：ADR-027 已否决，理由是"停用立即生效"这一零容忍成功标准要求会话可被
  服务端主动吊销，长期 JWT 做不到。
- **登录名可改**：ADR-028 已否决，理由是操作人展示依赖登录名稳定不变，改名会破坏历史记录的
  可读性。
- **邮箱/短信找回密码**：ADR-026 已否决，本期无邮箱/短信通道，找回统一走超管重置。
- **单设备登录（新登录踢旧会话）**：ADR-027 已否决，本项目无账号共享场景，多端同时登录对
  使用体验更友好。
- **建号与分配拆成两步接口**：ADR-026 已否决，一次「新建管理员」调用即完成建号+生成口令，
  避免"建了号但没分配"的中间态。

## 评审意见

### reviewer-security
- 【高危/阻塞】Cookie 属性完全未在契约中体现。`admin_session` 的 Set-Cookie 只写了"服务端会话，不透明标识"，未规定 `HttpOnly`、`Secure`、`SameSite` 属性。这是本 RFC 最大的遗漏：
  - 缺 `HttpOnly` → 会话标识可被 XSS 窃取。
  - 缺 `Secure` → 会话可能在明文 HTTP 上传输，被中间人窃听。
  - 缺 `SameSite`（建议 `Lax` 或 `Strict`）→ 直接导致下面的 CSRF 风险。
  这三个属性必须写进 RFC 的 securityScheme description 或单独一节，不能留给实现阶段"默认约定"，否则不同实现者可能遗漏。
- 【高危/阻塞】未提及 CSRF 防护。本 RFC 把鉴权从占位改为 cookie session，而 cookie 是浏览器自动携带的，这意味着所有 `/admin/*` 的状态变更接口（改密、建号、停用/启用、改角色、重置密码）在没有 CSRF 防护的情况下，可以被恶意页面诱导已登录管理员的浏览器发起跨站请求（如诱导超管在登录状态下访问恶意页面，触发"停用某账号"或"新建后门账号"）。仅靠 `SameSite=Lax/Strict` 可以缓解大部分场景，但 RFC 应明确选择：①仅依赖 `SameSite=Strict`（需确认后台无需跨站跳转登录的场景），或 ②额外加 CSRF token（如同步器 token 或校验 `Origin`/`Referer` header）。目前 RFC 对此完全未讨论，需要补充结论，否则视为遗漏。
- 【高危】密码存储与传输要求未写入契约/RFC。"新密码最少 8 位，需同时含字母与数字"只是复杂度要求，没有提到：
  - 服务端必须用 bcrypt/argon2/scrypt 等慢哈希存储密码，不能明文或简单哈希（如 MD5/SHA256 直接摘要）落库；
  - 全部 `/admin/*` 接口必须强制 HTTPS 传输（登录接口传密码明文 body，若允许 HTTP 明文传输等于密码直接泄露）。
  建议在"影响面"或新增一节"安全要求"里显式写明，否则实现阶段容易被跳过，且 ADR 里也未覆盖这一点，属于 RFC 应补的空白。
- 【中危】登录失败锁定机制可能被绕过用于账号枚举：
  - 当前 403 场景合并了"密码错误 / 账号已停用 / 账号被锁定"，从状态码看不出区别，这点做得对，能防止直接区分；但 description 里如果实现时给出不同的 errorMessage 文案（如"账号不存在"vs"密码错误"），依然会泄露 loginName 是否存在，建议在 RFC 里明确要求：登录失败（无论 loginName 不存在、密码错误、还是账号被锁定但外部不可见的场景）对外必须返回统一文案，不能区分。
  - 密码比对建议使用哈希库自带的恒定时间比较（如 bcrypt.compare），避免时序侧信道，这点也应在实现要求里提一句（虽然是实现细节，但账号安全模块建议 RFC 层面点名，防止遗漏）。
  - 锁定策略目前只按账号维度（连续 5 次锁 15 分钟），未提及 IP 维度限流。攻击者可对大量不同 loginName 各尝试 4 次（低于锁定阈值）做撞库/枚举，不会触发任何锁定。建议补充 IP 级别的速率限制（如 `express-rate-limit` 或网关层限流），或至少在"不做的替代方案"里显式说明"IP 级限流不在本期做"并说明理由，而不是完全不提。
- 【中危】一次性明文初始口令 / 重置口令的展示与传输：
  - `AdminAccountCreatedResponse.initialPassword` 明文写入响应体，若 HTTPS 强制传输能保证链路安全，但还需注意：访问日志、APM/错误监控、反向代理日志如果记录了完整 response body，会导致明文口令被持久化留存。建议 RFC 补一句"网关/日志系统需对 `/admin/accounts` POST 与 `/admin/accounts/{id}/password-reset` 的响应体做脱敏或禁止记录 body"，否则这条"服务端不落库明文"的承诺会被日志系统间接破坏。
  - 建议同时确认前端展示该口令的页面不允许被浏览器自动填充/缓存（但这属于实现细节，非阻塞项，供参考）。
- 【低危】越权检查基本覆盖：超管专属接口（建号/列表/停用启用/改角色/重置密码）均声明"仅 super_admin 可调用"并有 403，`CANNOT_DISABLE_SELF`、`LAST_SUPER_ADMIN` 也覆盖了自我停用与超管归零的越权/误操作场景，这部分设计是合理的。需要补一句确认：这些接口的 403 判断必须在服务端会话读取角色后做，不能信任客户端传入的角色字段（当前 requestBody 未包含角色自证字段，看起来没有这个风险，仅提醒实现时注意）。
- 建议：将上述"Cookie 属性"与"CSRF 防护"两项列为本 RFC 定稿前必须补充的内容，其余为实现阶段需遵守但可以不进契约本身的安全要求（可以写进 spec 或单独的安全实现清单）。

结论：发现 2 项高危（Cookie 属性缺失、CSRF 防护未定义）、1 项高危（密码存储/传输要求未写明），建议在合并前补充这三项后再定稿；IP 级限流与日志脱敏建议一并说明，不构成阻塞但应有明确结论而非沉默遗漏。

### reviewer-api
- **[高危] `FORBIDDEN` 403 复用过度，客户端无法按 code 分支**：errors.yaml 明确"客户端应按 code 分支"，但本 RFC 把"角色不足""账号已停用""密码错误""账号被锁定""强制改密未完成"五种语义完全不同的场景全塞进同一个 FORBIDDEN。建议拆出 `INVALID_CREDENTIALS`（密码错误）、`ACCOUNT_DISABLED`（账号已停用）、`MUST_CHANGE_PASSWORD`（强制改密未完成时调用其他接口），FORBIDDEN 只保留给"已登录但角色不足"。
- **[高危] 会话 Cookie 安全属性未定义**（与 security-reviewer 重合）：Set-Cookie 未规定 HttpOnly/Secure/SameSite/Path/Domain，且未说明管理后台与 API 是否同源（决定 CORS credentials 策略）。
- **[高危] "首个超管账号"的鸡生蛋问题未提及**：adminCreateAccount 要求调用者已是 super_admin，但上线时不存在任何账号，需要部署侧种子脚本，RFC"影响面"完全没提。
- **[中] 建号/重置密码的一次性明文口令与重试/幂等语义冲突**：这两个接口没有 Idempotency-Key，网络超时导致客户端未收到口令时，账号会陷入"存在但没人知道初始密码"的状态，只能靠再次 reset 补救。
- **[中] 登录失败计数的并发/竞态未定义**：计数器自增是否原子、锁定窗口是固定还是滑动、成功登录后是否清零、锁定判断与密码校验的先后顺序（侧信道风险）均未写明。
- **[中] 会话吊销要求"同步一致读，不允许缓存延迟"未显式写入**：源于"停用立即生效"的零容忍要求，若实现为内存缓存+定期刷新会引入延迟窗口。
- **[低-中] adminSetAccountStatus/adminSetAccountRole 的多校验规则判定顺序未定义**：存在性/自身操作限制/幂等短路/末位超管保护的先后顺序需显式写出（比照 F-005 的"检查顺序"写法）。
- **[低] 启用/停用用单一 POST+body.enabled，与 F-001 的独立动词端点风格不同**：两种模式各有合理性，建议在 RFC 里显式说明选择理由避免被误认为遗漏。
- **[低] AdminAccountList 缺少默认排序约定**。

**对其他端的隐含要求：** 运维侧需要种子脚本创建首个超管；管理后台前端需要按 Set-Cookie 实际属性决定 credentials 策略；F-001/F-003/F-004/F-005 的操作日志 operatorId 粒度（只记 accountId 还是连带 sessionId）需要明确。

### 裁决结果（用户授权按推荐方案自行决断）

| 问题 | 裁决 |
|---|---|
| Cookie 属性（阻塞级） | HttpOnly; Secure; SameSite=Strict; Path=/admin；管理后台前端与 API 同源部署 |
| CSRF 防护（阻塞级） | SameSite=Strict + 状态变更接口校验 Origin header 双重防护 |
| 密码存储/传输（阻塞级） | argon2id（或 bcrypt cost≥12），恒定时间比较，全站强制 HTTPS |
| FORBIDDEN 是否拆分 | 拆分为 FORBIDDEN（角色不足）/ MUST_CHANGE_PASSWORD / INVALID_CREDENTIALS / ACCOUNT_DISABLED / ACCOUNT_LOCKED |
| 密码错误 vs 账号不存在是否统一提示 | 统一为 INVALID_CREDENTIALS，防枚举；ACCOUNT_DISABLED/ACCOUNT_LOCKED 可区分（调用方已知 loginName，不构成新枚举面） |
| 首个超管的鸡生蛋问题 | 记为部署前置依赖（种子脚本，非契约范畴），已加入 RFC 独立小节 |
| 建号/重置密码是否加 Idempotency-Key | 不加，接受"网络超时后靠再次 reset 补救"的路径（ADR-026 既有裁决的自然延伸）；网关/日志强制脱敏两个接口的响应体 |
| 登录失败计数并发/窗口 | DB 原子自增，固定 15 分钟窗口，成功登录清零，先比对密码再判断锁定，登录接口加 IP 级限流 |
| 会话吊销一致性 | 显式要求同步一致读，不允许缓存延迟 |
| status/role 接口检查顺序 | 已写入接口 description（存在性 → 自身操作限制/角色校验 → 幂等短路 → 末位超管保护 → 执行） |
| 启用/停用端点风格选择 | 保留单一 POST+enabled 布尔值，RFC 内注明与 F-001 动词端点风格并存是刻意选择 |
| 账号列表默认排序 | id 升序 |
| operatorId 粒度 | 只记账号级 accountId，不记 sessionId |

以上均已落实到本 RFC 正文，无需再回评审小节确认。
