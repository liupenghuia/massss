# F-006 后台账号管理 — 评审对照表

> 由 /conflicts 生成，机械提取。不含整理者判断。

## 一致项
<!-- 各方无异议，可直接进 spec -->

- 管理后台必须登录才能进页面、才能调 `/admin/*`。
- 账号仅两级：管理员、超级管理员。无只读、无审核员、无审批流、无字段级分权。admin / api 另写明无多租户、无第三方身份登录。
- 车辆 / 图片 / 价格 / 回收站两边业务能力相同；权限差只在「生成、分配、停用管理员账号」。管理员不能创建 / 停用别人的账号。
- 前台无用户体系、`/public/*` 不带登录态；不得复用后台会话。
- 登录主体须作为 F-001 / F-003 / F-004 操作日志与价格记录的「操作人」。
- 停用后必须不能再登录、不能再改数据；不能只挡登录页 / 只藏按钮。
- 账号管理写接口必须再校验超级管理员角色；仅藏 UI 不够。
- 操作人落库用稳定账号 ID，不用微信昵称 / openid；停用后历史记录仍应对应同一 ID。
- 密码只存哈希；初始口令 / 凭证不写进仓库。
- miniapp：对照 ADR-001，本 feature 不做小程序、不做微信 / 企微登录、不把 `/admin/*` 接到小程序。

## 冲突项

### C-1 账号生命周期审计是否本期必做
- 各方主张：admin 主张生命周期本身要落库审计（谁在何时生成 / 停用了谁），本期可不做查看页 ／ api 主张 brief 未要求记录「谁创建 / 停用了谁」，列为低优先级 ／ qa 将其列为待答，未主张必做或可不做
- 分歧根因：brief 未写审计范围，admin 按追溯需要主张落库，api 按 brief 字面范围收缩
- 选项 A：本期落库审计、不做查看页 — 代价：评审原文未写实现与查询成本
- 选项 B：本期不记账号生命周期审计 — 代价：admin 写「出事时只能查库」

### C-2 「生成 / 分配」做成一步还是两步，口令谁产生
- 各方主张：admin 主张做成超管创建账号（标识 + 初始口令一次展示）；若产品把生成和分配合成一步，则做成「新建管理员」单动作 ／ api 接口草图为 `POST /admin/users`（仅 super），同时并列两种口令来源：超管指定登录名 + 初始密码，或系统生成随机口令再展示一次 ／ domain 主张「生成」与「分配」尚未建模，未选定一步或两步 ／ miniapp 主张不要出现「扫小程序码领账号」，形态由谁定未自认 ／ qa 主张步骤与凭证未定义则无法写用例
- 分歧根因：brief 并列「生成、分配」，未定义动作边界与凭证交付
- 选项 A：一次「新建管理员」（标识 + 口令一次展示） — 代价：domain 指出谁拥有凭证、何时可登录仍可能歧义
- 选项 B：生成与分配两步（先造号再交付 / 改密） — 代价：admin 写运营日常可能只是「给新人一个能登录的号」

### C-3 会话载体：服务端会话 vs 未选定的 cookie/token
- 各方主张：api 主张会话存服务端，不把角色塞进不可吊销的长 JWT；停用必须让已签发凭证立即失效 ／ admin 未选定 cookie 还是 token，只要求每次 `/admin/*` 校验未停用 ／ qa / domain / miniapp 要求停用后已有凭证立即失效，未主张具体载体
- 分歧根因：成功标准要求「立即」，各方对载体能否吊销的假设不同
- 选项 A：服务端可吊销会话（api） — 代价：评审原文未写存储与运维代价
- 选项 B：仅客户端 token / cookie、未承诺服务端吊销 — 代价：admin / api / qa 均标为高：过期前仍能改价、上下架、回收站

### C-4 停用后账号行是否保留（相对物理删除）
- 各方主张：domain 主张停用是状态转移、不是物理删除，以便历史操作人仍指向同一账号 ／ api 主张停用后若级联删用户行则日志外键断裂 ／ admin / qa 将「能否删除、与停用区别」列为未决，未主张必须删除
- 分歧根因：brief 只写停用，未写删除 / 再启用
- 选项 A：仅状态停用、保留行 — 代价：停用后无出口是否成死状态（domain 高）
- 选项 B：允许物理删除 — 代价：api 写日志外键断裂；domain 写历史操作人无法指向同一账号

## 无人认领的空白
<!-- 所有角色都默认别人会处理的事。这一节最有价值，务必仔细找 -->

下列事项没有任何角色写明「由本角色负责落地」；多为向别人提问或列为风险。

1. **首个超级管理员如何产生**  
   admin / api / domain / qa 均提出（安装种子、手工插库、一次性初始化页）。无人认领种子脚本、初始化页或插库规程。qa 另问自动化是否允许固定种子、口令如何安全存放，无人认领存放位置。

2. **「分配」的交付形态与责任人**  
   口令、一次性链接、仅超管代设密码：miniapp 问「由谁定」，admin / api / domain / qa 只提问。无人认领交付通道（如何把口令交给使用人）。

3. **忘记密码 / 首次强制改密 / 自行改密 / 超管重置别人密码**  
   五份评审均提问或列为未覆盖。无人认领改密接口、重置流程、忘记密码处理方。

4. **最后一个（或唯一）可用超级管理员被停用后的解锁**  
   各方列为风险或问题。无人认领「禁止停唯一超管」的实现方，也无人认领锁死后的恢复规程。

5. **超级管理员如何继续产生（多个超管、超管能否创建超管、超管停用超管 / 自己）**  
   全员提问。无人认领角色创建规则的写入与校验归属。

6. **登录名规则、能否变更、停用后登录名能否被新号占用**  
   api 主张登录名全局唯一索引，但复用规则未认领。admin / qa / domain 只提问。无人认领占用策略与改名策略。

7. **「立即」的量化与进行中写请求**  
   domain 问已持有登录态、进行中写事务、多标签页、最大失效窗口。api 问是否允许最多一次正在进行的请求做完。qa 要可测口径。无人认领失效窗口数值与事务打断策略。

8. **未登录 / 角色不足 / 已停用的稳定 HTTP 状态与错误码**  
   api 要求契约有未登录、无角色、已停用、登录失败、登录名冲突等稳定码，未写具体码值。qa 要可断言的状态码与错误体、是否区分三类。无人认领码表起草。

9. **登录页是否算 `/admin/*`、该页是否允许匿名**  
   qa 标低：登录页可匿名与「未登录不能进后台」易测成互斥。api 问登录接口是否匿名、其余是否全部要登录。无人认领登录路由与鉴权白名单。

10. **会话有效期、滑动续期还是绝对过期、是否单设备 / 多端同时在线**  
    admin / api / qa / miniapp 均提问。无人认领 TTL 与并发登录策略。

11. **登录失败锁定与密码强度**  
    api / qa / domain 提出。无人认领锁定策略与强度规则。

12. **角色创建后能否升降级**  
    仅 domain 提问。无人认领。

13. **管理员误开账号管理 URL 时的页面展示**  
    仅 admin 提问。无人认领 403 页 / 跳转 / 文案。

14. **账号列表是否展示已停用账号；筛选与导出**  
    admin 主张最小列与角色 / 状态筛选，本期不做批量停用、不做导出。qa 问列表是否仍展示已停用。展示规则无人与 qa 对齐认领。

15. **管理后台与前台同域时的 Cookie 隔离**  
    admin / api 提问并要求分区；无人认领部署拓扑与 Cookie 属性（Domain / Path / 分区）的具体方案。

16. **停用成功后，被停用者已打开后台的退出时机**  
    domain 写「下一次请求失败时退出」。admin 写「当前会话立即失效」。无人认领管理端如何侦测失败并整页回登录（与「立即」窗口相关）。

17. **操作人展示：稳定 ID、登录名，还是 ID + 当时显示名快照**  
    落库用稳定 ID 一致；展示字段五份都在问。无人认领日志 / 价格记录的展示字段。

18. **ADR-001 是否 100% 维持（全程无小程序）**  
    miniapp 提问。无人以产品身份确认；miniapp 只声明若维持则本端无增量。

19. **契约变更提案**  
    api 要求错误码与中间件；按项目铁律不直接改 contracts/。无人认领对 contracts 的 RFC / 提案起草。

20. **越权矩阵固定用例的编写归属**  
    qa 要求把「后台账号越权」写成固定用例（管理员改他人账号、已停用改车辆 / 价格 / 图片 / 回收站）。无人认领矩阵初稿由 qa 独写还是与 api 对码表后写。

## 需要用户裁决的问题

1. 第一个超级管理员怎么来：安装种子、手工插库，还是一次性初始化页？自动化验收是否允许固定种子账号？口令放哪里（不可进仓库）？
2. 「生成」和「分配」是两个步骤还是一次「新建管理员」？凭证如何交给对方（超管指定密码 / 系统随机口令展示一次 / 其他，且不要小程序码）？
3. 登录凭证是什么（登录名 + 密码）？是否强制首次改密？忘记密码谁处理？管理员能否改自己的密码？超管改 / 重置别人密码是否本期范围？
4. 超级管理员能否创建另一个超级管理员？系统是否允许多个超管？超管能否停用其他超管、能否停用自己？是否允许零个可用超管 / 最后一个启用超管是否禁止停用？
5. 停用后账号是保留（可再启用）还是不可逆？是否允许删除账号（与停用区别）？删除后历史操作人如何显示？列表是否仍展示已停用账号？
6. 登录名创建后能否修改？被停用账号的登录名能否被新号占用？
7. 「操作人」落库与展示分别是账号稳定 ID、登录名，还是 ID + 当时显示名快照？
8. 「立即」停用：是否作废全部已有会话、是否打断进行中的写请求？允许的最大失效窗口是多少？是否允许最多一次正在进行的请求做完？
9. 会话形态：cookie 还是 token、是否必须服务端可吊销？有效期多久，滑动续期还是绝对过期？同一账号是否允许多端 / 多标签同时登录？停用或改密后是否踢光全部会话？
10. 登录名规则与密码强度？登录失败是否锁定？
11. 角色创建后能否升降级，还是创建后不可变？
12. 未登录访问 `/admin/*` 的 HTTP 状态码、错误体、页面跳转分别是什么？已登录但角色不足、已停用是否同一套码？登录接口是否匿名，其余全部要登录？
13. 管理后台登录页的 URL 是否在 `/admin` 下？该页是否允许未登录访问？管理员误开账号管理 URL 时如何展示？
14. 账号管理页本期要不要操作记录查看？账号生命周期是否要落库审计（即使无查看页）？
15. 管理后台与前台是否同域部署？Cookie 如何隔离以免串到前台？
16. 是否 100% 维持 ADR-001（全程无小程序、无微信一键登录）？
