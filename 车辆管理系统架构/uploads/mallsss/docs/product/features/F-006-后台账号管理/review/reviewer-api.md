## 我理解的需求

管理后台全部走同一服务的 `/admin/*`；前台无用户体系、`/public/*` 永不带登录态。账号仅两级：管理员与超级管理员。无只读、无审核流、无字段级分权、无多租户、无第三方身份登录。未登录不得进入管理后台、不得调用 `/admin/*`。停用后须立即不能登录、不能再改数据。登录主体要能作为操作日志与价格记录的「操作人」。

## 我的方案倾向

- **模型**：`admin_users`（稳定内部 ID、登录名、密码哈希、角色 `admin|super_admin`、状态 `active|disabled`）。登录名全局唯一索引。
- **鉴权**：`/admin/*` 一律校验会话；角色检查只挡账号 CRUD。会话存服务端，不把角色塞进不可吊销的长 JWT；停用必须让已签发凭证立即失效。
- **接口草图**：`POST /admin/auth/login`、`POST /admin/auth/logout`、`GET /admin/auth/me`；`POST /admin/users`（仅 super）、`POST /admin/users/:id/disable`（仅 super）、`GET /admin/users`（仅 super）。
- **操作人**：日志与价格记录写账号内部 ID。账号停用后历史记录仍能解析到同一 ID。
- **密钥**：密码只存哈希；不把凭证写入仓库。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 停用与会话吊销不同步 | token 在过期前仍能调 `/admin/*`，违反成功标准与越权零容忍。 |
| 高 | 「生成、分配」语义未定义 | 未说明口令如何产生、如何交给使用人。 |
| 高 | 引导账号/最后一个超级管理员 | 第一个超管如何出现、能否停用唯一超管，未写。 |
| 中 | 登录接口暴力破解 | 无锁定策略时口令空间可扫。 |
| 中 | 操作人与停用账号的关联 | 停用后若级联删用户行，日志外键断裂；登录名复用会张冠李戴。 |
| 低 | 列表与审计 | 是否记录「谁创建/停用了谁」brief 未要求。 |

## 对其他端的隐含要求

- **管理后台**：所有 `/admin/*` 调用带会话；401 整页回到登录。角色由 `GET /admin/auth/me` 下发。
- **前台**：零登录、零账号 API。Cookie 分区以免前台带上后台凭证。
- **其它 feature**：写接口必须复用同一套「登录且 active」中间件。
- **契约**：需有未登录、无角色、已停用、登录失败、登录名冲突等稳定码。

## 我需要别人回答的问题

1. 「生成、分配」具体是：超管指定登录名+初始密码，还是系统生成随机口令再展示一次？
2. 是否强制首次登录改密？是否支持自行改密、超管重置别人密码？
3. 第一个超级管理员如何创建？超管是否只能有一个？超管能否被停用？
4. 管理员能否停用自己？超管能否创建另一个超管？
5. 停用是终态还是可再启用？
6. 登录名规则与密码强度？登录失败是否锁定？
7. 同一账号是否允许多端同时在线？停用或改密后是否踢光全部会话？
8. 会话有效期、滑动续期还是绝对过期？
9. 被停用账号的登录名能否重新分配给新人？
10. 账号生命周期是否要落操作日志（只落库）？
11. 「立即」的量化：是否允许最多一次正在进行的请求做完？
12. 登录接口是否匿名，其余全部要登录？
13. 管理后台与前台若同主域，Cookie 如何隔离？
