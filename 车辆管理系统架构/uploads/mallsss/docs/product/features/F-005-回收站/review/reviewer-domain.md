## 我理解的需求

管理员对车辆做软删除：离开在管列表进入回收站，前台立即不可见。回收站内可单条恢复；恢复后进入草稿，再按 ADR-003 发布。保留约 1 个月后自动彻底清除。本期不做回收站外彻底删除、不做批量、不做导出。价格记录不级联删除。图片/评估报告对象存储是否随彻底清除删除必须定稿。问题 25（删除可作用的状态）必须在本评审裁决。

## 我的方案倾向

- 回收站用独立生命周期态，不要塞进 F-001 三态枚举。建议 `lifecycle = active | in_recycle | purged` 与 `status` 正交。恢复时强制写成草稿。
- 删除允许作用于草稿、已上架、已下架全部三态（倾向，待裁）。
- 一致性边界：单车一次事务写入回收站标记；价格记录、图片元数据不在同一事务物理删。恢复保留同一技术主键。
- 1 个月必须二选一写死；定时任务幂等。
- 彻底清除后对象存储文件倾向删除。

## 反对/风险
| 严重度 | 问题 | 说明 |
|---|---|---|
| 高 | 状态机四态未定义 | 若把 in_recycle 做成 status 第四值，F-001 全部要改。 |
| 高 | 问题 25 未裁 | 不允许删草稿则误建无出口；不允许删已上架则多一步下架窗口。 |
| 高 | 恢复一律草稿 vs 原状态丢失 | 已上架误删后恢复变成草稿，需重新发布。 |
| 高 | 彻底清除与价格/文件/主键的一致性 | 价格成孤儿；主键复用会错配。 |
| 中 | 「1 个月」边界与死状态 | 过期仍可恢复或过期未清存储都是半死状态。 |
| 中 | 回收站内能否编辑 | 未定义。 |
| 中 | 无手动彻底删除 | 「确定要立刻腾存储」没有出口。 |
| 低 | 在管列表与回收站重复展示 | 运营会当两条车。 |

## 对其他端的隐含要求

- **F-001：** 在管操作必须排除回收站车辆；对回收站车辆发布/下架视为非法转换。
- **F-002 / public：** 过滤升级为 active 且 published。页面不可见 ≠ 文件不可达，要在本 feature 明确直链算不算违规。
- **F-003：** 进站后写附件是否拒绝；彻底清除时是否删对象。
- **F-004：** 删除/恢复/清除都不得抹价格。清除后价格记录入口必须定。
- **管理后台：** 独立回收站列表，与在管列表互斥。
- **F-006：** 普通管理员可删，不要默认写成只有超管能清。
- **操作日志：** 删除、恢复、定时清除都要落库。

## 我需要别人回答的问题

1. 删除允许作用于哪些 F-001 状态？（问题 25，必须裁决）
2. 恢复是否永远落到草稿，即使删除前是已上架？
3. 「1 个月」是 30×24 小时还是日历月？到期后 job 跑完前是否还允许恢复？
4. 彻底清除时车辆主记录物理删除还是保留 purged 标记？价格记录如何被查到？
5. 彻底清除时对象存储是否删除？公开直链在回收站期间是否继续可打开？
6. 回收站中是否允许编辑核心字段、改价、增删图片？
7. 是否维持只能到期自动彻底清除？
8. 在管列表是否必须完全排除回收站车辆？
9. 定时清除 job 的操作人记什么？
10. 同一辆车多次「删除→恢复」是否不限次数？每次是否重新计算 1 个月？
