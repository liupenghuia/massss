# F-005 回收站 — 评审对照表

> 由 /conflicts 生成，机械提取。不含整理者判断。

## 一致项
<!-- 各方无异议，可直接进 spec -->

- 本能力是管理后台：车辆软删除进入回收站，不是当场物理抹掉。
- 进回收站后前台必须立刻不可见；公开侧过滤必须在服务端完成（`/public/*`），不改前台展示逻辑本身。
- 恢复后车辆一律进入草稿，不自动上架；再发布走 F-001 / ADR-003。
- 保留约 1 个月后自动彻底清除；清除后不可恢复。
- 本期不做批量删除/恢复、不做回收站导出。
- 价格记录不随删除/恢复/彻底清除级联抹掉（进站、恢复、清除三条路径均不得抹历史价）。
- 删除允许作用于哪些 F-001 状态（问题 25）必须在本评审裁决。
- 彻底清除时对象存储（图片/评估报告）是否删除必须本 feature 定稿。
- F-001 未预留软删除字段，需要表迁移。
- 在管列表必须排除回收站车辆；回收站为独立列表/页，与在管互斥。
- 对回收站中的车辆不得走发布/下架/改价（及改核心字段、改图——见冲突项中「只读范围」）。
- 不做微信小程序入口（ADR-001）；删除/恢复仅管理后台会话。
- 不做回收站以外的彻底删除入口（admin / domain / api 陈述一致；qa 作为待确认项列出）。
- 停留期内对象/附件须仍可在恢复后使用（彻底清除前不删以便恢复）。
- 旧详情 URL / 公开子资源应对已进回收站或已清除车辆表现为不存在。
- 契约变更需先 RFC（api 明确；与项目铁律一致）。

## 冲突项

### C-1 回收站状态如何建模
- 各方主张：domain 主张独立生命周期 `lifecycle = active | in_recycle | purged`，与 F-001 的 `status` 正交，反对把 `in_recycle` 做成 status 第四值 ／ api 主张独立字段（如 `trashedAt` / `trashed_at`），不要做成第四个业务 status，`/public/*` 过滤「published 且 trashedAt IS NULL」 ／ qa 将「独立 status 还是 deletedAt 可空」列为待答 ／ admin 只说要做表迁移、需扩展「回收站中」以及恢复→草稿，未指定字段形态
- 分歧根因：回收站若并入 F-001 三态则 ADR-004 与全部在管接口要改；独立字段/独立生命周期则 F-001 操作必须处处排除该态。
- 选项 A：正交 lifecycle 或 `trashedAt` 可空，不改三态枚举 — 代价：所有列表/PATCH/publish 必须额外判断在回收站。
- 选项 B：`status` 增加第四值（trashed） — 代价：domain/api 标明 F-001/ADR-004 迁移面大。

### C-2 删除允许的源状态（问题 25）
- 各方主张：admin 主张草稿、已上架、已下架都应允许进回收站（倾向，待裁） ／ domain 主张删除允许作用于草稿、已上架、已下架全部三态（倾向，待裁） ／ api 提问：仅 published/unpublished 还是 draft 也可以 ／ miniapp 提问问题 25 ／ qa 提问删除允许作用于哪些状态、已上架是否允许不先下架、对不允许的状态返回什么
- 分歧根因：不允许删草稿则误建无出口；不允许删已上架则多一步下架窗口。
- 选项 A：三态均可删（含已上架直接进站） — 代价：已上架误删后恢复变草稿需重新发布（domain 标高风险）。
- 选项 B：仅已下架，或仅已上架+已下架（admin 列出的另外两档） — 代价：草稿或已上架无直接出口。

### C-3 恢复是否永远落到草稿（即使删除前是已上架）
- 各方主张：admin / api / miniapp / qa / domain「我理解的需求」均写恢复进入草稿 ／ domain 同时将「恢复一律草稿 vs 原状态丢失」标为高风险，并提问是否永远落到草稿
- 分歧根因：已上架误删后丢失原状态，需重新发布；admin 指出若不写成显式「回收站 → 草稿」，实现会按 ADR-004 拒绝恢复。
- 选项 A：恢复强制草稿 — 代价：原上架状态丢失。
- 选项 B：恢复回删除前状态（评审中仅作为风险对照，无角色主张实现） — 代价：未有角色给出完整方案。

### C-4 「1 个月」计时规则
- 各方主张：api 建议 30×24h，从 `trashedAt` 起算，并问任务最多延迟一个调度周期是否可接受 ／ admin / domain / miniapp / qa 均要求在自然月 vs 30×24 小时、时区、到期后 job 跑完前能否恢复之间写死
- 分歧根因：边界未写则过期仍可恢复或过期未清形成半死状态；qa 称禁止只靠人工等 30 天验收。
- 选项 A：30×24 小时自 `trashedAt` — 代价：与日历月观感可能不一致。
- 选项 B：日历月 + 指定时区 — 代价：自然月长度不等，夹具更复杂。

### C-5 彻底清除时对象存储是否删除
- 各方主张：admin 倾向删对象存储，停留期内不删；此条必须用户拍板 ／ domain 彻底清除后对象存储文件倾向删除 ／ api 对象删除走异步补偿，并问元数据是否删除 ／ miniapp / qa 要求裁决；miniapp 指出不删则微信内旧 URL 成幽灵资源
- 分歧根因：不删则持续占存储与直链可达；删除则与 DB 不能同事务，存在半清除。
- 选项 A：彻底清除时删对象（可异步补偿） — 代价：半清除、直链在补偿完成前仍可能打开。
- 选项 B：不删对象 — 代价：存储费用与公开直链长期可达。

### C-6 彻底清除后车辆主记录与主键
- 各方主张：domain 问物理删除还是保留 purged 标记，主键复用会错配 ／ api 中风险：车行已物理删除则主键复用导致价格挂到新车 ／ qa 主张彻底清除后同一车辆 id 在管理端、回收站、公开端均不可再操作，并问 id/VIN 能否被新车复用 ／ admin 问技术主键彻底清除后是否允许被新车复用
- 分歧根因：物理删 vs 保留标记决定价格入口与 id 复用。
- 选项 A：保留 purged 标记、禁止 id 复用 — 代价：表中永久留行。
- 选项 B：物理删除并允许或不允许复用主键（各方未对齐） — 代价：价格孤儿与错配。

### C-7 彻底清除后价格记录如何被查到
- 各方主张：全体同意不级联删价格 ／ admin 问孤儿价格在管理后台要不要可查 ／ api 问按原 vehicleId 查价格保留还是 404 ／ miniapp 问管理后台能否按已清除车辆检索 ／ qa 问按车辆 id 查询应 404 还是仍返回历史 ／ domain 问价格记录如何被查到
- 分歧根因：车没了、价还在，入口未定。
- 选项 A：管理端仍可按原 vehicleId 查历史价 — 代价：需定义「已清除车辆」检索形态。
- 选项 B：按原 id 查价格 404 — 代价：历史价无入口（与「永久保留」并存）。

### C-8 回收站内能否查看/编辑
- 各方主张：admin 回收站内不允许改核心字段、改价、改图；并问能否只读查看图片、报告、价格 ／ api 回收站内只读，禁止 publish/unpublish/改核心字段/改价/改图；并问是否允许查看/编辑 ／ miniapp：回收站中禁止走发布/下架/改价 ／ qa 问改信息/改价/改图还是只读直到恢复 ／ domain：回收站内能否编辑未定义，列为中风险
- 分歧根因：只读范围（字段 vs 附件 vs 价格）未写进同一句话。
- 选项 A：只读（含或不含看图/报告/价格）直到恢复 — 代价：进站后无法修正错误，只能先恢复。
- 选项 B：允许编辑 — 代价：与「在管操作排除回收站」冲突，domain 标未定义。

### C-9 对已在回收站的车重复删除
- 各方主张：api 对已在回收站的车重复删除幂等成功、不刷新 `trashedAt` ／ admin 问应提示失败还是当成功 ／ qa 要求错误码区分重复删除，并问恢复是否幂等
- 分歧根因：幂等成功 vs 业务失败决定错误码与是否刷新保留期。
- 选项 A：幂等成功且不刷新 trashedAt — 代价：调用方无法从成功响应判断是否「第一次删除」。
- 选项 B：提示失败（专用错误码） — 代价：与 api 倾向相反。

### C-10 定时清除与正在恢复谁赢
- 各方主张：admin 问恢复与到期清除同时发生谁赢 ／ api 问定时清除与正在点恢复冲突谁赢 ／ domain / qa 问到期后 job 跑完前是否还允许恢复
- 分歧根因：窗口期与并发无规则。
- 选项 A：恢复优先（到期未跑完仍可恢复） — 代价：过期车可能被救回。
- 选项 B：清除优先或到期即禁止恢复 — 代价：与恢复请求竞态需定义。

### C-11 是否允许回收站内「立即彻底清除」/站外彻底删除
- 各方主张：admin 彻底清除只走到期自动任务；问自动清除失败时运营有无补救（立即清除） ／ domain 倾向维持只能到期自动彻底清除；同时标「无手动彻底删除」为中风险 ／ api 问是否维持禁止站外彻底删除 ／ miniapp / qa 问是否允许立即彻底清除、是否绝对不做加速销毁
- 分歧根因：任务失败则无出口 vs 本期明确不做站外彻底删除。
- 选项 A：禁止任何手动彻底清除 — 代价：任务失败时半死状态无运营补救。
- 选项 B：允许立即彻底清除或失败补救入口 — 代价：突破「本期不做回收站外彻底删除」。

### C-12 公开侧对已进回收站详情的响应形态与缓存
- 各方主张：api / miniapp 建议公开子资源 404 ／ miniapp 另问统一 404 还是 200+ 空态、是否允许文案提及「已删除」；分享卡片无法强制撤回 ／ qa / miniapp 问「立即不可见」是否允许最多 N 秒缓存、N 是多少、进行中的公开请求删除后刷新是否必须失败 ／ domain：页面不可见 ≠ 文件不可达，直链算不算违规要在本 feature 明确 ／ api：公开直链在入站后是否仍保持不失效直到对象被删
- 分歧根因：接口过滤与对象直链/CDN/分享卡片是双通道。
- 选项 A：公开 JSON 一律 404，直链策略另裁 — 代价：分享卡片标题/封面可能残留。
- 选项 B：200+ 空态或提及「已删除」 — 代价：与「当作不存在」不完全一致。

### C-13 权限范围：普通管理员 vs 仅自己删除的车
- 各方主张：admin 已登录的管理员与超级管理员权限相同（都能删、都能恢复） ／ domain：普通管理员可删，不要默认写成只有超管能清；F-006 普通管理员可删 ／ api：F-006 只校验已登录 admin ／ miniapp 问普通管理员能否恢复他人删除的车 ／ qa 问回收站权限是全部车辆还是仅自己删除的；低风险写「恢复、看回收站范围未写」 ／ admin 另要求 F-006 停用账号必须立刻不能再删除/恢复
- 分歧根因：「角色相同」与「是否限本人删除的记录」不是同一问题。
- 选项 A：任何已登录管理员可对全部回收站车辆删/恢复/查看 — 代价：可恢复他人所删。
- 选项 B：仅能恢复自己删除的 — 代价：与 admin「权限相同」字面不完全同范围。

### C-14 删除确认、日志是否含「下架」、操作人
- 各方主张：admin 删除建议二次确认；问恢复是否要确认；问已上架直接删除是否还写一条「下架」日志 ／ qa 问删除是否要二次确认 ／ domain 删除、恢复、定时清除都要落库；问定时清除 job 的操作人记什么 ／ admin 删除进站、恢复、到期彻底清除写入操作日志
- 分歧根因：确认是 UI 规则；job 操作人无自然人。
- 选项 A：删除（及可选恢复）二次确认；日志含或不含下架 — 代价：未裁则实现分叉。
- 选项 B：无二次确认 — 代价：误删窗口只靠回收站。

### C-15 回收站列表展示与检索
- 各方主张：admin 按删除时间倒序；建议展示到期日；问是否要关键字搜索、是否展示原状态与剩余保留天数 ／ api 问展示哪些字段、剩余天数由谁计算 ／ qa 问排序、分页、搜索、展示字段、是否显示剩余天数 ／ domain 未列字段
- 分歧根因：列表可测字段不足则接口无契约。
- 选项 A：倒序 + 到期日/剩余天数 + 原状态 + 搜索分页 — 代价：计算职责（服务端 vs 前端）未定。
- 选项 B：最小列表（qa：UI 可带上线但不等于接口无契约） — 代价：验收字段不足。

### C-16 同一辆车多次删除→恢复、保留期是否重算
- 各方主张：domain 问是否不限次数、每次是否重新计算 1 个月 ／ api 重复删除不刷新 trashedAt（针对已在站内） ／ 其余角色未写次数上限
- 分歧根因：再进站是否新开 1 个月窗口。
- 选项 A：每次删除重新计算 1 个月 — 代价：可无限推迟彻底清除。
- 选项 B：有次数或窗口限制（无角色主张具体上限） — 代价：未定义。

### C-17 恢复后公开 URL 是否复用
- 各方主张：miniapp 问恢复为草稿后公开 URL 是否复用 ／ 其余未写
- 分歧根因：URL 稳定则分享链接在再发布后可能复活。
- 选项 A：复用同一公开 URL — 代价：需保证草稿期仍 404。
- 选项 B：不复用 — 代价：无角色给出替代标识方案。

## 无人认领的空白

- **定时清除 job 的实现责任人**：api 写「可重入扫描；失败重试」、qa 要时间夹具，无角色写「由我实现调度/运维/告警」。
- **job 操作日志的操作人身份**：domain 提问，无人认领写入规则（系统账号？空？）。
- **剩余保留天数由谁计算**：api 显式提问「由谁计算」，admin/qa 要展示，无角色认领服务端字段 vs 前端推算。
- **乐观锁 / version 谁贯穿 F-001 现有写接口**：api 要求删除/恢复带乐观锁并点出与发布/改价/改图竞态，admin 说带 version；无人说明 F-001 现网 PATCH 是否同期改。
- **半清除补偿与对账**：api 标对象删除不可与 DB 同事务、失败重试；无人认领补偿任务、残留对象扫描、失败告警归属。
- **公开直链 / CDN / 缓存失效**：domain/api/miniapp/qa 都指出双通道，无人认领缓存 TTL 数值、CDN 主动失效、对象 ACL 在进站时是否改为私有。
- **微信分享卡片残留**：miniapp 写无法强制撤回，无人认领是否要产品文案或验收例外。
- **进回收站期间附件写入是否拒绝**：domain/qa 标明 F-003 未定义，无人认领禁止或允许上传的接口行为。
- **错误码目录**：qa 要区分非法状态删除、重复删除、对已清除恢复；api 倾向重复删除成功；无人给出码表草案并认领写入 contracts。
- **RFC / contracts 起草人**：api 说契约变更先 RFC，无角色声明由谁写 F-005 接口草案（路径 api 有倾向但未认领落地）。
- **vehicles 表迁移执行与回滚**：多人说必须迁移，无人认领迁移脚本、存量 NULL、与 F-001 发布窗口。
- **孤儿价格在后台的展示入口**：所有人要求不删价格并追问怎么查，无角色认领「已清除车辆价格」页面或接口。
- **主键/VIN 回收策略的写入位置**：问的人多，无角色认领「禁止复用」写进哪份契约。
- **F-006 停用账号立刻不能删/恢复**：admin 对 F-006 提隐含要求，F-006 评审不在本目录，本 feature 无人认领联调用例。
- **删除已上架是否额外写「下架」日志**：仅 admin 提问，无日志方案认领人。
- **二次确认的文案与是否阻断**：admin/qa 提问，无 UI 文案认领。
- **进行中的公开 GET 与删除的可见性 SLA**：qa 要「删除 200 后第 N 次 public GET 必失败」，无人给出 N。
- **验收时间夹具谁提供**：qa 禁止人工等 30 天，无人认领可拨钟的测试时钟或管理接口。
- **回收站关键字搜索/分页契约**：问了，无角色认领分页参数与搜索字段。
- **普通管理员「看回收站」范围与列表接口**：qa 标范围未写；admin 说都能恢复但未写列表是否全量。无人认领 GET 过滤规则。
- **恢复幂等与并发错误码**：qa 中风险，无人认领重复恢复的响应。
- **直链在回收站停留期内是否算违规**：domain 要求本 feature 明确，无角色给出「算/不算」并认领安全/合规表述。

## 需要用户裁决的问题

1. 删除到回收站允许哪些源状态：仅已下架、已上架+已下架、还是草稿+已上架+已下架？不允许时返回什么？（问题 25）
2. 已上架是否允许不先下架直接进回收站？若允许，是否额外写一条「下架」操作日志？
3. 恢复是否必须永远落到草稿（即使删除前是已上架）？
4. 回收站建模：正交 lifecycle、`trashedAt`/`deletedAt` 可空，还是 `status` 第四值？
5. 「1 个月」按 30×24 小时还是日历月？时区？起算点是否为 `trashedAt`？到期后 job 跑完前是否仍允许恢复？
6. 自动清除任务频率、失败重试、最多延迟一个调度周期是否可接受？
7. 彻底清除时车辆主记录物理删除还是保留 purged 标记？
8. 车辆技术主键、VIN 在彻底清除后能否被新车复用？
9. 彻底清除时对象存储图片/报告是否物理删除？元数据是否删除？
10. 公开直链在入站后、对象删除前是否继续可打开？直链可达是否算本 feature 违规？
11. 车被彻底清除后，孤儿价格按原 vehicleId 查询保留还是 404？管理后台要不要可按已清除车辆检索？
12. 回收站内：只读还是可编辑核心字段/改价/增删图片？只读时能否查看图片、报告、价格？
13. 进回收站期间 F-003 附件写入是否拒绝？
14. 是否维持只能到期自动彻底清除、禁止站外/立即彻底清除？任务失败有无运营补救？
15. 对已在回收站重复删除：失败还是幂等成功？是否不得刷新 `trashedAt`？
16. 恢复是否幂等？恢复与到期清除并发谁赢？
17. 同一辆车多次「删除→恢复」是否不限次数？每次是否重新计算 1 个月？
18. 在管列表是否必须完全排除回收站车辆？（各方倾向是，需明示）
19. 普通管理员与超级管理员对删除/恢复/查看回收站是否权限相同？能否恢复他人删除的车？停用账号是否立刻失效？
20. 删除/恢复是否必须二次确认？
21. 定时清除 job 的操作日志操作人记什么？
22. 回收站列表：排序、分页、关键字搜索、原状态、到期日/剩余天数？剩余天数由谁计算？
23. 「立即不可见」：公开接口缓存最长可接受多久？删除 200 后第几次 public GET 必须失败？进行中的请求刷新是否必须失败？
24. 公开侧对已进回收站详情：统一 404 还是 200+ 空态？是否允许文案提及「已删除」？微信分享卡片残留标题/封面是否可接受？
25. 恢复为草稿后公开 URL 是否复用？
26. 彻底清除后同一车辆 id 在管理端、回收站、公开端是否均不可再操作？
