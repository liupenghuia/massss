# F-002 公开列表接口：聚合封面/当前价 + 搜索筛选参数

## 动机

F-002 spec（v1.2，ADR-018/019/022 已裁决）要求：
1. 公开列表卡片一次性带出封面缩略图与当前价，避免前台逐条请求造成 N+1 与「列表在、价格 404」的竞态（ADR-019 C-2）。
2. 前台提供关键字/价格区间/上牌年份/里程区间的搜索筛选，服务端执行，前台保持哑终端（ADR-022）。

现有 `GET /public/vehicles` 返回的 `PublicVehicleList.items` 为纯 `PublicVehicle`（无图无价，无筛选参数），
不满足上述两项已裁决需求。本 RFC 是 F-002 实现前的硬前置依赖。

## 提议

### 1. 新增 `PublicVehicleSummary` schema，作为列表 items 的类型

在 `PublicVehicle` 现有字段基础上，新增两个只读字段，用于列表场景：

```yaml
PublicVehicleSummary:
  type: object
  additionalProperties: false
  description: 公开车辆列表项。字段为 PublicVehicle 加列表专用聚合字段，供 GET /public/vehicles 使用。
  required:
    - id
    - status
    - brand
    - model
    - registrationYear
    - mileageKm
    - color
    - conditionDesc
    - energyType
    - transferCount
    - displacementL
    - energyConsumption
    - batteryKwh
    - createdAt
    - updatedAt
    - coverImageUrl
    - currentPrice
  properties:
    # ...复用 PublicVehicle 的全部现有字段（id/status/brand/.../updatedAt）...
    coverImageUrl:
      type: [string, "null"]
      description: 封面缩略图 URL，服务端保证的字段；无图片时为 null。不由前端拼 CDN 参数。
    currentPrice:
      $ref: "#/components/schemas/PriceValue"
      description: 当前价，等于该车最新一条价格记录的变动后值。面谈车 amount 为 null。
```

`PublicVehicleList.items` 的 `$ref` 从 `PublicVehicle` 改为 `PublicVehicleSummary`。
`GET /public/vehicles/{id}`（详情接口）与 `PublicVehicle` schema 本身**不变**——详情页仍各自调用
`/public/vehicles/{id}/images`、`/public/vehicles/{id}/price` 取完整数据，本 RFC 不影响详情页现有调用方式。

### 2. `GET /public/vehicles` 新增可选查询参数

```yaml
parameters:
  - $ref: "#/components/parameters/Page"
  - $ref: "#/components/parameters/PageSize"
  - name: keyword
    in: query
    required: false
    schema: { type: string, minLength: 1, maxLength: 50 }
    description: 模糊匹配品牌+车型（ADR-022）
  - name: priceMin
    in: query
    required: false
    schema: { type: number, exclusiveMinimum: 0, multipleOf: 0.01 }
    description: |
      当前价下限（人民币元）。使用价格区间筛选（priceMin/priceMax 任一存在）时面谈车（amount=null）
      一律不进结果集。服务端按分为单位（乘 100 取整）比较，不依赖 schema 校验器的浮点 multipleOf 判定，
      避免 128000.10 等合法两位小数被浮点误差误拒。priceMin > priceMax 时返回 400 VALIDATION_ERROR。
  - name: priceMax
    in: query
    required: false
    schema: { type: number, exclusiveMinimum: 0, multipleOf: 0.01 }
    description: 当前价上限，规则同 priceMin。
  - name: registrationYearMin
    in: query
    required: false
    schema: { type: integer, minimum: 1980, maximum: 2100 }
    description: 上牌年份下限。上限动态约束为「当前年份+1」由服务端校验；registrationYearMin > registrationYearMax 时返回 400 VALIDATION_ERROR。
  - name: registrationYearMax
    in: query
    required: false
    schema: { type: integer, minimum: 1980, maximum: 2100 }
    description: 上牌年份上限，规则同 registrationYearMin。
  - name: mileageKmMin
    in: query
    required: false
    schema: { type: integer, minimum: 0 }
    description: 里程下限（千米）。mileageKmMin > mileageKmMax 时返回 400 VALIDATION_ERROR。
  - name: mileageKmMax
    in: query
    required: false
    schema: { type: integer, minimum: 0 }
    description: 里程上限，规则同 mileageKmMin。
```

- 全部参数可选、可组合，组合语义为 AND；不传即当前行为（全量已上架列表）。
- 排序仍固定 `id` 降序（ADR-019），本 RFC 不新增排序参数。
- `priceMin`/`priceMax` 存在任一时，`amount IS NOT NULL`（即排除面谈车）；面谈车不受其余三组参数影响。
- **区间颠倒**（任一组 min > max）：`400 VALIDATION_ERROR`，不当空结果处理。
- **keyword 匹配规则**：服务端 `trim` 后按不区分大小写模糊匹配品牌+车型；trim 后为空字符串等价于未传 keyword。
- **金额精度**：服务端按分为单位（金额 × 100 取整）比较，不依赖 schema `multipleOf` 的浮点判定。
- **分页越界**：筛选后命中总数小于 `(page-1)×pageSize` 时，返回 `items: []`、`total` 为筛选后匹配总数，不报错。
- **无匹配结果**：`total: 0`，`items: []`，`page`/`pageSize` 原样返回请求值。
- **coverImageUrl 为 null**：前台展示占位图，不视为异常（v1.2 spec 已要求前台按空值映射表处理，本条为契约层显式约定）。

### 3. 服务端实现要点（非契约，供实现方参考）

- `coverImageUrl`、`currentPrice` 由服务端一次查询聚合返回，不做运行时逐条 N+1 查询。
- 当前一百台规模内**不需要**为价格/里程/年份区间额外建索引，全表扫描性能足够；规模明显增长后再评估（reviewer-api 指出这是过度设计，采纳）。
- 列表 `currentPrice` 与用户点击详情之间存在极短窗口的读一致性竞态（查询瞬间到用户点击前），属已知可接受限制，比 N+1 方案的竞态窗口已经收窄，不视为缺陷。
- 400 响应复用项目现有错误响应结构（`VALIDATION_ERROR` code），与 `/admin/*` 现有校验错误保持同一套错误体格式。

## 影响面

| 端 | 影响 |
|---|---|
| 服务端 | 新增 `PublicVehicleSummary` schema；列表查询逻辑改为聚合封面+当前价；新增 6 个可选筛选参数与对应查询条件；需要为筛选字段建索引 |
| 前台 | 列表页改用新字段渲染封面/当前价；新增搜索/筛选 UI，转换为查询参数；不再需要（也禁止）对列表逐条请求 images/price |
| 管理后台 | 无影响，`/admin/*` 接口不变 |
| F-001 | 无影响，车辆核心字段与状态机不变 |
| F-004 | 无影响，价格写入接口与历史记录接口不变；`currentPrice` 为只读投影，复用既有 `PriceValue` schema |

## 契约变更

- `contracts/openapi.yaml`：
  - 新增 schema `PublicVehicleSummary`（含 `coverImageUrl`、`currentPrice` 两个新字段）
  - `PublicVehicleList.items` 的 `$ref` 由 `PublicVehicle` 改为 `PublicVehicleSummary`
  - `GET /public/vehicles` 新增 6 个可选 query 参数：`keyword`、`priceMin`、`priceMax`、
    `registrationYearMin`、`registrationYearMax`、`mileageKmMin`、`mileageKmMax`
- 字段与参数只增不改语义；`PublicVehicle`（详情用）、其余接口不变。

## 不做的替代方案

- **前台对列表每条再打 `images`/`price` 接口（N+1）**：代价是 N+1 请求与「列表在、价格 404」的竞态，
  ADR-019 已明确否决，改为服务端一次聚合返回。
- **前台本地过滤/搜索**：与筛选结果的分页、可见性硬过滤（`published`）无法保证一致，
  且违反哑终端原则，ADR-022 已明确否决。
- **面谈车在价格区间筛选时按 0 元或最低价参与排序**：会让访客误以为面谈车是「白菜价」，
  ADR-022 已裁决面谈车一律不进价格区间结果集。
- **列表接口另设排序参数（如按上架时间/改价时间）**：本次不做，ADR-019 已裁定排序固定 `id` 降序，
  不在本 RFC 范围内引入。

## 评审意见

### reviewer-qa
- **区间颠倒未定义**：priceMin>priceMax、registrationYearMin>Max、mileageKmMin>Max 三组区间均未说明服务端行为——是 400 拒绝、直接返回空集，还是静默忽略颠倒条件？这是最容易漏测的边界，必须先定行为再写用例。
- **单边区间语义未明确**：只传 priceMin 不传 priceMax（或反之）是否为合法的开区间查询？三组区间参数是否都允许"只传一边"？契约里 min/max 是分别独立的 optional 参数，隐含允许单边，但未显式写出，需在 acceptance 用例中补一条"仅下限/仅上限"验证。
- **priceMin/priceMax 与 exclusiveMinimum:0 的边界**：0 元本身被排除是对的（面谈车逻辑），但如果访客传 priceMin=0 应返回 400（schema 校验失败）还是被当作"未传"处理？需要明确非法值（0、负数、非法 multipleOf 精度如 1.005）时接口返回 400 还是静默降级。
- **registrationYearMin/Max 缺少边界约束**：只写了 `type: integer`，没有 minimum/maximum。是否允许负数年份、超未来年份（如 9999）、0？需要显式约束。
- **keyword 边界值未覆盖**：minLength:1/maxLength:50 的等值边界（0/1/50/51 字符）需要有对应用例；大小写敏感、中英文混合、trim 首尾空格、纯空格字符串是否算合法 keyword，建议列入待问清单而非自行假设。
- **面谈车与非价格筛选组合的语义空白**：建议在 acceptance.md 里显式补一条"价格区间 + 其他区间同时传，面谈车仍被排除"的组合用例。
- **无匹配结果的响应形态未定义**：筛选后 0 条命中时 total/items/page 的行为需要在 acceptance 里补一条空结果集用例。
- **参数与分页组合**：请求超出筛选后总数范围的 page 时返回空 items 还是 400，需要与既有 Page/PageSize 约定对齐。
- **coverImageUrl 为 null 时前台隐含要求**：需在「影响面」表格前台一行显式写明"封面为 null 展示占位图"，并确认 F-002 acceptance.md 是否已有对应用例。
- **PublicVehicleSummary 字段易与 PublicVehicle 漂移**：正文用省略号带过具体字段列表，落地 openapi.yaml 时建议做一次字段级 diff 校验。
- **400 错误响应缺少统一 schema 引用**：非法 keyword/price/year 的 400 场景未指向项目既有错误响应格式。
- **与 acceptance.md 的逐条核对未完成**：建议合入前再做一次 acceptance.md diff，确认上述边界用例是否已存在。

**需裁决问题（QA 提出）：**
1. priceMin>priceMax / registrationYearMin>Max / mileageKmMin>Max 时，服务端返回 400 还是空结果集？
2. registrationYearMin/Max 是否需要 minimum/maximum 边界（如 1900～当前年份+1）？
3. 请求 page 超出筛选后总数范围时，返回 400 还是空 items？
4. keyword 为纯空格字符串时是否视为合法查询（是否需要服务端 trim）？
5. 400 错误响应是否有统一 schema 可复用，其结构是什么？
### reviewer-api
- 缺失区间校验语义：priceMin/priceMax、registrationYearMin/Max、mileageKmMin/Max 均未声明"下限>上限"时的行为，也没写清是报 400 还是当空结果处理。
- `multipleOf: 0.01` 在浮点数上有精度陷阱，建议注明"服务端按分为单位比较，不依赖 schema 校验器的浮点判定"。
- `registrationYearMin`/`Max` 只声明 `type: integer`，无 minimum/maximum，建议补合理范围（如 1980～当前年+1），避免脏值。
- "priceMin/priceMax 存在任一时面谈车一律不进结果集"这条业务规则只写在 RFC 描述里，未落进契约 description，必须写进 openapi.yaml 对应参数的 description，否则实现/联调时会被遗漏。
- `PublicVehicleList.total` 在筛选场景下的语义需显式声明为"筛选后匹配总数"。
- `keyword` 是否大小写不敏感、是否 trim 首尾空格未定义，纯空格字符串会通过 minLength:1 校验但语义不清。
- 索引建议与 `docs/principles.md` 的"百台以内"规模不符，属过度设计，建议改为"当前规模可不建索引，未来增长再评估"。
- 残留读一致性问题：列表 `currentPrice` 与详情价格可能存在极短窗口的不一致（比 N+1 方案的竞态窗口已收窄），建议在「影响面」补一句注明为已知可接受限制。

- keyword 是否要求大小写不敏感、是否 trim 空白？（英文品牌名场景通常需要）
