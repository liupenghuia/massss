# ADR-001 前台与管理后台均采用 Web，不做微信小程序

Status: Accepted
Date: 2026-08-19
Feature: F-001, F-002, F-006（全局技术选型，问题来源于 F-001 的 /conflicts 第 19 条）
Supersedes: -

## Context

F-001 的 5 方独立评审中，reviewer-miniapp 指出全项目文档从未确认是否以微信小程序形式交付任何一端，
其余四方评审均默认走 Web、且从未确认过这个前提。arbiter 在 `/conflicts F-001` 中将此列为
「需要用户裁决的问题」第 19 条，并指出这直接决定 miniapp 评审的其余风险条目（第 20-23 条：
小程序类目资质、账号体系与微信身份绑定、评估报告在小程序端的可预览格式、
"发链接给客户看"是否要求脱离微信打开）是否成立。

## Decision

前台与管理后台均采用 Web 交付，不做微信小程序端。移动端体验通过响应式/自适应网页兼容手机浏览器实现，
不引入小程序技术栈，不涉及小程序账号体系与登录态，不涉及小程序审核与类目资质问题。

## Consequences

+ 与 principles.md 中"发链接给客户看 → 纯客户端渲染即可"的诉求直接匹配，链接语义清晰，无需额外的小程序码/短链方案。
+ 管理后台维持"桌面优先"定位不变，避免为小程序表单能力弱、文件操作能力弱的问题投入额外开发成本。
+ 避免了二手车/汽车展示类目在微信小程序审核中可能被要求额外资质的风险（miniapp 评审问题 20）。
+ F-001 conflicts.md 中的问题 20-23（小程序类目资质、账号与微信身份绑定、小程序端文件预览格式、分享链路）随之作废，无需再裁决。
- 放弃了微信生态内的低门槛触达与分享能力（如小程序卡片分享、小程序码），后续若确需借助微信流量导流，需重新立项评估。
- 管理员"随手在手机上快速上下架"的场景依赖响应式网页而非原生小程序体验，交互流畅度弱于原生小程序。
