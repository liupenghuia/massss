# ADR-031 F-006 账号与会话接口契约定稿

Status: Accepted
Date: 2026-08-19
Feature: F-006
Related: ADR-026（账号生命周期与超管制衡）、ADR-027（会话鉴权与停用即时性）、ADR-028（账号数据模型与部署隔离）
RFC: docs/rfc/2026-08-19-F-006-账号与会话接口.md（Accepted，契约已改）

## Context

ADR-026/027/028 裁决了账号体系的业务规则，但契约层的鉴权实体化与安全属性一直是占位状态——
`contracts/openapi.yaml` 的 `adminAuth` securityScheme 明确写着"本 scheme 仅为占位"，
`errors.yaml` 的 `UNAUTHORIZED` 也写着"不在本期定义 403"。RFC 落地评审由 reviewer-security
与 reviewer-api 发现多项安全阻塞项（Cookie 属性缺失、CSRF 未定义、密码存储要求缺失）与设计
缺口（错误码复用过度、首个超管的鸡生蛋问题、幂等语义未定义）。用户授权按推荐方案自行决断
定稿，契约已改入 `contracts/openapi.yaml` 与 `contracts/errors.yaml`。本 ADR 记录最终定稿的
安全属性与接口边界。

## Decision

### 会话与 Cookie 安全属性（阻塞级，已修复）
- Cookie 属性：`HttpOnly; Secure; SameSite=Strict; Path=/admin`。
- 管理后台前端与 API **同源部署**，不需要跨域 CORS credentials 配置。
- CSRF 双重防护：`SameSite=Strict` + 全部状态变更接口（POST/PUT/DELETE）校验 `Origin` header。
- 会话吊销**同步一致读**：每次请求实时查会话存储判定是否已吊销，不允许缓存延迟窗口。

### 密码安全（阻塞级，已修复）
- 服务端用 **argon2id**（或 bcrypt，cost ≥ 12）存储密码哈希，禁止明文/弱哈希落库。
- 全部 `/admin/*` 强制 HTTPS。
- 密码比对用恒定时间比较，避免时序侧信道。

### 错误码拆分（避免 FORBIDDEN 过度复用）
- `FORBIDDEN`（403）仅用于"已登录但角色不足"。
- 新增 `MUST_CHANGE_PASSWORD`（403）、`INVALID_CREDENTIALS`（403，密码错误或账号不存在统一
  返回同一码防枚举）、`ACCOUNT_DISABLED`（403）、`ACCOUNT_LOCKED`（403）、
  `ACCOUNT_LOGIN_NAME_TAKEN`（409）、`CANNOT_DISABLE_SELF`（403）、`LAST_SUPER_ADMIN`（409）。

### 登录失败防护
- 失败计数按账号维度、DB 原子自增；固定 15 分钟锁定窗口；成功登录清零。
- 先做密码比对再判断锁定阈值，避免侧信道；登录接口加基础 IP 级速率限制。

### 一次性口令与幂等
- 建号 / 重置密码**不提供 Idempotency-Key**：网络超时未收到口令时，接受"靠再次 reset 补救"
  的恢复路径（不做"重放返回同一口令"以免破坏"口令不落库明文"的安全承诺）。
- 网关/日志系统对这两个接口的响应体做脱敏（不记录 body）。

### 检查顺序（status / role 变更接口）
- 统一顺序：角色校验（是否超管）→ 目标账号存在性 → 自身操作限制（不能停用/降级自己相关规则）
  → 幂等短路（已是目标状态直接 200）→ 末位超管保护 → 执行变更。

### 部署前置依赖（非契约，记录以防遗漏）
- 首个超级管理员种子脚本（ADR-026 已定口令来源，脚本本身需部署阶段实现）。
- 全站 HTTPS 强制，网关层配置。

## Consequences

+ 三项安全阻塞项（Cookie 属性、CSRF、密码存储）在合并进契约前被拦下并修复，避免留下可被
  安全审计打回的漏洞。
+ 错误码拆分后前端可以精确区分"密码错、账号停用、需要改密、无权限"四种完全不同的处理路径。
+ 检查顺序显式写入契约，避免多个校验规则同时命中时的行为不确定。
- 新增 8 个错误码，客户端错误处理分支进一步增多（叠加 F-005 的 3 个，账号相关模块的错误码
  已经不少，需要前端有一份集中的错误码到 UI 文案映射表）。
- 首个超管种子脚本与 HTTPS 强制是部署侧责任，不受契约测试覆盖，需要在上线检查清单里显式列出，
  否则契约测试全绿也可能因为漏了这一步而无法登录。
- 建号/重置密码不支持幂等重放，极端网络环境下运维体验略差（需要多点一次重置），
  换来的是不在系统任何地方持久化明文口令的安全保证，判断为值得的取舍。
