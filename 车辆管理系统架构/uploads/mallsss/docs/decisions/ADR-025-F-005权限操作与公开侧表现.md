# ADR-025 F-005 权限、操作与公开侧表现

Status: Accepted
Date: 2026-08-19
Feature: F-005, F-002, F-006
Related: ADR-019（F-002 公开接口读模型与缓存）、ADR-006/待定 F-006 权限模型

## Context

`/conflicts F-005` 冲突项 C-8、C-12、C-13、C-14、C-15、C-17，用户裁决问题 12、13、18-25。
回收站内能做什么、谁能操作、删除要不要二次确认、公开端看到什么，是本 feature 面向用户的
最后一批空白。本文件定稿。

## Decision

### 回收站内的车辆
- **完全只读**：禁止发布 / 下架 / 改核心字段 / 改价 / 改图。
- 允许**查看**该车全部图片、评估报告、完整价格历史（只读展示，不可编辑）。
- 停留在回收站期间，F-003 的附件上传接口对该车**拒绝写入**（与只读原则一致）。
- 要修改任何内容，必须先恢复到草稿。

### 权限范围
- 任何已登录管理员权限相同：**都能删除、恢复、查看全部车辆的回收站记录**，
  不限「只能恢复自己删除的」。
- F-006 账号被停用后，**立刻**不能再执行删除 / 恢复（与账号会话失效同步）。

### 操作确认与日志
- **删除**需要二次确认（防误删）；**恢复**不需要二次确认。
- 删除进站、恢复、到期彻底清除（含失败重试）均写入操作日志。
- 定时清除 job 的操作人字段记为**系统账号标识**（如 `system:scheduled-cleanup`），
  不留空、不冒用任何管理员身份。

### 回收站列表
- 排序：**删除时间倒序**。
- 展示字段：车辆基本信息、**原状态**（删除前的 status）、删除时间、**到期日 / 剩余保留天数**
  （服务端计算并返回，前端不推算）。
- 支持**关键字搜索**（品牌/车型）与**分页**，与 F-001 在管列表的搜索体验一致。

### 公开侧表现（对齐 ADR-019）
- 公开端对已进回收站的车辆 id **一律 404 VEHICLE_NOT_FOUND**，与「不存在 / 已下架」同一响应，
  **不做** 200 + 空态，**不提**「已删除」等文案。
- 遵循 ADR-019 的零缓存策略：删除动作生效后，下一次公开 GET 必须立即 404，无可接受延迟窗口。
- 微信分享卡片的标题/封面**无法强制撤回**，属已知限制，书面接受，不作为验收失败项。
- 恢复为草稿后，若后续再次发布，**复用同一个公开 URL**（URL 基于车辆 id，天然稳定）；
  草稿期该 URL 仍按 ADR-019 统一 404 语义处理。

## Consequences

+ 只读范围一句话覆盖了写操作与查看操作，实现时不需要在多处零散判断。
+ 权限「都一样、不限本人」简化了鉴权逻辑，与 F-006「无审批流程、单一管理员角色」的既有裁决一致。
+ 公开侧 404 语义与 F-002 完全对齐，不需要为回收站单独写一套响应规则。
- 「删除需要二次确认」增加一次前端交互，误删概率降低但操作链路变长。
- 微信分享卡片残留是不可控的第三方缓存行为，运营需要口头知晓「删除不等于别人转发出去的卡片消失」。
- 权限不区分「谁删的」意味着任何管理员都能恢复他人误删的车，也能重新删除他人恢复的车，
  多人协作下可能出现来回拉扯，本期接受，不做记录级权限控制。
