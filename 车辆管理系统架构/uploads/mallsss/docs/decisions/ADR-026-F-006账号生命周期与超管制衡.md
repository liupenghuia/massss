# ADR-026 F-006 账号生命周期与超管制衡

Status: Accepted
Date: 2026-08-19
Feature: F-006

## Context

`/conflicts F-006` 冲突项 C-1、C-2、C-4，用户裁决问题 1-5。
首个超管如何产生、建号与分配是否分步、超管之间能否互相操作、停用后账号是否可逆，
决定了账号体系的基本骨架。本文件定稿。

## Decision

### 首个超级管理员
- 部署时跑**种子脚本**创建唯一初始超级管理员，口令通过**环境变量**注入，不写进仓库、不写进代码。
- 自动化测试允许使用固定种子账号，但**仅限测试环境**，不得复用到生产种子口令。

### 建号与分配
- 建号是**一次性动作**：超管填写登录名提交「新建管理员」，系统**生成随机初始口令**，
  在创建成功页面**展示一次**（不落明文、不可再查看）。
- 超管口头/线下把口令告知新人，不做小程序码等自动化交付通道。

### 登录凭证与改密
- 凭证为**登录名 + 密码**。
- 新账号**首次登录强制改密**，改密前不能进入后台其他功能。
- 管理员可自行修改自己的密码。
- 超级管理员可为忘记密码的管理员**重置密码**（生成新随机口令、展示一次），
  重置后该账号同样触发「首次强制改密」。
- 不做邮箱 / 短信找回流程。

### 超管制衡
- 允许**多个超级管理员**同时存在。
- 超管可以创建、停用**其他超管**账号，但**不能停用自己**。
- 系统**禁止停用最后一个处于启用状态的超级管理员**，停用操作若会导致「零个启用超管」直接拒绝，
  返回明确错误，避免系统被锁死。

### 角色升降级
- 账号创建后**允许角色升降级**（管理员 ⇄ 超级管理员），由超级管理员操作，
  校验规则与停用一致：**不能把最后一个启用超管降级为普通管理员**。
- 角色变更同样落库审计（见 ADR-028）。

## Consequences

+ 种子脚本 + 环境变量注入，符合项目铁律「密钥不进仓库」。
+ 一次性建号 + 首次强制改密，堵住了「初始口令长期有效」的常见漏洞。
+ 禁止停用最后一个超管，从根上避免了「无人能管理账号」的死锁场景。
- 忘记密码依赖超管人工重置，没有自助找回，管理员数量增长后超管的操作负担会上升，
  当前规模可接受。
- 口令展示一次且不落库明文，若超管操作时手滑关闭页面，只能重新触发一次重置，无法找回。
- 允许角色升降级意味着一个账号的权限历史可能随时间变化，操作日志按「当时角色」不做快照，
  只按当前角色实时判断权限，历史操作是否合规需结合审计表的角色变更记录人工核对。
