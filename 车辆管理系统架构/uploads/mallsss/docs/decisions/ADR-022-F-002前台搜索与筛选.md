# ADR-022 F-002 前台搜索与筛选

Status: Accepted
Date: 2026-08-19
Feature: F-002
Amends: ADR-019（覆盖其「前台禁止筛选、搜索」一条，其余条款不变）
Related: ADR-006（管理后台筛选搜索，属 F-001，本次不变）

## Context

`/decide F-002` 遗留的 open-questions #25：前台是否做搜索/筛选未纳入否定范围。
用户裁决：**展示端与管理后台前端都要有搜索/筛选能力**。

其中管理后台部分 **ADR-006 已经定稿**（按状态筛选 + 关键字搜索，属 F-001 范围），本次不动。
本 ADR 只新增前台（访客端）搜索与筛选，并覆盖 ADR-019 中「前台禁止筛选、搜索」的表述。

## Decision

### 执行层
- 搜索与筛选**全部由服务端执行**：`GET /public/vehicles` 增加查询参数，服务端过滤后再分页返回。
- 前台**依然是哑终端**：只负责把用户输入转成查询参数、渲染服务端返回的结果。
  **禁止**任何浏览器内的本地过滤、本地重排、本地排序切换。
- ADR-019 的「排序固定 id 降序、前台禁止本地重排」**继续有效**：筛选改变的是结果集，不是排序规则。

### 开放的筛选维度
| 维度 | 形态 |
|---|---|
| 关键字 | 单一搜索框，模糊匹配**品牌 + 车型** |
| 价格区间 | 按当前价的最小值 / 最大值 |
| 上牌年份 | 年份区间 |
| 行驶里程 | 里程区间 |

- 所有条件**可组合**，组合语义为 AND。
- 无条件时等价于当前的全量已上架列表。
- 筛选结果同样遵守 ADR-019：`published` 硬过滤、id 降序、`pageSize = 20`。

### 面议车辆与价格区间
- 使用**价格区间**筛选时，面议车辆（无金额）**一律不进结果集**。
- 不提供「含面议」开关。
- 关键字、年份、里程三个维度不受此限制，面议车辆正常出现。

### 契约影响
- 上述查询参数**并入 F-002 已有的那份 RFC**（原为扩展列表聚合字段），一次改完
  `contracts/openapi.yaml`，避免分两次动契约。
- 参数只增不改语义；全部为可选参数，不传即为当前行为。

## Consequences

+ 访客能按预算和需求快速找车，是列表页最高频的真实需求。
+ 服务端执行保证了筛选结果与分页、可见性过滤的一致性，没有「只搜到当前页」的坑。
+ 哑终端原则未被破坏：前台仍不做任何业务判断。
- **ADR-019「前台禁止筛选、搜索」一条作废**，其余条款（排序、分页、缓存、404 语义、直链、限流）全部继续有效。
- 契约变更面变大，RFC 需同时覆盖聚合字段与筛选参数，评审工作量增加。
- 服务端需要为筛选维度建立索引，否则规模增长后查询会退化。
- 面议车不进价格区间结果，意味着这批车只能靠关键字或无条件浏览被发现，运营需知晓。
- 前台筛选维度多于后台（后台仍只有状态 + 关键字），两端能力不对称是已知且接受的现状；
  若将来后台要对齐，须新增 ADR 覆盖 ADR-006 并重开 F-001 定稿。
