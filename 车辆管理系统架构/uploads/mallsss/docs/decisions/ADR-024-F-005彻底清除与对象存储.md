# ADR-024 F-005 彻底清除与对象存储

Status: Accepted
Date: 2026-08-19
Feature: F-005
Related: ADR-009（对象存储直链不因下架失效）

## Context

`/conflicts F-005` 冲突项 C-4、C-5、C-6、C-7、C-10、C-11，用户裁决问题 5-11、14、16、26。
彻底清除涉及定时任务、对象存储删除、主键复用三个互相牵连的风险点，且清除任务失败时
运营是否有补救手段需要拍板。本文件定稿这批规则。

## Decision

### 保留期计时
- 保留期为 **30 × 24 小时**，自 `trashedAt` 起算，时区 **Asia/Shanghai**。
- 不采用自然月计算，避免月长度不等造成的边界歧义。

### 定时清除任务
- 任务**每日执行一次**，可重入扫描到期记录（`trashedAt` + 30 天 ≤ now 且未清除）。
- 单条记录清除失败**自动重试**，允许最多延迟一个调度周期。
- **禁止任何手动 / 立即彻底清除入口**，站内站外均不做「加速销毁」。任务失败时暂无运营补救，
  下一次调度周期自动重试即为唯一恢复路径。

### 到期与恢复的竞态
- **恢复优先**：只要清除任务尚未跑完（记录仍存在），点击恢复即可成功。
- 清除任务对同一条记录与恢复操作之间用乐观锁 / 状态位保证不会双写冲突。
- 已被清除任务处理完成（记录已置 `purged`）的车辆，恢复接口返回专用错误码，不允许恢复。

### 对象存储
- 彻底清除时**删除对象存储中的图片与评估报告文件**，删除动作**异步执行、可补偿重试**。
- 保留期内（未到期）**不删除任何对象**，保证恢复后附件仍可用（与 ADR-009 一致，
  下架 ≠ 文件消失，此处进一步延伸为「进回收站 ≠ 文件消失」）。
- 半清除窗口（DB 已标记 purged、对象补偿尚未跑完）内直链可能短暂仍可访问，属已知可接受的代价。

### 主记录与主键
- 彻底清除**不物理删除**车辆主记录，改为置 `purged = true` 标记，行永久保留。
- 车辆技术主键与 VIN **禁止被新车复用**。
- 价格记录不级联删除，通过原 `vehicleId` 关联到已 `purged` 的主记录，避免孤儿价格错配到新车。

### 已清除车辆的后续可查性
- 管理后台可按已清除车辆 id 检索，返回该车辆的只读主记录 + 全量历史价格记录。
- 公开端（`/public/*`）对已清除车辆的 id **一律 404**，管理端与公开端行为不同：
  管理端为审计可查，公开端为访客不可见。

### 彻底清除后的操作边界
- 同一车辆 id 在**管理端**（只读检索价格历史除外，不可编辑/发布/恢复）、
  **回收站列表**（不再出现）、**公开端**（404）均不可再操作。

## Consequences

+ 恢复优先 + 每日调度的组合把「误删后来不及点恢复」的窗口降到最低。
+ 保留 purged 标记 + 禁止主键复用，从根上避免了价格记录错配到新车的合规风险。
+ 管理端仍可查已清除车辆价格，兜底了「这车之前卖多少钱」的历史追溯需求。
- 每日一次的任务频率意味着到期后最多有一天的清除延迟，属可接受但需运营知晓。
- 表中车辆记录只增不减（保留 purged 行），长期需要归档策略，本期不做，后续按数据量评估。
- 对象异步删除存在半清除窗口，若要杜绝需引入分布式事务或对账补偿系统，超出本期范围。
