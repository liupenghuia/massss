# ADR-029 F-002 列表聚合筛选契约定稿

Status: Accepted
Date: 2026-08-19
Feature: F-002
Related: ADR-019（读模型与缓存）、ADR-022（前台搜索与筛选）
RFC: docs/rfc/2026-08-19-F-002-公开列表聚合与筛选.md（Accepted，契约已改）

## Context

ADR-019/022 已裁决「列表聚合封面+当前价」与「服务端搜索筛选」两个方向，但未落到契约层的
具体边界规则。RFC 落地评审中 reviewer-api、reviewer-qa 各自提出若干契约缺口，用户对此做了
补充裁决。契约已由 contract-keeper 依此改入 `contracts/openapi.yaml`。本 ADR 记录这批边界规则。

## Decision

- **区间参数颠倒**（`priceMin>priceMax` / `registrationYearMin>registrationYearMax` /
  `mileageKmMin>mileageKmMax`）：返回 **400 VALIDATION_ERROR**，不当空结果处理。
- **上牌年份边界**：`registrationYearMin`/`registrationYearMax` 增加 `minimum: 1980, maximum: 2100`
  约束，避免脏值触发异常查询。
- **分页越界**：筛选后命中总数小于 `(page-1)×pageSize` 时，返回 `items: []`、`total` 为筛选后
  匹配总数，**不报错**。
- **关键字匹配**：服务端 **trim** 后按**不区分大小写**模糊匹配品牌+车型；trim 后为空字符串等价
  于未传 keyword。
- **金额精度**：服务端**按分为单位**（金额 × 100 取整）比较 `priceMin`/`priceMax`，**不依赖**
  OpenAPI schema `multipleOf: 0.01` 的浮点判定，避免合法两位小数被浮点误差误拒。

以上规则已写入 `GET /public/vehicles` 的接口 description 与对应参数 description，并落实到
`contracts/openapi.yaml`（新增 `PublicVehicleSummary` schema、`PublicVehicleList.items` 改引用、
6 个可选查询参数）。

## Consequences

+ 边界行为全部可断言，QA 可直接照此写自动化用例，不需要实现时再猜测。
+ 区间颠倒统一报错而非静默降级，避免前端把「参数写反」误判成「无库存」。
+ 金额精度改为服务端整数比较，避免了 OpenAPI schema 校验器在浮点 `multipleOf` 上的已知陷阱。
- 服务端筛选查询逻辑比最初 RFC 草案更复杂（需要额外处理 trim、大小写、分单位比较、越界分页），
  实现工作量比"直接转发参数给 ORM"要高。
- 1980~2100 的年份硬约束是经验值，若未来出现年代更早的车辆（如老爷车拍卖场景）需要新开 ADR 调整。
