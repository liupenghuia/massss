# ADR-015 F-004 数据模型与记录规则修正

Status: Accepted
Date: 2026-08-19
Feature: F-004
Supersedes: ADR-012

## Context

`/conflicts F-004` 问题 3、4、5、6、7、8、9、10、17、20。用户确认「同意本包」后，
与已落地的 ADR-012 有两处不一致：相同报价的处理（ADR-012 为拦截提交；本包为成功且不写记录）、
金额精度（ADR-012 为只允许整数；本包为最多 2 位小数）。其余数据模型条款与 ADR-012 一致，
本文件整份取代 ADR-012，避免实现时两份 ADR 并存。

## Decision

- 不单独建当前价格快照表。当前价格 = 该车价格记录表中最新一条的「变动后值」。
- 「价格是否已填写」（供 ADR-003 发布校验）= 该车是否至少有一条价格记录。「面谈」视为已填写。
- 首次设价生成一条记录，「变动前值」为显式「未填写」占位（不是 0、不是空字符串）。
- 「面谈」与具体数值互相切换，算一次变动，生成记录。
- 提交值与当前价格完全相同（类型 + 金额均同）：返回成功，不生成新记录（不是报错拦截）。
- 不提供编辑或删除已生成记录的入口；改错只能再改一次覆盖，错误记录永久留在历史中。
- 价格一旦设置，不允许清空回「未填写」，只能改成另一个具体数值或「面谈」。
- 货币为人民币，单位元，最多 2 位小数，必须 > 0，不设上限；「面谈」不走数字字段。
- 价格记录不设备注/原因字段，只存变动前值、变动后值、变动时间、操作人。
- 创建草稿车辆时允许同一动作带初始价格，内部走一次设价逻辑生成第一条记录。

## Consequences

+ 单表模型下当前价与历史不会分裂，符合价格错乱零容忍。
+ 相同报价幂等成功，避免管理员误触保存刷出空历史，也不把「没改」当成错误。
+ 允许分（2 位小数）覆盖常见标价，不必把 9.98 万元强行改成整数元。
- 无纠错、不可清空，手误记录会留在前台历史里，用户已接受。
- 不设上限，极端多输 0 只能靠运营核对。
